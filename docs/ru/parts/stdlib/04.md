`format_field` добавляет `s` как есть, а если `s` содержит разделитель,
кавычку или перевод строки - в кавычках с удвоенными кавычками. Разделители
между полями и перевод строки после записи пишет вызывающий код.

```faloya
for row in rows {
    csv::format_field(out, row.name);
    out.push(',');
    format(out, row.count, "\n");
}
```

## json

JSON, как определено в RFC 8259, тремя способами: писатель, добавляющий
значения в конструктор; парсер, строящий дерево документа; и читатель,
отображающий текст прямо на типы вызывающего кода, как делает derive в serde.
`import json;` кладёт их в пространство имён `json`.

### Запись

```faloya
fn format_string(out: u8[>..]&, s: u8[:])    // в кавычках, с escape для " \ и управляющих символов
fn format_key(out: u8[>..]&, key: u8[:])     // ключ в кавычках и его двоеточие: "key":
fn format_number(out: u8[>..]&, v: f64)      // кратчайшая форма, читающаяся обратно как v
fn format_int(out: u8[>..]&, v: i64)
fn format_bool(out: u8[>..]&, b: bool)
```

Скобки и запятые между значениями пишет вызывающий код. Байты строки от 0x80
и выше записываются без изменений, поэтому UTF-8 текст остаётся UTF-8.
`format_number` пишет наименьшее число значащих цифр, которое читается
обратно ровно как `v`, в том же формате, что serde_json (`1.0`, `0.1`, `1e-7`,
`1.5e300`, `0.30000000000000004`). Для NaN и бесконечностей, которым в JSON
нет чисел, она пишет `null`.

```faloya
out.push('{');
json::format_key(out, "name");
json::format_string(out, player.name);
out.push(',');
json::format_key(out, "pos");
out.push('[');
json::format_number(out, player.x);
out.push(',');
json::format_number(out, player.y);
out.append("]}");
```

### Дерево документа

```faloya
struct Node { next: Node&<u32>?, first: Node&<u32>?, key: const u8[:], val: Value }
enum Value { Null, Bool { v: bool }, Int { v: i64 }, Num { v: f64 }, Str { s: const u8[:] },
             Arr { count: i64 }, Obj { count: i64 } }
fn parse(text: u8[:], doc: Node[>..]&, decoded: u8[>..]&) -> Node?, u8[>..]
                                             // корень, либо null и ошибка
fn member(n: Node?, key: u8[:]) -> Node?     // первый член с именем key; null, если его нет
fn each<F>(n: Node&)                         // F(child) для каждого элемента или члена, по порядку
fn as_f64(n: Node?) -> f64, bool             // Int или Num
fn as_i64(n: Node?) -> i64, bool             // Int
fn as_bool(n: Node?) -> bool, bool
fn as_string(n: Node?) -> const u8[:], bool
```

`parse` добавляет узел для каждого значения в `doc` в порядке текста. Каждый
узел держит ссылку на следующего соседа, ссылку на первого ребёнка (для
контейнера), свой ключ (пустой в массиве) и своё значение. Ключи и строки -
срезы `text`. Те, что содержали escape, вместо этого - срезы их декодированного
текста, который добавляется в `decoded`; больше ничего не копируется. Число
без дробной части и экспоненты, влезающее в `i64`, становится `Int`. Любое
другое число становится `Num`, корректно округлённым, и бесконечным, если
слишком велико для `f64`. Escape декодируются в UTF-8: суррогатная пара
становится одной кодовой точкой, а одинокий суррогат - тремя байтами,
кодирующими его собственную кодовую точку. Строки не проверяются на
корректность UTF-8.

На испорченном тексте `parse` возвращает null и сообщение, называющее байт,
на котором текст оказался испорчен, например
`json: expected ',' or '}' at byte 41`. Узлы до этой точки уже добавлены.

Парсер - один цикл, который держит открытые контейнеры на собственном стеке,
поэтому можно разбирать вложенность любой глубины. `member` и аксессоры
принимают null-узел, поэтому поиски можно выстраивать в цепочку. Дублирующиеся
ключи остаются в дереве, и `member` находит первый.

```faloya
var doc: json::Node[>..] = [];
var decoded: u8[>..] = [];
let root, err = json::parse(text, doc, decoded);
guard root else { abort(err); }
let w, ok = json::as_i64(json::member(json::member(root, "window"), "width"));
let items = json::member(root, "items");
if items {
    json::each(items) { item =>
        let name, named = json::as_string(json::member(item, "name"));
        if named { print(name); }
    };
}
```

### Чтение в свои типы

```faloya
struct Reader { text: const u8[:], pos: i64, error: const u8[:], error_at: i64 }
fn reader(text: const u8[:]) -> Reader
fn each_member<F>(r: Reader&)                // F(key) для каждого члена объекта под курсором
fn each_element<F>(r: Reader&)               // F() для каждого элемента массива под курсором
fn read_number(r: Reader&) -> f64
fn read_int(r: Reader&) -> i64               // без дробной части и экспоненты, и влезает в i64
fn read_bool(r: Reader&) -> bool
fn read_string(r: Reader&, scratch: u8[>..]&) -> const u8[:]
fn skip(r: Reader&)                          // проходит мимо значения любого вида, проверяя его
fn peek(r: Reader&) -> u8                    // следующий байт за пробельными; 0 в конце
fn finish(r: Reader&) -> bool                // нет ошибки, и остались только пробельные символы
fn message(r: Reader&) -> u8[>..]            // "json: <what> at byte <n>"
```

Читатель разбирает на ходу и ничего не строит. Каждый блок читает переданное
ему значение функцией для того типа, которого ожидает, и использует `skip`,
чтобы пройти мимо ненужных значений. `read_string` возвращает срез текста, а
для строки, содержавшей escape, - срез `scratch`. Ключи передаются блоку как
написано, включая любые escape, поэтому ключ, записанный с escape, никогда не
равен тому же ключу без него. Ошибки липкие: чтение, нашедшее неожиданный
текст, записывает, чего оно ожидало и где, и двигает курсор в конец, поэтому
каждое следующее чтение тоже даёт неудачу и каждый цикл кончается. Вызывающий
код проверяет один раз через `finish`, которая также отвергает всё, кроме
пробельных символов, после значения. Чтобы обработать `null` там, где значение
опционально, проверьте `peek(r) == 'n'` и вызовите `skip`.

```faloya
struct Item { id: i64, price: f64 }

fn read_items(text: u8[:]) -> Item[>..] {
    var r = json::reader(text);
    var items: Item[>..] = [];
    json::each_element(r) {
        var it = Item { id: 0, price: 0.0 };
        json::each_member(r) { key =>
            if key == "id" { it.id = json::read_int(r); }
            else if key == "price" { it.price = json::read_number(r); }
            else { json::skip(r); }
        };
        items.push(it);
    };
    if !json::finish(r) { abort(json::message(r)); }
    return items;
}
```

## regex

Регулярные выражения с синтаксисом и правилами сопоставления крейта `regex`
из Rust, по байтам. `import regex;` кладёт их в пространство имён `regex`.

```faloya
fn compile(pattern: u8[:]) -> Regex                  // останавливается на испорченном шаблоне
fn compile(pattern: u8[:], err: u8[>..]&) -> Regex   // вместо этого добавляет ошибку в err
fn find(re: Regex&, text: u8[:]) -> i64, i64         // начало и конец первого совпадения; -1, -1
fn matches(re: Regex&, text: u8[:]) -> bool          // есть ли совпадение
fn count(re: Regex&, text: u8[:]) -> i64             // совпадения, которые находит each_match
fn each_match<F>(re: Regex&, text: u8[:])            // F(start, end) для каждого совпадения
fn each_captures<F>(re: Regex&, text: u8[:])         // F(caps: Captures) для каждого совпадения
fn format_replaced<F>(out: u8[>..]&, re: Regex&, text: u8[:])
                                                     // text, где каждое совпадение заменено на F(caps)
struct Captures { text: const u8[:], slots: const i64[:] }
fn group(c: Captures, k: i64) -> const u8[:]         // текст группы k; пустой, если она не участвовала
```

Сопоставление - самое левое из первых, как в крейте, Perl и большинстве
движков. Выбирается совпадение, начинающееся раньше всех, а среди совпадений
с этим началом - то, которое предпочитает шаблон: альтернативы пробуются по
порядку, а повторения жадные, если они не ленивые. Поиски без якорей.
Итерирующие функции находят неперекрывающиеся совпадения слева направо и
никогда не находят пустое совпадение там, где кончилось предыдущее: `a*` на
`baaa` совпадает в 0..0 и 1..4. Группа 0 - всё совпадение, остальные группы
нумеруются по их открывающим скобкам. Группа k занимает
`slots[2k]..slots[2k + 1]` текста; оба слота равны -1 для группы, которая не
участвовала. Повторяющаяся группа захватывает свою последнюю итерацию. Срез,
который возвращает `group`, укоренён в `Captures`, переданном блоку.
Представление группы, которое должно пережить блок, например ключ словаря,
должно вместо этого срезать текст по слотам.

Поддерживаемый синтаксис:

* литеральные байты;
* `.`, совпадающий с переводом строки только под флагом `s`;
* классы `[a-z]` и `[^...]`, где `]` в начале или `-` в начале или в конце
  означает сам себя;
* `\d \w \s` и их дополнения `\D \W \S`, также внутри классов;
* escape `\n \t \r \f \v \xHH` и любая пунктуация (`\.`, `\\`);
* группы `(...)`, `(?:...)` и именованные группы `(?P<name>...)` или
  `(?<name>...)`, чьи имена принимаются, но не используются;
* флаги `i` (буквы совпадают в любом регистре) и `s`, записываемые `(?i)`
  для действия до конца группы или `(?i:...)` для действия внутри, и `(?-i)`,
  чтобы выключить один;
* альтернатива `|`;
* `* + ? {n} {n,} {n,m}`, каждый становится ленивым с `?` после него.

Классы и приведение регистра - ASCII, как в крейте при выключенном Unicode.
Якоря и границы слов (`^ $ \A \z \b \B`), операции над множествами классов
(`&& -- ~~`), вложенные классы, Unicode-классы и остальные флаги не
поддерживаются, и `compile` сообщает о них как об ошибках:
`regex: anchors are not supported at offset 0 in ^a`. Заголовок модуля
описывает два известных отличия от крейта: альтернатива, чьи ветки делят
повторяющийся префикс, сопоставляется как написано, как в Perl и RE2, а
группы в конце шаблона под `{0}` сохраняются.

`compile` заранее строит полные DFA: одну, находящую, где кончается
совпадение, и одну по обращённому шаблону, находящую, где оно начинается.
Поэтому поиск стоит одно обращение к таблице на каждый просмотренный байт
текста. Когда каждое совпадение имеет редкие начальные байты или редкий байт
после части, неспособной содержать этот байт, поиск проскальзывает по тексту
через `find_pair` или `find_any` (выше) и смотрит только туда, где совпадение
возможно. Там, где шаблон даёт группе фиксированное место в совпадении,
группа берётся с того места; иначе она приходит из бэктрекера, работающего по
одному лишь совпадению. `find`, `matches` и `count` не используют ни то, ни
другое.
DFA может потребовать экспоненциально много состояний, и шаблон, чья
программа или DFA разрослись бы слишком сильно (`[ab]*a[ab]{20}` или счётные
повторения в тысячи), сообщается как ошибка, а не компилируется. Создавайте
`Regex` один раз, вне цикла, который им ищет.

```faloya
let re = regex::compile("(\\w+)=(\\d+)");
regex::each_captures(re, line) { c =>
    let n, ok = parse_int(regex::group(c, 2));
    if ok { settings.insert(line[c.slots[2]..c.slots[3]], n); }    // ключ, переживающий c
};

var err: u8[>..] = [];
let user = regex::compile(pattern_from_user, err);
if err.len > 0 { print(err); }

var out: u8[>..] = [];
let field = regex::compile("""\{\{\s*(\w+)\s*\}\}""");
regex::format_replaced(out, field, template) { caps =>
    let value = vars.get(regex::group(caps, 1));
    if value { value } else { "" }
};
```

## gfx

Графика на GPU API SDL3, который рисует через Direct3D 12, Vulkan или Metal:
окно и его ввод, буферы, текстуры, сэмплеры, пайплайны, проходы рендера и
вычислений, а также чтение результатов обратно. Модуль опционален: он требует
компилятор, собранный с сабмодулем `third_party/SDL`, а программа, его
использующая, линкует то, что печатает `faloya --gfx-link msvc|cc` (ответный
файл: `cl game.c @<it>`, `cc game.c -o game @<it>`). Компилятор, собранный без
него, всё равно проверит типы и сгенерирует C для такой программы; провалится
только запуск программы внутри процесса. Всё в пространстве имён `gfx`;
`samples/27_gfx_cube.fal` - маленькая полная программа, а
[docs/gfx.md](https://github.com/mel0k1/faloya_gfx/blob/main/docs/gfx.md)
пакета рассказывает, как он устроен.

**Отрисовка текста обеспечивается модулем [`ui`](#отрисовка-текста-и-игровые-hud)**,
включая шрифты, позиционированный текст и неинтерактивные игровые HUD.
Используйте `ui::label` или `ui::draw_text`, затем `ui::render` поверх сцены
gfx. Отдельный рендерер текста нужен только специализированным художественным
задачам или требованиям к рендерингу.

### Шейдеры

```faloya
// Код, общий для шейдеров, в global, который каждый называет как часть.
let scene = """
    layout(set = 1, binding = 0) uniform Scene { mat4 view_proj; };
    """;

// Исходник шейдера после его стадии, "vert", "frag" или "comp", либо файл,
// .vert, .frag или .comp, относительно этого.
let vs = embed_shader("vert", scene, """
    layout(location = 0) in vec3 a_pos;
    void main() { gl_Position = view_proj * vec4(a_pos, 1.0); }
    """);
let fs = embed_shader("lit.frag");
```

`embed_shader` - встроенная операция. Шейдер GLSL 450 компилируется вместе с
программой, сразу в SPIR-V, MSL и HLSL, и результат - `const u8[:]`
статических данных, передаваемый в `pipeline` или `compute_pipeline`.
Его исходник обычно строка `"""` (спецификация §2), записанная в месте
вызова. Он может также состоять из нескольких частей, каждая - строковый
литерал или глобальная `let`/`const`, инициализированная таким литералом;
части соединяются как строки, по порядку. Шейдер, который не компилируется, -
ошибка компиляции в месте вызова. Если есть провинившаяся строка GLSL, ошибка
указывает на неё, в программе или в файле шейдера. `#include "x.glsl"`
разрешается относительно файла шейдера, а для исходника, написанного в
программе, - относительно файла программы. Диалект - как в cute_spirv
(`third_party/cute_spirv`): нет doubles и нет стадий геометрии или
тесселляции, uniform-блоки не имеют имён экземпляров, а каждый блок
storage-буфера держит один рантайм-массив (`buffer B { vec4 items[]; };`).

Ресурсы попадают туда, куда их ждёт SDL_GPU, что проверяет компилятор:

| Стадия | `set` | что держит; привязки каждого set нумеруются с 0 в этом порядке |
|---|---|---|
| vertex | 0 | сэмплеры, затем storage-текстуры, затем storage-буферы (только чтение) |
| vertex | 1 | uniform-блоки |
| fragment | 2 | сэмплеры, затем storage-текстуры, затем storage-буферы (только чтение) |
| fragment | 3 | uniform-блоки |
| compute | 0 | сэмплеры, затем read-only storage-текстуры, затем read-only storage-буферы |
| compute | 1 | read-write storage-текстуры, затем read-write storage-буферы |
| compute | 2 | uniform-блоки |

`slot` вызова `bind_*` считается внутри одного вида: первый storage-буфер -
slot 0, сколько бы сэмплеров перед ним ни было. Read-write ресурсы
compute-шейдера вместо этого передаются в `begin_compute` в порядке привязок.

### Устройство, окно и кадры

```faloya
fn open(title: const u8[:], width: i64, height: i64) -> bool        // и (..., flags)
fn open_headless(width: i64, height: i64) -> bool                   // без окна; и (..., flags)
fn close()
fn frame() -> bool          // завершает кадр, рисованный с последнего вызова; false после запроса на закрытие
fn quit()                   // frame() вернёт false следующим
fn flush()                  // отправить всё и дождаться GPU
fn error() -> u8[>..]       // почему последний неудавшийся вызов не удался
fn check()                  // останов, если программа злоупотребила gfx
fn driver() -> u8[>..]      // "direct3d12", "vulkan" или "metal"
fn set_title(title: const u8[:])
fn set_fullscreen(on: bool) -> bool   fn fullscreen() -> bool   fn maximize()
fn screen() -> Texture      fn screen_depth() -> Texture      fn screen_size() -> int2
fn pixel_density() -> f32   fn display_scale() -> f32
fn time() -> f64            fn delta_time() -> f64            fn frame_count() -> i64
```

Флаги для `open`: `WINDOW_RESIZABLE`, `WINDOW_HIDDEN`, `WINDOW_FULLSCREEN`,
`NO_VSYNC`, `DEBUG` (слои валидации, где установлены; включён в отладочной
сборке слоя). С `FALOYA_GFX_HEADLESS=1` в окружении `open` не открывает
окно; этим пользуются тестовые раннеры. Экран - текстура RGBA8 размером окна
в пикселях, с текстурой глубины. Кадр рисуется в неё, и `frame()` показывает
её. Окно имеет ширину и высоту, которые задал `open`, в собственных
координатах дисплея, и в этой области у него каждый пиксель, какой есть у
дисплея. На дисплее высокой плотности пикселей больше, чем ширина и высота;
`screen_size()` считает эти пиксели, и в них же сообщается позиция мыши.

`pixel_density()` - пиксели экрана на единицу этих координат: 2 на
большинстве дисплеев высокой плотности, 1 в остальных случаях, включая
Windows при любом масштабе. `display_scale()` - это, умноженное на масштаб
контента системы, тот, в котором система рисует собственные текст и
контролы: 2 на Mac с высокой плотностью, 1.5 на Windows, поставленной на
150%. Оба - значения SDL для окна, 1 при headless или без открытого окна, и
они меняются, когда окно переходит между дисплеями, поэтому следящая за ними
программа читает их каждый кадр. Они только сообщают: gfx и ui не применяют
ни тот, ни другой, а насколько крупно рисовать - выбор программы. Для ui
размером с системный передайте `display_scale()` в `ui::set_scale`.

`set_fullscreen` делает окно полноэкранным без рамки в разрешении рабочего
стола или снова окном. Она возвращает false, если окно не может смениться, и
в headless. SDL меняет это асинхронно, поэтому `fullscreen()` может
отставать на кадр-два. `maximize` заполняет рабочий стол как окно.

```faloya
guard gfx::open("demo", 1280, 720) else { abort(str("gfx: ", gfx::error())); }
while gfx::frame() {
    gfx::begin_screen(float4 { 0.1, 0.1, 0.1, 1.0 });
    // привязки, юниформы, отрисовка ...
    gfx::end_pass();
}
gfx::close();
```

Ошибки: вызов, который может провалиться по причинам вне программы,
возвращает false или нулевой хэндл, а `error()` говорит почему. Вызов,
которого программе делать не следовало, печатается в момент свершения и
пропускается, а программа останавливается на следующем `frame()`, `check()`,
чтении результатов или `close()`. Примеры: отрисовка без привязанного
пайплайна, оставшаяся непривязанной текстура, которую сэмплирует шейдер,
освобождённый хэндл и uniform-структура неверного размера.

### Ввод

```faloya
fn key_down(name: const u8[:]) -> bool        // имена клавиш SDL: "A", "Space", "Left", "Escape"
fn key_pressed(name: const u8[:]) -> bool     // нажата с последнего frame()
fn key_released(name: const u8[:]) -> bool
fn mouse_down(button: i64) -> bool            // MOUSE_LEFT, MOUSE_MIDDLE, MOUSE_RIGHT
fn mouse_pressed(button: i64) -> bool         fn mouse_released(button: i64) -> bool
fn mouse_pos() -> float2    fn mouse_delta() -> float2      // в пикселях экрана
fn mouse_wheel() -> f32     fn mouse_in_window() -> bool    // над окном или тянет от него
fn focused() -> bool                                      // клавиатурный фокус на последнем frame()
fn set_mouse_relative(on: bool) -> bool    fn mouse_relative() -> bool
fn set_cursor(shape: i64) -> bool                         // системный курсор, CURSOR_*
fn set_cursor_visible(visible: bool) -> bool    fn cursor_visible() -> bool
fn inject_key(name: const u8[:], down: bool) -> bool           // как набранное, видно на следующем frame()
fn inject_mouse(x: f32, y: f32, button: i64, down: bool)       // в пиксель x, y; button 0 только двигает
fn inject_text(text: const u8[:]) -> bool                      // по EVENT_TEXT на символ
fn inject_focus(focused: bool) -> bool                        // имитация фокуса на следующем frame()
fn events() -> Event[>..]           // ввод последнего кадра, в порядке поступления
fn text_input(on: bool)             // набранный текст как EVENT_TEXT: по умолчанию выключен
fn scancode(name: const u8[:]) -> i64       fn key_name(scancode: i64) -> u8[>..]
fn clipboard() -> u8[>..]           fn set_clipboard(text: const u8[:]) -> bool
fn open_count() -> i64              // сколько раз gfx открывался: старые хэндлы исчезли
```

Функции состояния сообщают состояние на кадр; `events()` сообщает, что
случилось между двумя кадрами, что нужно редактированию текста. События:

* нажатия и отпускания клавиш, со scancode, символом, который печатает
  клавиша (`keycode`), и зажатыми `MOD_*`;
* набранные символы;
* движение мыши;
* кнопки (`MOUSE_*`, включая X1 и X2), со счётчиком щелчков;
* колесо.

В headless gfx использует собственный буфер обмена, а не системный.

`mouse_pos` сообщает позицию мыши с момента открытия окна, даже до первого
движения мыши. `mouse_in_window` истинно, пока мышь над окном и пока она
держит кнопку, нажатую там, как это сообщает SDL. Для окна, открывшегося под
мышью, SDL сообщает это самое позднее с первого движения мыши. После ухода
мыши `mouse_pos` остаётся в точке ухода, за экраном, поэтому проверка скролла
у края смотрит на обе. В headless мышь в окне, когда последняя внедрённая
позиция на экране.

`set_mouse_relative(true)` запирает мышь в окне и прячет её курсор.
`mouse_delta()` продолжает сообщать движение за краями окна, в пикселях
экрана: используйте её для поворотов камеры от первого лица, а не
`mouse_pos()`. Установка другого режима выбрасывает накопленное движение и
очищает текущую дельту, чтобы ранее накопленный сдвиг не повернул камеру.
Повторный вызов с тем же режимом сохраняет движение. Она возвращает false при
неудаче, включая окно без клавиатурного фокуса; `error()` даёт причину.

`set_cursor_visible(false)` прячет курсор для программ, рисующих свой. Его
предпочтение действует вне относительного режима: относительный режим всегда
прячет курсор, и `cursor_visible()` сообщает это действительное состояние
внутри окна. Предпочтение восстанавливается, когда относительный режим
выключен. Спрятать курсор без фокуса не удаётся; показать работает всегда,
пока gfx открыт.

`set_cursor` выбирает один из системных курсоров, чтобы показать, что сделает
щелчок по предмету под мышью:

| Константа | Курсор |
|---|---|
| `CURSOR_DEFAULT` | стрелка |
| `CURSOR_TEXT` | каретка ввода текста |
| `CURSOR_POINTER` | рука над ссылкой или кнопкой |
| `CURSOR_CROSSHAIR` | перекрестие |
| `CURSOR_WAIT`, `CURSOR_PROGRESS` | занят, и занят, но ещё кликабелен |
| `CURSOR_MOVE` | перемещение в четыре стороны |
| `CURSOR_NOT_ALLOWED` | здесь действия нет |
| `CURSOR_EW_RESIZE`, `CURSOR_NS_RESIZE` | меняет размер стороны, в обе стороны |
| `CURSOR_NWSE_RESIZE`, `CURSOR_NESW_RESIZE` | меняет размер угла, в обе стороны |
| `CURSOR_N_RESIZE`, `CURSOR_E_RESIZE`, `CURSOR_S_RESIZE`, `CURSOR_W_RESIZE` | меняет размер от этой стороны |
| `CURSOR_NW_RESIZE`, `CURSOR_NE_RESIZE`, `CURSOR_SE_RESIZE`, `CURSOR_SW_RESIZE` | меняет размер от этого угла |

Она возвращает false для любого другого значения или при неудаче; `error()`
даёт причину. Форма сохраняется до смены, а видимость и относительный режим
остаются как есть. В headless она проверяет форму и ничего не меняет на
рабочем столе. `close()` возвращает курсор по умолчанию.
