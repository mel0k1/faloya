`split_once` режет s по первому sep, как `strings.Cut` в Go: часть до и часть
после, срезы s только для чтения, плюс `true`. Когда sep не встречается в s,
она даёт s целиком, пустой срез и `false`, так что первая часть в любом случае
даёт всё поле. Пустой sep никогда не находится, как и в `split`.

Классы символов работают только с ASCII, как `<ctype.h>` в C в локали C и как
`u8::is_ascii_digit` в Rust и его родственники: ни один байт от 0x80 и выше не
входит ни в один из них. Они живут в пространстве имён `ascii`, которое
подключает `import std;`, чтобы короткие распространённые имена вроде
`is_digit` оставались свободными в глобальном.

```faloya
let text = "1f8B rest";
var v = 0;
var i = 0;
while i < text.len && ascii::hex_value(text[i]) >= 0 {
    v = v * 16 + ascii::hex_value(text[i]);
    i++;
}
print(v, " ", i, " ", ascii::is_alpha(text[i + 1]));   // 8075 4 true
```

`each_utf8` декодирует так же, как декодер WHATWG. Оборванная последовательность,
слишком длинная форма, суррогат или кодовая точка выше 0x10FFFF дают по одному
0xFFFD на каждую максимальную подчасть (Unicode §3.9), а байт, сломавший
последовательность, начинает следующую: `[0xC3, 'A']` даёт 0xFFFD, а затем `A`.
`push_utf8` пишет суррогат как три байта его собственного кода, так `json`
сохраняет одиночный escape `\u`.

```faloya
var line: u8[>..] = [];
format(line, "x=");
format_int(line, x, 16, 8, '0');
each_split(text, '\n') { handle(trim(it)); };
let n, ok = parse_int(trim(field));
let key, value, has_value = split_once(arg, '=');   // "-o=out": "-o", "out", true
let cmd = words(input);                   // "take  the sword": ["take", "the", "sword"]
if cmd.len > 1 && cmd[0] == "take" { take(cmd[cmd.len - 1]); }
```

`format_uleb` и `parse_uleb` пишут и читают префикс длины, который используют
сериализованные образы (`design/serialization.md`). Отдельная запись префикса
позволяет программе сохранить представление `bytes_of`, не копируя его сначала
в образ. Чтение префикса сообщает потоковому читателю, сколько байт полезной
нагрузки ждать.

```faloya
let payload = pool.bytes_of();            // представление, ничего не скопировано
var head: u8[>..] = [];
format_uleb(head, payload.len);
write_file(path, head); append_file(path, payload);
```

`format_flt` округляет точное двоичное значение `v` при любом размере и до
любого числа разрядов: `format_flt(out, 0.1, 20)` пишет
`0.10000000000000000555`, как `printf("%.20f")` в C, а
`format_flt(out, 2.675, 2)` пишет `2.67`, потому что ближайший к 2.675 double
чуть ниже него. Иначе, чем `printf`, который округляет половину к чётному,
округляется только значение, стоящее ровно посередине: `format_flt(out, 0.125, 2)`
пишет `0.13`. Обычный `format` пишет кратчайший текст, читающийся обратно как
то же значение.

## exception

Типизированные исключения, реализованные на Faloya через `return ... from`
(спецификация §7.9), по образцу
[модуля исключений Lobster](https://github.com/aardappel/lobster/blob/master/modules/exception.lobster).
Импортируйте `exception`; его функции живут в пространстве имён `exception`.

```faloya
fn try<E, Body, Catch>()            // Body(); при ошибке Catch(error)
fn try<E, Body>()                   // Body(); отбросить ошибку
fn try<E, Body, Catch, Finally>()   // как первая, затем Finally() на каждом выходе
fn throw(value)                    // выйти к ближайшему охватывающему обработчику
```

```faloya
import exception;

fn load() {
    // Здесь может быть любое число вызовов под try.
    exception::throw(str("cannot load item ", 42));
}

exception::try<u8[]>(load) { error => print(error); };
```

`E` - тип ошибки, задаваемый явно в `try`: `u8[]` для владеемого текста, целое
число или struct/enum приложения (`Error..` для перечисления переменного
режима). Брошенное значение должно подходить под `E`, а `E` должен быть
пригоден как элемент массива. Тело и catch - статические функциональные
значения; Faloya разрешает один замыкающий блок, поэтому дайте имя хотя бы
одному из колбэков. Результаты тела отбрасываются; оно может обновлять
захваченные выходные переменные.

Обработчик возвращает пустой `E[]` при успехе и массив из одного элемента с
ошибкой при неудаче. Здесь используются обычные стеки данных, значение `E` по
умолчанию не нужно, а `0`, `false` и `""` допустимы как ошибки. Catch
выполняется после возврата обработчика. Поэтому `throw` в catch бросает
исключение к внешнему `try`; чтобы перебросить владеемую ошибку переменного
размера, используйте `exception::throw(copy(error))`. Существующее
нефиксированное значение также требует `copy` при первом броске; свежие
конструкторы и строковые срезы можно передавать напрямую. Владеемый текст
копируется до выхода кадров, содержащих его.

Проверки и ограничения языка продолжают действовать:

* У каждого throw должен быть обработчик на каждом путе вызова, известном при
  компиляции, включая броски из catch. Несовместимый тип ошибки - ошибка
  компиляции.
* Ссылки, переносимые дальним возвратом, должны указывать на глобальные или
  статические данные. Используйте владеемый `u8[]`, а не срез в локальной
  строке, и владеемые поля в записях ошибок.
* Рекурсивный код может бросить исключение внешнему обработчику. Сам `try`
  нельзя рекурсивно перезапустить: его нефиксированный результат-обработчик
  держал бы стек данных через рекурсивный вызов (§7.8).
* Проверяющий распространяет вызовы, которые никогда не возвращают управление
  вызвавшему. Функция, объявленная с возвращаемым значением, может закончиться
  `exception::throw(error);`, и бросающая ветка не требует результата. Это не
  даёт `throw` тип значения: используйте его как оператор или ветку, а не как
  `return throw(error);` или аргумент, требующий значения. Рекурсивный вывод
  консервативен (спецификация §7.3).
* Ловятся только вызовы `throw`. Отказы рантайма, `abort` и `exit` остаются
  неперехватываемыми. Средства трассировки стека нет.

`try<E>(body, catch, finally)` выполняет `finally` после завершения тела,
после перехваченного throw и когда throw или лексический `return`,
адресованный другой функции, выходит через этот вызов. Это `defer finally();`
перед try (см. reference, "defer"), поэтому `finally` подчиняется правилам
тела defer: из него нельзя выйти, и он не может бросать, ловить или вызывать
что-то, что бросает.

## dictionary

```faloya
struct dictionary<K, V> { count: i64, slots: dictionary_slot<K, V>[>..<] }
fn get<K, V>(d: dictionary<K, V>&, key: K) -> V?               // ссылка на значение или null
fn contains<K, V>(d: dictionary<K, V>&, key: K) -> bool
fn insert<K, V>(d: dictionary<K, V>&, key: K, val: V) -> bool   // перезаписывает; true, если ключ новый
fn get_or_insert<K, V>(d: dictionary<K, V>&, key: K, v0: V) -> V&
fn update<K, V, F>(d: dictionary<K, V>&, key: K, v0: V)         // F(val&); сначала вставляет v0, если ключа нет
fn remove<K, V>(d: dictionary<K, V>&, key: K) -> bool
fn clear<K, V>(d: dictionary<K, V>&)
fn reserve<K, V>(d: dictionary<K, V>&, n: i64)                  // место под n записей без рехеша
fn each<K, V, F>(d: dictionary<K, V>&)                          // F(key, val&); порядок не специфицирован
```

Таблица использует открытую адресацию с линейным пробированием, ёмкость,
равную степени двойки, и удаление обратным сдвигом. Ключи и значения имеют
фиксированный размер; типу ключа нужны `hash` и `==`. Каждый слот хранит
31 бит хеша своего ключа как тег, поэтому поиск сравнивает ключи только там,
где теги совпали, а рост и удаление не хешируют ключи заново (в таблицах до
2^31 слотов). `insert`, `update` и `get_or_insert` ищут ключ один раз, есть он
или нет. Таблица удваивается на месте при загрузке 2/3; `reserve(n)` подбирает
размер под `n` записей при этой загрузке.
Строки ключуются как срезы `u8[:]` в текст, который держит вызывающий код
(`const u8[:]` для литералов или представлений данных `const`, §9.5), либо как
встроенные `u8[..k]`. Множество - это `dictionary<K, bool>`.

Массив слотов растёт и сжимается, поэтому последнее использование ссылки в
него (результат `get` или `get_or_insert`, либо binder из `each`) должно быть
раньше следующего `insert`, `update`, `remove` или `clear`. Иначе проверяющий
сообщит об ошибке на мутации, назвав ссылку и место её связывания
(спецификация §5.2). Сначала закончите со ссылкой или используйте `update`,
который делает поиск и изменение одним вызовом:

```faloya
var counts = dictionary<const u8[:], i32> {};
each_split(text, ' ') { counts.update(it, 0) { it += 1; } };
counts.each() { w, n => if n > 100 { print(w, " ", n); } };
let n = counts.get("the");
if n { print(n); }               // последнее использование n; после него counts снова свободен
```

Проверяющий смотрит на живучесть, а не на область видимости: ссылке, чьё
последнее использование раньше мутации, блок вокруг не нужен, а ссылка,
используемая после мутации, - ошибка независимо от места объявления. Тип
ключа - `const u8[:]`, потому что его требуют литералы и срезы только для
чтения, возвращаемые `split` (§9.5). Словарь с перезаписываемыми срезами может
использовать `dictionary<u8[:], V>`, независимо от того, чем связан базовый
буфер, `let` или `var`.

Значение может быть ссылкой, если оно опционально: `Cell?` или ссылка в пул
вроде `Cell&<u32 in cells>?`. Неиспользуемые слоты хранят `default<V>()`,
которого у необязательной ссылки нет. `insert` по существующему ключу
сохраняет новую ссылку, а не пишет через старую. `get` и `get_or_insert`
возвращают сам сохранённую ссылку, и блоки `update` и `each` получают её
(`V?` и `V&` от ссылки - это сама ссылка, §3.8), загруженную, если она
относительная. Запись через неё пишет в цель; замена требует `insert`. `get`
возвращает null и для нулевого значения, и для отсутствующего ключа;
`contains` их различает. Такая ссылка указывает на свою цель, а не в массив
слотов, поэтому может оставаться живой через следующую мутацию:

```faloya
var owner = dictionary<i64, Cell?> {};
owner.insert(7, cells[3]);
let c = owner.get(7);
owner.insert(7, cells[4]);       // cells[3] не изменился, и c всё ещё указывает на него
if c { c.v += 1; }
```

## Переход с reusable

`reusable` и `reusable[]` устарели; их встроенные операции по-прежнему
доступны. Импортируйте `slot_pool` для отдельных слотов или `slice_pool` для
непрерывных серий.

| Запись сейчас | Запись в библиотеке |
|---|---|
| `reusable var p: T[>..] = [];` | `var p = slot_pool<T> {};` |
| `reusable[] var p: T[>..] = [];` | `var p = slice_pool<T> {};` |
| параметр пула `p: T[>..]&` | `p: slot_pool<T>&` или `p: slice_pool<T>&` |
| `p[i]`, `p.len`, `for x in p` | `p.items[i]`, `p.items.len`, `for x in p.items` |
| `u32 in p`, `Node&<u32 in p>` | `u32 in p.items`, `Node&<u32 in p.items>` |
| `p.alloc_ref(value)` | то же для копируемых значений; `p.alloc_with() { fresh_value }` для конструкции на месте |
| `p.alloc_index(value)` | то же для копируемых значений; `p.alloc_index_with() { fresh_value }` для конструкции на месте |
| `p.free(i)` | то же; или `p.free_ref(node)`, когда элемент сам не является ссылкой |
| `p.alloc_slice(n)`, `p.free_slice(s)`, `p.realloc_slice(s, n)` | те же имена методов у `slice_pool` |
| выделить срез, затем скопировать в него | `p.alloc_copy(source)` |

Обе библиотеки сохраняют стабильное инициализированное хранилище. `items.len`
- максимальный счётчик, включая свободные записи, и итерация проходит по ним.
Освобождённые ссылки/представления остаются действительными и могут наблюдать
подменённые значения; обнаружение логического use-after-free и двойного
освобождения требует учёта на стороне приложения.
`recycle_all` делает всё хранилище снова используемым, не сжимая его и не
очищая значения.
Не сжимайте и не подменяйте `items` и не правьте учётные данные аллокатора
напрямую.

Освобождение слота чужого пула через `free_ref` сохраняет проверку
`index_of` на этапе компиляции. Освобождение непустого среза чужого пула
сейчас падает на проверке принадлежности в рантайме
(`slice_pool.free_slice: slice is not from this pool`); предупреждения при
компиляции пока нет. Пустые срезы любого происхождения безвредны. Как и
каждая проверка внутри стандартной библиотеки, проверки пулов сообщают строку
программы, которая их вызвала.
Подходящие `items` можно сериализовать отдельно, но это опускает состояние
аллокатора.
Целые корневые владельцы не сериализуются и не копируются воркерам
автоматически.
Для плоских элементов [пример со снапшотами воркера](../../samples/32_pool_worker_snapshots.fal)
явно копирует `items` и метаданные аллокатора во владельца, локального для
воркера.
Типы метаданных срезов - детали реализации, поэтому держите этот рецепт в
согласии с библиотекой, не считая его стабильным форматом сериализации.

Ссылки пула можно хранить в обычных структурах, захватывать, возвращать, пока
жив их владелец, и делать опциональными. Это гибче встроенных ссылок пула.
Корневой владелец сам по себе остаётся только локальным/глобальным; вложенные
корневые владельцы отложены.

## slot_pool

`import slot_pool;` даёт стабильные переиспользуемые слоты через обычные поля
и функции корневой структуры. Используйте его вместо устаревшего языкового
средства `reusable`.

```faloya
root struct slot_pool<T> {
    items: T[>..] = [],
    free_slots: i64[>..<] = []
}

fn alloc_index<T>(pool: slot_pool<T>&, value: T) -> i64
fn alloc_ref<T>(pool: slot_pool<T>&, value: T) -> T&
fn alloc_with<T, F>(pool: slot_pool<T>&) -> T&
fn alloc_index_with<T, F>(pool: slot_pool<T>&) -> i64
fn free<T>(pool: slot_pool<T>&, i: i64)
fn free_ref<T>(pool: slot_pool<T>&, value: T&)
fn recycle_all<T>(pool: slot_pool<T>&)
```

Объявите локального или глобального владельца и используйте `items` для
обычной индексации, срезания, итерации и `index_of`:

```faloya
import slot_pool;

fn main() {
    var pool = slot_pool<i64> {};
    let first .= pool.alloc_ref(10);
    let index = pool.items.index_of(first);
    pool.free(index);
    assert(pool.alloc_index(20) == index);
    print(first);                         // 20: тот же слот, теперь переиспользован
}
```

Элементы должны иметь фиксированный размер. Значение по умолчанию не нужно:
каждое выделение поставляет значение. `alloc_index` и `alloc_ref` принимают
нормально копируемые значения.
Выделение берёт последний освобождённый индекс или добавляет в конец, когда
свободного слота нет. `alloc_index` возвращает его индекс; `alloc_ref`
возвращает ссылку на его значение. Для ссылочных элементов `T&` сворачивается
в `T`, как обычно; используйте `alloc_index`, когда нужна идентичность слота.
Присваивание целого элемента подменяет ссылочные элементы, не записывая через
них.

`alloc_with` и `alloc_index_with` принимают функцию без аргументов или
замыкающий блок, создающий `T`; вторая прямо возвращает выбранный индекс.
Она сначала выбирает слот, один раз вызывает конструктор и строит результат
прямо там. Это поддерживает самосоотносительные ссылки и `self`,
относительный к пулу:

```faloya
import slot_pool;
struct Node { value: i64, me: Node&<u32>, next: Node&<u32>? }
fn main() {
    var nodes = slot_pool<Node> {};
    let first .= nodes.alloc_with() { Node { value: 1, me: self } };
    let second .= nodes.alloc_with() { Node { value: 2, me: self, next: first } };
    let index = nodes.items.index_of(second);
    nodes.free(index);
    nodes.alloc_with() { Node { value: 3, me: self, next: first } };
    assert(second.value == 3 && second.me .== second);
}
```

Свежие результаты могут приходить из других функций. Существующие
самосоотносительные значения по-прежнему нельзя копировать, а ссылки должны
указывать внутрь принимающего массива.
Замыкающий блок выводит тип своего результата; для ссылочного `T` передайте
именованную функцию, явно возвращающую этот ссылочный тип.

В отличие от аргументов-значений, конструктор запускается после изъятия
свободного индекса. Слот, освобождённый конструктором, остаётся доступным для
последующего выделения. Новый слот попадает в `items.len` только по завершении
конструкции; нелокальный возврат до завершения его не публикует.
Переиспользование не транзакционно: нелокальный выход не возвращает изъятый
индекс и не отменяет побочные эффекты инициализатора.
Обычные правила конструкции отвергают конфликтный рост `items` внутри
конструктора. Проверки границ переиспользуемого индекса выполняются до
конструктора.

`free` проверяет `0 <= i < items.len` в каждой сборке, затем записывает
индекс. Она оставляет элемент инициализированным и не сжимает массив.
Существующие ссылки остаются действительными и могут наблюдать позднейшую
подмену. Двойные освобождения и использование логически освобождённого слота
- ошибки приложения, как и с `reusable`; пул не отслеживает занятость или
поколения. `items.len` - число когда-либо добавленных слотов, включая
свободные, и итерация проходит и по ним.

Считайте `free_slots` учётными данными. Не сжимайте и не подменяйте `items`,
не правьте список свободных слотов напрямую: это может сделать недействительным
логическое состояние пула. Обычные проверки границ массива и времени жизни
продолжают действовать. `recycle_all` снова делает доступным каждый слот в
порядке индексов, сохраняя инициализированные значения и хранилище.
Она не сжимает `items`, не уничтожает значения и не лишает силы существующие
ссылки.
`free_ref` объединяет `index_of` с `free`, сохраняя его проверку происхождения
на этапе компиляции; для ссылочных элементов используйте индексы, поскольку их
ссылки называют цель, а не слот пула. Подходящий компонент `items`
можно сериализовать отдельно, но его образ опускает список свободных слотов.

Для глобального `var pool` компактные ссылки и индексные типы могут называть
его массив: `Node&<u32 in pool.items>`, `u32 in pool.items` и
`u32 upto pool.items`.
Значения, относительные к пулу, с обычными ссылками копируемы и работают с
`alloc_ref`.
Самосоотносительные значения и инициализаторы `self` используют `alloc_with`
для конструкции в выделенном слоте.
Корневого владельца нельзя скопировать воркеру; пулы, локальные для воркера,
разрешены.
См. [план миграции](../design/root_structs.md#separate-follow-up-reusable-pools-in-the-stdlib).

## slice_pool

`import slice_pool;` даёт переиспользуемые непрерывные серии элементов
фиксированного размера.
`alloc_slice` и `realloc_slice` требуют значения по умолчанию; `alloc_copy`
требует только копируемые значения. Владелец объявляется как
`var pool = slice_pool<T> {};`.
Используйте его вместо устаревшего языкового средства `reusable[]`. Обе
встроенные операции остаются доступными для существующего кода; их удаление -
отдельный шаг в будущем.

```faloya
fn alloc_slice<T>(pool: slice_pool<T>&, n: i64) -> T[:]
fn alloc_copy<T>(pool: slice_pool<T>&, src: T[:]) -> T[:]
fn free_slice<T>(pool: slice_pool<T>&, s: T[:])
fn realloc_slice<T>(pool: slice_pool<T>&, s: T[:], n: i64) -> T[:]
fn recycle_all<T>(pool: slice_pool<T>&)
fn trim(pool: slice_pool<u8>&) -> bool
```

```faloya
import slice_pool;
fn main() {
    var pool = slice_pool<i64> {};
    var entries = pool.alloc_slice(3);
    entries[0] = 7;
    entries = pool.realloc_slice(entries, 5);
    print(entries);                         // [7, 0, 0, 0, 0]
    pool.free_slice(entries);
    let again = pool.alloc_slice(2);
    print(again, " ", pool.items.len);       // [0, 0] 5
}
```

Выделение выбирает первый в порядке индексов свободный диапазон, куда
помещается запрос. Если такого нет, оно растит базовый массив, сначала
используя любой свободный диапазон в хвосте. Свободные диапазоны сливаются с
соседями. Расширенное B+ дерево из узлов по 512 байт ведёт поиск первого
подходящего и поиск соседей обходами дерева и ограниченными сканами узлов;
опустевшие узлы переиспользуются. Код дерева из рантайма, от `reusable[]`, в
копии, которая проверяет всё, что читает из `nodes` и `tree`, поэтому политика
совпадает.

`alloc_slice` заполняет значениями по умолчанию каждый выдаваемый элемент,
включая переиспользуемые.
`alloc_copy` инициализирует сразу из исходного среза, без предварительного
заполнения по умолчанию. Она поддерживает перекрывающиеся представления
`items` и не освобождает источник.
Например, `strings.alloc_copy(text)` выделяет и копирует строку.
`realloc_slice` сохраняет первые `min(s.len, n)` элементов, возвращает
укороченный хвост дереву и по разу заполняет по умолчанию каждый добавленный
элемент. Рост остаётся на месте в конце массива или когда следующий свободный
диапазон достаточен (включая расширение в хвосте). Иначе она освобождает
старую серию и выбирает первое подходящее место, копируя в порядке, безопасном
при перекрытии. Выражения по умолчанию не должны мутировать или повторно
входить в тот же пул. Каждый опубликованный элемент базового массива
инициализирован.

`free_slice` и `realloc_slice` принимают поддиапазоны серии пула. Они
проверяют, что непустой срез выровнен и целиком лежит в `items`, даже когда
его происхождение известно только в рантайме. Пустые срезы и срезы по
умолчанию можно освобождать безвредно; рост пустого среза выделяет новую
серию. Отрицательные или избыточные размеры аварийно останавливают любую
сборку до изменения дерева. `items.range_index(s)` восстанавливает индекс
непустой серии; для любого пустого среза она возвращает ноль.

Освобождение и сжатие серий не сжимают `items` и не лишают силы старые
представления. Удерживаемое представление наблюдает позднейшие подмены по
своему исходному адресу; перемещение его не перенаправляет. Двойные
освобождения, перекрывающиеся живые выделения из-за неверных освобождений и
доступ к логически освобождённой серии - ошибки приложения.
`items.len` - максимальная длина, а не число живых элементов. Считайте
`nodes` и `tree` внутренней бухгалтерией и не сжимайте и не подменяйте
`items`.
Обычные проверки границ и времени жизни продолжают действовать для этих
публичных полей. Рантайм проверяет каждый номер узла и счётчик записей,
которые читает из них: узел, записанный программой неверно, останавливает
программу с `slice pool span tree is corrupt`. Диапазон, отредактированный
так, что он начинается за концом `items`, останавливает программу с
`span tree is corrupt` в операции, которая его выдала; другие отредактированные
диапазоны могут выдать элементы дважды, как и двойное освобождение.
`recycle_all` делает весь максимальный диапазон одной свободной серией и
перерабатывает все метаданные-узлы. Она сохраняет инициализированные значения,
хранилище и существующие представления; следующее выделение начинается с
нулевого индекса.

`trim` возвращает ОС физическую память свободных серий пула `u8` (а в Windows
и их commit charge), как `os::trim_memory` делает над вершинами стеков: она
отбрасывает целые страницы внутри каждого свободного диапазона, а они читаются
обратно нулями, какими `alloc_slice` их и заполняет. Свободные диапазоны уже
слились с соседями, поэтому остаётся только страница, где есть и живой
элемент. Живые серии, представления и `items.len` остаются как есть, диапазон
адресов остаётся зарезервированным, поэтому виртуальный размер процесса не
падает. Выделение, переиспользующее диапазон, снова берёт его страницы. Как и
`trim_memory`, это явно: освобождение остаётся столь же дешёвым, а долго
работающая программа вызывает `trim` после закрытия больших буферов, а не
после каждого освобождения. Чтение освобождённой серии - ошибка приложения,
но без `trim` такое чтение видит старые байты серии, пока пул её не
переиспользует; после `trim` оно видит нули, поэтому добавление вызова `trim`
может изменить поведение программы, которая всё ещё читает освобождённые
серии. В Windows устаревшее представление, читающее отброшенную страницу,
снова её коммитит, поэтому чтение освобождённых серий отменяет trim для этих
страниц. Функция ограничена `u8`, потому что отброшенная страница должна
читаться обратно как корректный элемент. `false` означает неудачу запроса к
ОС.

Владелец следует тем же ограничениям размещения, сериализации и воркеров, что
и `slot_pool`: сериализуйте подходящие `items` отдельно и создавайте
владельцев, локальных для воркера, вместо передачи корневых владельцев.
`alloc_slice` строит значения по умолчанию на месте, поэтому выделение и
освобождение поддерживают самосоотносительные элементы, допускающие значение
по умолчанию; `realloc_slice` требует нормально копируемые элементы, как и
встроенная операция.
Глобальные индексные/пул-относительные типы могут называть `pool.items`, как и
для `slot_pool`.
Опциональные ссылки на отдельно владеемое хранилище и объявленные значения
полей по умолчанию поддерживаются, когда у `T` есть значение по умолчанию.

См. [отчёт о бенчмарке slice-pool](../../bench/slice_pool.md) со сравнениями с
`reusable[]`, включая сохранённые границы вызовов функций.
