`focused()` сообщает клавиатурный фокус, который отличается от
`mouse_in_window()`.
`events()` включает `EVENT_FOCUS_GAINED` и `EVENT_FOCUS_LOST` по порядку вместе
с прочим вводом; у этих видов нет полезной нагрузки. Потеря фокуса очищает
зажатые клавиши и кнопки и дельты мыши/колеса, выключает относительный режим и
возвращает курсор в видимое состояние. Ввод, полученный без фокуса,
игнорируется. Получение фокуса оставляет относительный режим выключенным,
чтобы игра могла поставить паузу при потере фокуса и дождаться щелчка перед
повторным захватом. Зажатые клавиши/кнопки также получают фронты отпускания и
синтетические события отпускания перед `EVENT_FOCUS_LOST`, поэтому UI,
управляемый событиями, не может удерживать зажатую клавишу или перетаскивание
через переключение приложений. `close()` также отпускает мышь и возвращает
курсор.

Headless gfx стартует с фокусом, видимым курсором и выключенным относительным
режимом.
Сеттеры имитируют своё состояние, не трогая системную мышь.
`inject_focus` ставит те же переходы в очередь для тестирования; он не меняет
фокус операционной системы. Закрытие и повторное открытие сбрасывает все эти
состояния.

Пайплайн не привязан к форматам, в которые рисует; он создаётся под цели
каждого прохода при первой привязке в нём. Входы вершинного шейдера читаются
в порядке location, один за другим, из одного упакованного элемента,
разложенного так, как struct в Faloya раскладывает свои поля:
`struct Vertex { pos: float3, uv: float2 }` питает
`layout(location = 0) in vec3` и `layout(location = 1) in vec2`. Входы с
`instance_location` и дальше приходят по экземпляру из вершинного буфера 1,
а `formats[location]` переопределяет формат location
(`VERTEX_UBYTE4_NORM` для цвета четырьмя байтами, `VERTEX_HALF2` и
остальное из `VERTEX_*`). Примитивы
`TRIANGLES`, `TRIANGLE_STRIP`, `LINES`, `LINE_STRIP`, `POINTS`; отсечения
`CULL_NONE`, `CULL_FRONT`, `CULL_BACK` (передние грани против часовой, если не
задан `clockwise`); смешивания `BLEND_NONE`, `BLEND_ALPHA`, `BLEND_ADD`,
`BLEND_PREMULTIPLIED`, `BLEND_MULTIPLY`.

Uniform-блоки раскладываются по std140, тогда как структуры Faloya упакованы.
В std140 член vec3 или vec4 начинается на кратности 16 байтам, а размер блока
округляется вверх до 16, поэтому соответствующая структура требует заполнения
(`struct Place { rect: float4, depth: f32, pad 12 }`). Передача структуры,
чей размер отличается от блока шейдера, - злоупотребление. На Direct3D 12
`gl_InstanceIndex` шейдера не учитывает `first_instance` отрисовки, поэтому
держите `first_instance` равным 0, если шейдер читает `gl_InstanceIndex`.

## audio

Процедурные звуковые эффекты PCM поверх SDL3, независимые от окна или
графического устройства. `import audio;` использует пространство имён
`audio::`. Это модуль пакета `gfx`
([faloya_gfx](https://github.com/mel0k1/faloya_gfx)). Он компилируется в
компилятор с `-DFALOYA_BUILTIN_LIBS=all`, а иначе собирается при первом
использовании; `faloya build` его линкует. Микшер описан в
[docs/audio.md](https://github.com/mel0k1/faloya_gfx/blob/main/docs/audio.md)
пакета.

| Функция | Поведение |
|---|---|
| `available() -> bool` | Истинно, когда нативный слой слинкован; без опроса устройства. |
| `open(sample_rate = 48000) -> bool` | Открывает устройство вывода по умолчанию, стереовыход. |
| `open_offline(sample_rate = 48000) -> bool` | Открывает тот же микшер без устройства и фонового потока. |
| `close()` | Останавливает воспроизведение, освобождает все звуки, лишает силы хэндлы; повтор безопасен. |
| `create_sound(samples: const f32[:], sample_rate = 48000, channels = 1) -> Sound` | Копирует моно или чередующееся стерео PCM в собственное хранилище. |
| `release_sound(sound) -> bool` | Останавливает его голоса и освобождает PCM. Ноль безвреден. |
| `play(sound, volume = 1.0, pan = 0.0, pitch = 1.0, looping = false) -> Voice` | Запускает независимый голос, допуская перекрывающиеся повторы. |
| `playing(voice) -> bool` | Смешивается ли ещё голос. Протухшие/нулевые хэндлы возвращают false. |
| `stop(voice)`, `stop_all()` | Останавливает один или все голоса. Завершённые/протухшие/нулевые голоса безвредны. |
| `set_voice(voice, volume, pan, pitch) -> bool` | Меняет живой голос без перезапуска. |
| `voice_position(voice) -> f64` | Секунды в звуке играющего голоса; -1, когда он не играет. |
| `seek(voice, seconds: f64) -> bool` | Перемещает играющий голос на столько секунд в его звуке. |
| `render(out: f32[:]) -> bool` | Только офлайн: пишет чередующийся стереовыход и двигает воспроизведение. |
| `error() -> u8[>..]` | Последняя неудача; успешные вызовы её не очищают. |
| `error_into(out: u8[:]) -> i64` | Копирует столько текста ошибки, сколько влезает, возвращая полную длину. |

Все вызовы выполняются на главном потоке; вызовы, достижимые из `thread_fn`,
отвергаются.
`Sound { id: u64 }` и `Voice { id: u64 }` - явные ресурсы. Создание звука
сразу копирует источник: после этого Faloya может изменять или освобождать
свой массив. Освобождение звука останавливает все его голоса. Завершённые
голоса перерабатываются автоматически. Новый ресурс никогда не совпадает со
старым хэндлом, даже через `close()` и `open()`.

Микшер один, не более `MAX_SOUNDS = 256` звуков и `MAX_VOICES = 64`
одновременных голосов. Исчерпание возвращает ноль, не отбирая голос. Частоты
8000..192000 Гц. PCM должен быть непустым, конечным, в `[-1, 1]`, с полными
кадрами (два сэмпла на стереокадр). Громкость `0..1`; панорама `-1..1`,
центр в нуле, ослабляет противоположный канал; высота `0.125..8` и меняет
скорость и длительность вместе. Смешивание использует линейную интерполяцию и
обрезает итоговую сумму до `[-1, 1]`. Оставляйте запас, когда накладывается
много эффектов.

Неверные аргументы, протухшие звуки, недоступные устройства и исчерпание
ресурсов возвращают false или нулевой хэндл и задают `error()`. Они не
останавливают программу аварийно. Остановка или опрос завершённого голоса
нормальны; обновление возвращает false. Офлайн `render` требует чётного числа
сэмплов, допускает пустой вывод и двигает ровно на `out.len / 2` кадров.
Режим устройства двигается автоматически; `playing()` описывает микшер,
поэтому немного аудио, уже буферизованного устройством, может остаться после
завершения или остановки. `voice_position` учитывает эту буферизацию: с
устройством она сообщает то, что слышит слушатель, сглаженное между колбэками
устройства, поэтому может держать что-то в такт со звуком. Офлайн это
собственная позиция микшера. `seek` за конец оборачивает зацикленный голос и
двигает любой другой к его последнему кадру; отрицательная позиция даёт
неудачу. В модуле нет декодирования файлов, потокового ввода, записи или
эффектов.

```faloya
import audio;
import math;
import os;

fn main() {
    if !audio::open() { print(audio::error()); return; }
    var pcm: f32[>..] = [];
    for i in 12000 {
        let t = i as f64 / 48000.0;
        let envelope = 1.0 - i as f64 / 12000.0;
        pcm.push((sin(TAU * 440.0 * t) * 0.2 * envelope) as f32);
    }
    let tone = audio::create_sound(pcm);
    let voice = audio::play(tone);
    while audio::playing(voice) { sleep_ms(5); }
    sleep_ms(100); // Дадим устройству доиграть уже смешанный хвост.
    audio::close();
}
```

## physics

Физика твёрдых тел на Box3D: миры, тела, фигуры всех видов, какие есть в
Box3D, девять видов суставов, события контакта, сенсора, удара, движения и
суставов, броски лучей и фигур, запросы перекрытия, персонажный движитель, а
также запись и воспроизведение.
Как и `gfx`, модуль опционален: он требует компилятор, собранный с сабмодулем
`third_party/box3d`, а программа, его использующая, линкует то, что печатает
`faloya --physics-link msvc|cc` (`cl game.c @<it>`,
`cc game.c -o game @<it>`; программа, использующая ещё и `gfx`, добавляет
ответный файл gfx). Компилятор, собранный без него, всё равно проверит типы и
сгенерирует C для такой программы; провалится только запуск программы внутри
процесса.
Всё в пространстве имён `physics`; `samples/28_physics_boxes.fal` - полная
программа, а
[docs/physics.md](https://github.com/mel0k1/faloya_physics/blob/main/docs/physics.md)
пакета рассказывает, как он устроен.

API - это Box3D под именами Faloya: `b3Body_GetPosition` - это
`position(body)`, `b3CreateRevoluteJoint` - это `create_revolute_joint`,
геттер использует имя свойства, а сеттер ставит перед ним `set_`. Box3D
работает в метрах, килограммах и секундах и не имеет встроенного направления
вверх; гравитация по умолчанию - -10 по y. Там, где Box3D принимает колбэк,
этот API использует другие формы: события и результаты запросов возвращаются
свежими массивами (у каждого есть и форма `_into`, копирующая в предоставленный
вызывающим срез и возвращающая их число), а смешивание трения и упругости
выбирается из правил `MIX_*`. Пользовательские фильтры контактов, колбэки
предрешения, отладочная отрисовка и отдельное динамическое дерево не входят.

Физика выполняется на главном потоке; `thread_fn`, достающий до неё, -
ошибка компиляции. Box3D раскладывает шаг по собственным рабочим потокам,
столько, сколько просит `WorldDef.workers`, и результаты одинаковы при любом
числе воркеров.

### Ошибки

Вызов, который может провалиться по причинам вне программы, например
отсутствующий файл или точки, не образующие выпуклой оболочки, возвращает
false или нулевой хэндл, а `error()` говорит почему. Вызов, которого
программе делать не следовало, сообщается в момент свершения и пропускается,
а программа останавливается на следующем `step()`, `destroy(world)` или
`check()`. Примеры: уничтоженное тело, вращательная функция на призматическом
суставе, поле высот на динамическом теле. Каждый хэндл несёт поколение,
поэтому использование уничтоженного объекта сообщается как ошибка вместо
падения.
