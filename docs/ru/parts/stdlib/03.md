Все функции `checkfree` (спецификация §7.14).

Поэлементные `+ - * /` встроены в язык (`a + b`, `p - q`), как и унарный
минус для вектора из чисел с плавающей запятой или знаковых целых (`-v`).

масштабирующая `float3`, требует явного `as f32`. Покомпонентные
`min`/`max` записываются развёрнуто (`min(a.x, b.x)`).

## math

Модуль `math` открывает libm на обеих ширинах (`sin(x)` выбирает `sin` или
`sinf` по типу аргумента): `sqrt sin cos tan asin acos atan atan2 exp log log2 log10
pow hypot cbrt exp2 expm1 log1p sinh cosh tanh floor ceil round trunc
copysign`. Они возвращают числа с плавающей запятой, как C (`as i64`
приводит к целому). `expm1(x)` и `log1p(x)` - это `exp(x) - 1` и
`log(1 + x)` без потери цифр маленького `x`; `copysign(x, y)` - модуль `x` со
знаковым битом `y`, что отличает `-0.0` от `0.0`.
`sqrt` реализован в рантайме (`gs_sqrt`, `gs_sqrtf`). Он даёт тот же
корректно округлённый корень, что C, и NaN ниже нуля, но без errno из C, так
что там, где компилятор C позволяет, это голая инструкция извлечения корня.
Остальные функции, для которых C выставляет errno (от `sin` до `tanh`), -
собственные функции libm под именами рантайма (`gs_exp`, `gs_expf`, ...), о
которых gcc и clang предупреждены, что те зависят только от своих аргументов.
Поскольку в Faloya нет errno, вызов не заставляет компилятор C перезагружать
значения, которые цикл вокруг вызова держит в регистрах. Оба компилятора всё
же знают их как функции libm, поэтому сворачивают константные аргументы и
объединяют `sin` и `cos` одного значения в один вызов `sincos`, где это есть
в библиотеке C. Целочисленный аргумент приводится к обеим ширинам одинаково
хорошо, поэтому вызов должен назвать одну (`sqrt(n as f64)`);
`sqrt(n * 0.5)` вызывает версию `f64`, как и `sqrt(0.5)`.

`mul_add(x, y, z)` на обеих ширинах - это `x * y + z` с одним округлением
там, где код собран под FMA, и с двумя, где нет. Какой вариант получает
вызов, решает реализация (спецификация §7.12). Бэкенд C округляет один раз на
arm64, на x86-64, собранном под AVX2 или новее (`-march=x86-64-v3`,
`/arch:AVX2` у clang-cl), и в версиях AVX2 и AVX-512 `simd fn`. В остальных
случаях, под MSVC и под JIT, он округляет дважды. Записанное явно
`x * y + z` всегда округляет дважды.

Два способа округления могут давать сильно разные результаты, а не отличаться
лишь последним битом:

- **Взаимное уничтожение.** Там, где `x * y` и `z` почти взаимно уничтожаются,
  слитный результат сохраняет младшие биты произведения, а неслитный их
  теряет, поэтому один может быть нулём там, где другой нет.
  `mul_add(x, x, -(1.0 + 2.0 * (x - 1.0)))` при `x = 1 + 2^-30` даёт `2^-60`
  слитно и `0.0` неслитно, и ветвление по нему может пойти в любую сторону.
- **Переполнение.** `mul_add(1.0e308, 2.0, -1.0e308)` даёт `1.0e308` слитно,
  но `inf` неслитно, потому что произведение переполняется до сложения.

Внутри `simd fn` сливаются только вызовы, которые Faloya порождает в
собственном теле этой функции: её собственный код и функции, которые Faloya в
неё встраивает. Вызов в обычной вспомогательной функции, которую вызывает
`simd fn`, сохраняет округление помощника, даже если компилятор C позже
встроит помощника. Встраивает ли Faloya маленького помощника, зависит от
уровня оптимизации, поэтому перенос `mul_add` в помощника может изменить и
результат, и скорость между `-O0` и `-O2`.
Пометка помощника `inline fn` сохраняет слияние его вызовов в
`simd`-вызывающих на каждом уровне, кроме `-O0`, где Faloya ничего не
встраивает. Значение функции разрешается при компиляции, поэтому `simd fn`,
получивший `mul_add` как такое значение (`F(x, y, z)`, где `F` это `mul_add`),
сливает, как прямой вызов.

В модуле также есть:

```faloya
let PI = 3.141592653589793;   let TAU = 6.283185307179586;
let E = 2.718281828459045;    let INF = 1.0 / 0.0;   let NAN = 0.0 / 0.0;
fn radians(deg: f64) -> f64   fn degrees(rad: f64) -> f64      // и f32
fn is_nan(x: f64) -> bool     fn is_inf(x: f64) -> bool        // и f32
fn is_finite(x: f64) -> bool                                   // не inf и не NaN; и f32
fn fract(x: f64) -> f64                                        // x - floor(x); и f32
fn inverse_lerp(a: f64, b: f64, v: f64) -> f64                 // (v - a) / (b - a); и f32
fn smoothstep(edge0: f64, edge1: f64, x: f64) -> f64           // и f32
fn wrap_angle(x: f64) -> f64                                   // в [-PI, PI); и f32
```

`fract`, `smoothstep` и `inverse_lerp` следуют GLSL и `lerp` из std:

- `fract(x)` - это `x - floor(x)`, поэтому она никогда не отрицательна:
  `fract(-0.25)` даёт `0.75`. Крошечный отрицательный `x` округляется к
  `1.0`, как в GLSL.
- `inverse_lerp(a, b, v)` обращает `lerp(a, b, t)`: 0 при `a`, 1 при `b`, без
  ограничения, поэтому `v` за `b` даёт больше 1. При `a == b` это NaN или
  бесконечность.
- `smoothstep(edge0, edge1, x)` равен 0 до `edge0`, 1 от `edge1` и
  `3t² - 2t³` от ограниченного `t = inverse_lerp(edge0, edge1, x)` между
  ними. Переставленные края прогоняют его назад. Равные края, которые GLSL
  оставляет неопределёнными, дают 0 ниже края, 1 выше и NaN на нём.
- `wrap_angle(x)` прибавляет или отнимает целые обороты, чтобы привести
  радианы в `[-PI, PI)`, как сделал бы остаток с округлением вниз: `PI`
  оборачивается в `-PI`, а `-0.0` остаётся `-0.0`. Границы формы f32 - это
  `PI`, округлённое до f32.

Каждая даёт NaN для аргумента NaN, а `fract` и `wrap_angle` дают NaN для
бесконечности. Знак `NAN` не специфицирован.
`INF` и `NAN` принимают тип, который требует контекст, как и `PI`
(`let inf32: f32 = INF;`).

Функции libm - `extern fn`, а перечисленные выше - `checkfree`, поэтому
функция `checkfree` (спецификация §7.14) может вызвать что угодно из math.

## os

Небольшой интерфейс к `src/runtime/runtime_os.h`:

```faloya

fn write_file(path: const u8[:], data: const u8[:]) -> bool
```

`trim_memory` просит ОС отбросить целые страницы за каждой текущей вершиной
стека данных в программе вызывающего потока, включая её глобальные переменные
и черновую память завершившихся областей видимости. Она сохраняет живые
значения, заимствованные представления, ёмкость массивов ограниченного
размера и резервирования виртуальных адресов; последующий рост работает как
обычно. Других воркеров она не затрагивает. Используйте её после большой
работы, например после замены документа, а не после каждого временного
значения. Обычный выход из области видимости оставляет страницы доступными
для дешёвого повторного использования, а усечённая страница вызывает отказ
страницы, когда стек снова растёт в неё.

Страницы освобождаются сразу. Windows отменяет их коммит, что возвращает и их
commit charge, а Linux сразу убирает их из резидентного набора.
macOS подменяет неиспользованный суффикс каждого резервирования свежей
анонимной памятью по тем же адресам. На всех трёх платформах снова растущий
стек получает свежие обнулённые страницы. Усечение в macOS покрывает всё
неиспользованное резервирование, поэтому обычному росту не нужны отслеживание
в рантайме или обработка сигналов. `false` означает, что хотя бы один запрос
к ОС не удался.

Пути на каждой платформе в UTF-8; в Windows рантайм переводит их в UTF-16 для
широких API системы. Значения переменных окружения и аргументы программы тоже
в UTF-8. В Windows аргументы сначала проходят через кодовую страницу ANSI,
поэтому в них остаются только символы этой страницы. Путь отклоняется и вызов
возвращает `false`, если он длиннее 4095 байт, содержит байт NUL или (в
Windows) не является корректным UTF-8, потому что путь, обрезанный или
декодированный иначе, мог бы назвать другой файл.

`read_file` при неудаче ничего не добавляет. `read_stdin` добавляет байты без
изменений, и в Windows тоже, где текстовый режим библиотеки C превратил бы
каждый `\r\n` в `\n` и остановился на Ctrl-Z. `read_line` убирает `\r` перед
переводом строки строки вместе с самим переводом. `read_stdin(out, max)`
добавляет до `max` байт и ждёт, пока получит их или ввод не кончится, поэтому
большой канал можно читать кусками. Она возвращает false, ничего не добавив,
если байт не осталось или `max` равен 0 или меньше. Интерактивный ввод
построчно остаётся за `read_line`.

`write_file_atomic` - для файлов, которые никогда нельзя видеть
недописанными, например для сохранений. Она пишет данные в новый файл в том
же каталоге, что `path`, названный по `path` со случайной пометкой и `.tmp`
на конце. Затем она сбрасывает этот файл на диск и переименовывает его поверх
`path`, сохраняя права `path` на POSIX. Падение или сбой в любой точке
оставляет `path` либо со старым содержимым, либо со всем новым. При сбое
новый файл удаляется; после падения он может остаться, с именем,
оканчивающимся на `.tmp`.
`rename_file` делает ту же замену одним шагом для файла, который программа
написала сама, в пределах одного тома. В Windows файл нельзя подменить, пока
другая программа держит его открытым, а антивирусы ненадолго открывают только
что записанные файлы, поэтому обе функции ждут такой файл до секунды, прежде
чем вернуть `false`.

`list_dir` пропускает `.` и `..` и сортирует имена побайтово, поэтому выдача
не зависит от файловой системы. Имя, которое нельзя записать одной строкой
UTF-8 (имя POSIX с переводом строки или имя Windows, не являющееся корректным
UTF-16), тоже пропускается. При неудаче ничего не добавляется.

```faloya
var names: u8[>..] = [];
if list_dir("saves", names) {
    each_split(names, '\n') { if it.len > 0 { load_save(str("saves/", it)); } };
}
if !write_file_atomic("saves/slot1.sav", image) { write_stderr("not saved\n"); }
```

### Ресурсы приложения

Обычные относительные пути разрешаются от рабочего каталога процесса, как в
C/C++. Faloya не меняет этот каталог при запуске программы.
Для данных, распространяемых с приложением, `resource_dir()` возвращает
абсолютный UTF-8 каталог с завершающим разделителем, готовый к конкатенации:

```faloya
var wad: u8[>..] = [];
if !read_file(str(resource_dir(), "data/map.wad"), wad) {
    abort("cannot read map.wad");
}
```

В JIT-запусках корень - каталог входного исходника, независимо от того, какой
импортированный модуль вызвал помощника. В AOT-программах это каталог
исполняемого файла, который определяется в рантайме, а не записывается при
компиляции. В обычном пакете `.app` macOS это `Contents/Resources/`.
Размещайте данные относительно этого корня; перенос исполняемого файла вместе
с данными сохраняет поиск ресурсов. AOT-программа не зависит от исходного
дерева исходников или рабочего каталога запустившего процесса. Разделяемая
библиотека, которую блок `extern "..." { }` называет с разделителем пути,
например `"bin/steam_api64"`, открывается относительно того же корня
(спецификация §7.10), поэтому библиотека, лежащая рядом с программой,
находится так же, как её данные.

Форма, возвращающая строку, аварийно останавливается, если каталог не удаётся
обнаружить; перегрузка с конструктором возвращает false и ничего не
добавляет. Нативное обнаружение поддерживает Windows, Linux и macOS. Этот
каталог предназначен для поставляемых ресурсов; записываемость не
гарантируется. Пользовательские пути, вывод и сохранения могут продолжать
пользоваться обычными файловыми операциями и выбранными для них местами.

`exit(code)` и `abort(msg)` - встроенные операции, чтобы проверяющий знал об
их расхождении. Подпроцессы и сеть не входят в v1; они придут как
`extern fn`, когда программе понадобятся.

## ffi

```faloya
fn cstr(p: u64, out: u8[>..]&) -> bool       // строка C по адресу p, без её NUL; false для null
fn cstr(p: u64) -> u8[>..]                   // то же, новая; пустая для null
fn bytes(p: u64, n: i64, out: u8[>..]&) -> bool   // n байт по адресу p; false для null
fn bytes(p: u64, n: i64) -> u8[>..]
```

Эти функции читают память, которой владеет библиотека C. Функция, связанная из
разделяемой библиотеки
(спецификация §7.10, [reference.md §24](reference.md#24-calling-c-and-being-called-from-c)),
возвращает `const char *` или массив, который держит библиотека, как `u64`,
сквозь который Faloya читать не умеет. Эти функции копируют данные в
хранилище Faloya, поэтому чужая память никогда не становится значением Faloya
без копии.
Они доверяют указателю и длине, как каждый extern-вызов доверяет C: неверный
указатель или длина - такая же ошибка, как в C, и она не ловится. Нулевой
указатель ничего не добавляет и даёт результат `false`.

```faloya
import ffi;
extern "SDL2" {
    fn SDL_Init(flags: u32) -> i32;
    fn SDL_GetError() -> u64;
}
if SDL_Init(0x20) < 0 { abort(str("SDL: ", ffi::cstr(SDL_GetError()))); }
```

## binary

Проверяемые чтения и добавляющие записи внешних форматов, little- и
big-endian, написанные на Faloya (числа с плавающей запятой проводят свои биты
через маленькие помощники рантайма). `import binary;` кладёт API в
пространство имён `binary`. Вход - `const u8[:]`;
возвращаемые байтовые срезы и имена фиксированной ширины заимствуют этот вход
без копирования или выделения памяти. Их времена жизни и доступ только на
чтение проверяются как обычно.
Этот API не разбирает образы сериализации Faloya (`from_bytes`).

```faloya
fn read_u64le(data: const u8[:], at: i64) -> u64, bool    // и read_u64be
fn read_i64le(data: const u8[:], at: i64) -> i64, bool    // и read_i64be
fn read_f32le(data: const u8[:], at: i64) -> f32, bool    // и read_f32be
fn read_f64le(data: const u8[:], at: i64) -> f64, bool    // и read_f64be
fn read_bytes(data: const u8[:], at: i64, size: i64) -> const u8[:], bool
fn read_name(data: const u8[:], at: i64, width: i64) -> const u8[:], bool
```

Смещения и размеры - в байтах. Отрицательные значения, обрезанные поля и
смещения за концом дают неудачу с нулём или пустым срезом и `false`; проверка
диапазона не переполняется на крайних смещениях или размерах. Пустой диапазон
на конце корректен. Чтения работают по невыровненным смещениям при любом
порядке байтов хоста. Чтения `le` берут младший байт первым, чтения `be` -
старший. Чтение числа с плавающей запятой сохраняет биты значения точно,
включая полезную нагрузку NaN.
`read_name` проверяет всё поле фиксированной ширины и возвращает байты до
первого NUL, а если NUL нет - все `width` байт. Она не проверяет заполнение и
не трактует байты как конкретную текстовую кодировку.

### Курсор и ограниченные подчитчики

```faloya
struct Reader { data: const u8[:], pos: i64 }
fn reader(data: const u8[:]) -> Reader
fn read_u8(r: Reader&) -> u8, bool
fn read_u16le(r: Reader&) -> u16, bool    // у каждого чтения по смещению есть форма с курсором
fn read_bytes(r: Reader&, size: i64) -> const u8[:], bool
fn read_name(r: Reader&, width: i64) -> const u8[:], bool
fn skip(r: Reader&, size: i64) -> bool
fn subreader(r: Reader&, size: i64) -> Reader, bool
```

Курсор хранит только свой вход и байтовую позицию. Каждое чтение возвращает
собственный флаг успеха. Успех двигает `pos` (на полную ширину для имени);
неудача возвращает ноль/пустоту и оставляет `pos` без изменений, поэтому
следующим можно попробовать более короткое чтение. Присваивайте `pos` для
позиционирования; отрицательная или вне диапазона позиция делает чтения
неудачными. Вызывающий код сам хранит нужные ему смещения в файле или
диагностический контекст. Липкого состояния ошибки нет.

`subreader` изымает ограниченный диапазон у родителя и выдаёт новый курсор с
нулевой позиции. Неудача возвращает пустого читателя и `false`, оставляя
родителя на месте. Держите родителя в области видимости, пока пользуетесь
дочерним курсором или возвращёнными срезами; текущий анализ ссылочных
результатов может связать их время жизни с родителем.

```faloya
// data владеет байтами файла. Первые четыре байта дают длину полезной нагрузки.
var r = binary::reader(data);
let size, size_ok = binary::read_u32le(r);
if !size_ok { abort("missing payload length"); }
var payload, payload_ok = binary::subreader(r, size);
if !payload_ok { abort("truncated payload"); }
let version, version_ok = binary::read_u16le(payload);
let name, name_ok = binary::read_name(payload, 8);
if !version_ok || !name_ok { abort("truncated payload header"); }
// name заимствует data. payload не может читать в следующую запись.
```

Для произвольного доступа используйте чтения по смещениям, для
последовательных записей - курсоры.
Приложения по-прежнему сами проверяют подписи, счётчики, индексы и
специфичные для формата пределы после проверки чтения. Загрузчик WAD в
[`31_mini_doom.fal`](../../samples/31_mini_doom.fal) показывает оба стиля.

### Записи

```faloya
fn write_u8(out: u8[>..]&, v: u8)
fn write_i8(out: u8[>..]&, v: i8)
fn write_u16le(out: u8[>..]&, v: u16)    // и write_u16be
fn write_i16le(out: u8[>..]&, v: i16)    // и write_i16be
fn write_u32le(out: u8[>..]&, v: u32)    // и write_u32be
fn write_i32le(out: u8[>..]&, v: i32)    // и write_i32be
fn write_u64le(out: u8[>..]&, v: u64)    // и write_u64be
fn write_i64le(out: u8[>..]&, v: i64)    // и write_i64be
fn write_f32le(out: u8[>..]&, v: f32)    // и write_f32be
fn write_f64le(out: u8[>..]&, v: f64)    // и write_f64be
```

Каждая запись добавляет байты значения в `out` в том порядке, в каком их
берёт одноимённое чтение, поэтому запись, за которой следует такое чтение,
возвращает значение.
Запись числа с плавающей запятой сохраняет биты значения точно, включая
полезную нагрузку NaN. Записи не могут дать сбой; `out` растёт, как при
добавлении.

```faloya
var out: u8[>..] = [];
binary::write_u32be(out, 0x89504E47);    // подпись, старший байт первым
binary::write_u16le(out, 3);
binary::write_f32le(out, 1.5);
let version, version_ok = binary::read_u16le(out, 4);
assert(version_ok && version == 3);
```

### Патчи, заполнение и окна

```faloya
fn write_bytes(out: u8[>..]&, data: const u8[:])             // дописывает целый срез
fn zeros(out: u8[>..]&, size: i64)                           // дописывает size нулевых байтов
fn align(out: u8[>..]&, to: i64) -> i64                      // добивает до кратности `to`, возвращает новую длину
fn reserve(out: u8[>..]&, size: i64) -> i64                  // оставляет size нулевых байтов, возвращает смещение для будущего патча
fn patch(out: u8[>..]&, at: i64, data: const u8[:]) -> bool  // копирует data поверх уже записанных байтов
fn patch_u8(out: u8[>..]&, at: i64, v: u8) -> bool           // и patch_i8
fn patch_u16le(out: u8[>..]&, at: i64, v: u16) -> bool       // и остальные ширины чтений, le и be
fn patch_f64be(out: u8[>..]&, at: i64, v: f64) -> bool
fn window(out: u8[>..]&, at: i64, size: i64) -> u8[:], bool  // изменяемое окно в память буфера
fn left(r: Reader) -> i64                                    // сколько байтов ещё не прочитано
fn done(r: Reader) -> bool                                   // курсор дошёл до конца
fn remaining(r: Reader&) -> const u8[:]                      // окно непрочитанного хвоста
```

Записи добавляют байты в конец; `patch_*` переписывает байты, которые уже
лежат в буфере, по абсолютному смещению, не меняя его длины. Так писатель
возвращается и исправляет длину или цель перехода, которые становятся
известны позже. Каждый патч проверяет диапазон по `out.len` тем же правилом
без переполнения, каким проверяются чтения по смещениям: на отрицательном
или выходящем за границы смещении возвращает `false` и не трогает буфер,
при успехе `true`. Пустой патч в конце валиден. Патч числа с плавающей
запятой сохраняет биты значения точно.

`window` отдаёт изменяемое окно прямо в память буфера: записи через него
попадают в сам `out`, копирования нет (элементы grow-only массива не
двигаются). Окно покрывает байты, существовавшие на момент среза, и не
растёт вместе с новыми `push`. Пара `reserve` и `patch` - обычный способ
для поля, значение которого известно только после записи остальных данных.

`left`, `done` и `remaining` читают позицию курсора: сколько байтов ещё не
прочитано, дошёл ли курсор до конца, и окно непрочитанного хвоста,
занимающее данные курсора. `remaining` не двигает `pos`.

```faloya
var out: u8[>..] = [];
let size_at = binary::reserve(out, 2);       // поле длины, заполняется позже
binary::write_bytes(out, "hello");
binary::write_bytes(out, "world");
let size = out.len - 2;
binary::patch_u16le(out, size_at, size as u16);
binary::align(out, 4);
let w, w_ok = binary::window(out, 2, 5);
w[0] = 'H';                                  // "Hello" на месте, без копии
var r = binary::reader(out);
binary::skip(r, 2);                          // мимо поля длины
let payload, ok = binary::read_bytes(r, binary::left(r));
```

## base64

Base64, как определено в RFC 4648 §4: стандартный алфавит (`A`-`Z`, `a`-`z`,
`0`-`9`, `+`, `/`) и заполнение `=`. `import base64;` кладёт его в
пространство имён `base64`.

```faloya
fn encode(out: u8[>..]&, src: const u8[:])            // добавляет 4 символа на 3 байта, с заполнением
fn decode(out: u8[>..]&, src: const u8[:]) -> bool    // добавляет байты; false, если src некорректен
```

`decode` принимает только полные группы из четырёх символов, последняя может
оканчиваться на `=` или `==`. Она отвергает переводы строк, пробельные
символы, текст без заполнения и другие алфавиты (`-` и `_` из URL-безопасного
алфавита недопустимы).
Она не требует, чтобы биты, оставшиеся перед заполнением, были нулями,
поэтому `Zh==` декодируется так же, как `Zg==`; большинство декодеров это
допускают. На некорректном входе она возвращает `false` и оставляет `out`
как был.

```faloya
var text: u8[>..] = [];
base64::encode(text, "foobar");              // "Zm9vYmFy"
var bytes: u8[>..] = [];
if !base64::decode(bytes, text) { abort("not base64"); }
```

Кодек вычисляет алфавит, а не смотрит его в таблице, поэтому компилятор C
векторизует оба цикла. Оба также являются `simd fn` (спецификация §7.12):
когда clang собирает под x86-64, они работают как код AVX2 или AVX-512 на
поддерживающем это CPU, в несколько раз быстрее, чем с базовой SSE2.

## csv

Значения, разделённые запятыми, как определено в RFC 4180. `import csv;`
кладёт читатель и экранирование писателя в пространство имён `csv`.

```faloya
fn each_record<F>(text: const u8[:], sep: u8 = ',') -> bool    // F(fields: const u8[:][:]) на каждую запись
fn format_field(out: u8[>..]&, s: u8[:], sep: u8 = ',')         // s, с экранированием, где оно нужно
```

`each_record` передаёт поля каждой записи своему блоку по порядку, как срезы
текста. Ничего не копируется, а срез полей принадлежит читателю и
переиспользуется для следующей записи. Поле может быть в кавычках, и поле в
кавычках может содержать разделители, переводы строк и удвоенные кавычки,
каждая из которых означает одну кавычку. Поле в кавычках передаётся без
окружающих кавычек, с удвоенными кавычками как есть. Поскольку поле без
кавычек не может содержать кавычку,
`format_replaced(out, field, "\"\"", "\"")` добавляет текст любого поля.
Записи кончаются на LF или CRLF, кроме последней записи, которой это не
обязательно.
Пустая строка - запись из одного пустого поля, а заголовок - запись, как
любая другая. Пробелы вокруг поля - часть поля. `sep` может быть любым
байтом, кроме кавычки или перевода строки, например `';'`, или `'\t'` для
значений, разделённых табуляцией.

`each_record` возвращает `false` на первой испорченной записи, передав своему
блоку все предыдущие записи; блок испорченную запись не видит. Запись
испорчена, если в ней есть кавычка в поле без кавычек, поле в кавычках без
закрывающей кавычки или что-то, кроме разделителя или перевода строки, после
закрывающей кавычки. `return` в блоке выходит из функции, вызвавшей
`each_record`, как и в любом блоке.

```faloya
var total = 0.0;
let ok = csv::each_record(text) { fields =>
    let price, valid = parse_flt(fields[2]);
    if valid { total += price; }
};
if !ok { abort("malformed CSV"); }
```
