  которую держит временное значение, из снятого элемента или из значения
  управляющей конструкции, копирующей значение своей ветви даже там, где оно
  называет хранилище (§4.1). Поля или элементы такого значения, держащие
  самоотносительные ссылки, не читаются, не срезаются и не итерируются;
  `match` не связывает его payload по ссылке; а `print`, рендерящий ссылку
  как её указуемое, само значение не рендерит. Скалярное поле такого значения
  читается как обычно (`a.pop().v`).

  Стройте такие значения на месте, литералами. Поле, которое заполняет `..`
  литерала, берёт значение по умолчанию своего типа, у которого ссылки равны
  null, а ограниченные массивы пусты, и не является копией. Связывайте их
  payload match по ссылке, и пусть case-функции принимают свои варианты по
  ссылке, а перегрузки `format` - тоже по ссылке. АТД, чьи payload держат
  самоотносительные ссылки, используется в переменном режиме, чьи payload
  связываются по ссылке там, где АТД не изменяемый (§3.5).

  Результат вызова по значению тоже не копия, поскольку он строится там, где
  принимается (§4.3, §7.3); это включает агрегат фиксированного размера и
  свежий результат завершающего блока. Ссылки на существующие элементы
  требуют, чтобы принимающее хранилище и эти элементы делили точный корень,
  проверяемый при каждом вызове, включая перенаправленные и рекурсивные
  вызовы. Слот аргумента, отброшенный результат или временное значение
  операнда не наследует корень объемлющего результата. Результат, полагающийся
  на этот корень, не может быть значением заполнения resize и не может
  проходить преобразование представления, которое промежуточно размещает или
  перемещает его байты; вариант может строиться за тегом своего АТД.

  Именованный результат функции (§7.3) тоже не копия: это локальное значение,
  которое даёт каждый return функции, построенное в назначении согласно
  объявлению. Именованный результат, являющийся структурой, заканчивающейся
  изменяемым значением, требует, чтобы поля до его изменяемого хвоста были
  свободны от самоотносительных ссылок и от всего, на что указывает
  самоотносительная ссылка в хвосте, поскольку эти поля достигают вызывающего
  как копия (C.3). И значение по умолчанию (`..` литерала, `default<T>()`)
  не копия: его ссылки - null, или `self` там, где значение поля по умолчанию
  это задаёт.
  (TODO 16: отслеживать область, над которой пробегает относительная ссылка,
  чтобы можно было разрешить доказуемо покрывающие всю область копии.)
* Поскольку структуры, связанные самоотносительными ссылками, не зависят от
  позиции, их можно сериализовать или отображать напрямую: `to_bytes(a)`
  записывает образ массива, `bytes_of(a)` смотрит его без копирования, а
  `from_bytes<T[>..]>(bytes)` проверяет образ обратно внутрь (§12,
  `../design/serialization.md`). Без проверки приходящие байты были бы
  единственным местом, где ссылка могла бы войти в программу недоказанной
  (§9.4). Проверка - ещё и причина, по которой вид `bytes_of` никогда не
  записываем: байты, записанные через него, были бы связями, которые
  проверяльщик никогда не доказал.

**Пул-относительная (`in pool`).** `pool` называет *глобальный* `var` (или
`reusable var`) только растущего изменяемого типа (`[>..]`), чьё хранилище
может вместить `T` по значению: как элемент или как поле элемента по
значению, транзитивно (кандидатное понятие из §9.5). Всё остальное - ошибка
компиляции. Для локального или параметрического пула ошибка указывает на
самоотносительную форму, поскольку пул называется там, где объявлено поле, а
имя локального значения там ничего не значит.

Имя может также выбирать изменяемое прямое поле-массив глобального `var`
`root struct`, как в `Node&<u32 in nodes.items>`. Имя владельца может быть
квалифицировано пространством имён. Компилятор разрешает объявление и поле
статически; псевдонимы, пересечения ссылок, индексация массивов и вложенные
пути полей не поддерживаются. Каждый компонент - отдельная идентичность пула
со своей базой. Те же требования только-растущности, вмещения указуемого и
ширины применяются к полю-массиву.

* Пул - часть идентичности типа: `Node&<u32 in pool>` - ни `Node&<u32>`, ни
  `Node&<u32 in spare>`. Загрузка любой формы даёт обычную `Node&`, а запись
  перекодирует.
* Хранимое значение - `(target - base(pool)) + 1`, беззнаковое, поэтому 0 -
  это null опциональной формы, а ширина `uN` покрывает пул до
  2^N - 1 байт; `varint` - беззнаковая LEB-форма (§3.6). Загрузка -
  `base(pool) + stored - 1`, и результат - `T&`, укоренённая в `pool`
  *точно* (§9.2), откуда бы её ни прочитали.
* Запись требует, чтобы корень значения был точно `pool`. Иначе ошибка
  называет корень значения или, при неточном чтении обратно, кандидатов,
  между которыми §9.5 не смог выбрать. Назначение может быть где угодно
  (другое глобальное, локальное, указуемое параметра), поскольку смещение не
  зависит от того, где оно хранится. Это допускает связи между массивами:
  массив слотов может держать 4-байтовые ссылки в пул. Поскольку пул
  глобальный, его время жизни удовлетворяет правилу записи из §9.2.
* Ширина ограничивает *пул*, а не расстояние между двумя концами, поэтому
  запись проверяется на диапазон ровно там, где резервирование пула может её
  превысить (§10.4): `u32` при резервировании 2 ГБ проверки не требует, а
  `u16` при любом реалистичном резервировании требует. `base(pool)` никогда
  не перемещается: область элементов только растущего глобального значения
  начинается с резервирования его стека, а рост только двигает вершину.
* Значение, чьи относительные поля *все* `in pool`, копируется как любое
  другое (присваивание, аргументы по значению, копии элементов, `pop`): его
  смещения не зависят от того, где оно лежит. Значение, смешивающее обе
  формы, - нет.
* Указывает ли *параметр* внутрь `pool`, решается в каждом месте вызова,
  поэтому функция, переставляющая связи (`fn front(head: Node&, n: Node&)`),
  специализируется по пулу, как и всякий другой корневой класс (§10.2), и не
  требует ничего передавать.

**Значения.** Относительная ссылка - хранилище (поле, элемент или переменная
либо параметр, чьё объявление пишет тип или псевдоним такого), никогда не
значение. Загрузка даёт обычную ссылку, и обычную ссылку получает всё
остальное. Результат функции не может быть объявлен относительным; объявите
обычную `T&` или `T?`, которую относительная ячейка, принимающая его,
закодирует. Результат, который аргумент типа делает относительным, например
`-> T` у `fn get<T>(a: T[>..]&, i: i64)` над массивом связей, - обычная
ссылка, как её даёт индексация. То же верно для переменной или параметра,
который аргумент типа делает относительным: `let t: T` и `v: T` над массивом
связей держат обычную ссылку. Так генерик-код, перемещающий элементы через
локальное значение типа `T` (`swap_at` из std, §3.8), перемещает связи,
перемещая обычные ссылки. Каждая запись обратно в элемент кодирует ссылку
заново, поэтому самоотносительная ссылка всё ещё обязана указывать внутри
корня того элемента, а ссылка `in pool` - внутри своего пула. Поле или
элемент типа `T` (`T[4]`, `struct Box<T> { x: T }`) - это связь.
`default<T>()` опциональной относительной ссылки аналогично - обычный null,
любой ширины.

**`self`.** Неопциональная относительная ссылка не имеет null, поэтому
значение, чьи связи указывают обратно на него самого (сигнальный элемент
циклического списка, первый узел пула), вообще нельзя было бы построить: нет
ничего, на что связи могли бы указывать. `self`, записанное как весь
инициализатор такого поля в литерале структуры или варианта, обозначает
значение, которое строит этот литерал:
`Node { key: -1, prev: self, next: self }`. Оно законно только там и только
когда тип поля - неопциональная относительная ссылка, чьё указуемое - тип
значения, строящегося литералом (для литерала варианта в любом режиме enum,
§3.5, это enum, включая тег). `self` во вложенном литерале называет литерал,
в котором написано, никогда объемлющий. Этот тип не должен быть изменяемым:
одно смещение не может достать до заголовка изменяемого значения. По той же
причине правило общего корня держит любую *другую* относительную ссылку
подальше от изменяемого значения. В самоотносительном поле хранимое смещение
равно минус собственное байтовое смещение поля внутри значения, поэтому это
единственная относительная ссылка, чей смысл не зависит от того, где
хранится значение. В поле `in pool` хранимое смещение - собственное смещение
значения в пуле, которое есть только у литерала, строящегося *внутри*
`pool`: в `push` или `append`, в `alloc_index`/`alloc_ref` или при записи
элемента в пул. Где-либо ещё `self` в поле `in pool` - ошибка компиляции.
Это позволяет структуре использовать неопциональные связи по всей длине.
Сигнальный элемент устраняет нужду в null-связях, а загрузка неопциональной
относительной ссылки требует только сложения, без проверки на null.

**Какая форма.** Самоотносительные ссылки используйте для не зависящих от
позиции блоков данных, таких как компактное дерево, сохраняемое, отображаемое
или перемещаемое целиком (однобайтовые связи с ближними узлами, см. A.2), и
для структур в локальном или параметрическом пуле, у которого нет имени для
записи. `in pool` используйте для структур с частой перестройкой связей в
глобальном пуле, где запись - вычитание из базы, уже лежащей в регистре, а
не из собственного адреса поля. Используйте её также для ссылок *в* этот пул
из других массивов, которые самоотносительные ссылки вообще не умеют
выражать, и там, где смещение нужно как индекс, поскольку `&pool[i]`
кодируется как `i * sizeof(T) + 1`, а `index_of` (§3.3) читает его обратно.

### 3.10 Срезы

`T[:]` - ссылка плюс количество элементов, ссылающаяся на непрерывный отрезок
`T` внутри некоторого корня. Срезы - универсальный параметрный тип "обработай
диапазон", объединяющий все представления массивов. Как ссылки, срезы несут
корень и полностью участвуют в системе времён жизни (§9), что предотвращает
висячие срезы. Это задуманный путь *чтения*, а изменение идиоматично идёт
через ссылки, но записи через срез законны, когда его происхождение
записываемо (§9.5).

* Создаются срезированием любого значения семейства массивов или среза:
  `a[x..y]` (x включительно, y исключительно; пропуск даёт 0 / len; `^k`
  значит "len - k") или выделением из пула срезов (§5.4). Массив или ссылка
  на массив, достигающая назначения, чей тип - срез его типа элемента,
  неявно становится срезом всего этого массива, как дал бы `a[..]`. Это
  преобразование применяется к параметрам, хотя перегрузка с точным типом
  имеет приоритет. Оно также применяется к проаннотированным объявлениям
  `let`/`var` и глобальным значениям; присваиваниям переменных, полей или
  элементов-срезов; полям литералов структур и вариантов и значениям полей по
  умолчанию; и элементам литералов массивов. Другие назначения: `push`,
  `return`, финальное выражение тела и ветвь, чья объемлющая конструкция
  имеет значение-срез (§6.4). Срез `const` там, где массив только для чтения
  (§9.5), и правила времён жизни трактуют его как любой другой срез (§9.2):
  `let s: const u8[:] = item.name;` смотрит на `item.name`, а
  `let s: const u8[:] = make();` связывает вид временного значения и является
  ошибкой. (Литерал массива с элементами переменного размера - не такой
  массив: у него нет временного значения для срезирования, §4.2.)
* Срезы массивов с элементами фиксированного размера индексируются и
  итерируются с проверкой границ против собственной длины среза. Срезы
  никогда не растут; сжать срез (пересрезировать) всегда безопасно.
* Срезы массивов с переменными элементами только итерируются (без
  индексации); количество - это число элементов.
* Срезы подчиняются тем же ограничениям, что и внутренние ссылки (§3.8):
  срез растущего-сжимаемого массива держится только переменными и обязан
  больше не быть живым к моменту следующего сжатия массива (§5.2).
* Срез только растущего изменяемого массива, взятый до роста, остаётся
  корректным (он не включает новые элементы).

### 3.11 Типы индексов и границ

*Тип индекса* `uN in a` - беззнаковое целое, которое ниже `a.len` везде, где
его можно наблюдать. *Тип границы* `uN upto a` - беззнаковое целое, которое
не больше `a.len`: конец диапазона. Индексация `a` индексом `a` не требует
проверки, и индекс, сохранённый в данных, сохраняет эту гарантию, куда бы
его ни скопировали.
Так индекс, загруженный из одного массива (цели рёбер графа, индексный буфер
меша), проверяется один раз, при входе в программу, а не везде, где
используется (`../design/index_types.md`).

```faloya
struct Node { lo: u32 upto edges, hi: u32 upto edges }
var nodes: Node[>..] = [];
type NodeId = u32 in nodes;
var edges: NodeId[>..] = [];
```

* `uN` - это `u8`, `u16`, `u32` или `u64`. `a` называет глобальный `var`
  (или `reusable var`) только растущего типа `T[>..]` с элементами
  фиксированного размера, разрешается там, где написан тип, как имя пула
  (§3.9). Всё остальное - ошибка компиляции: локальное значение или параметр
  не имеет имени там, где объявлен тип, любой другой вид массива может
  сжиматься, а последовательный массив нельзя индексировать.
  Изменяемое прямое поле-массив глобального `var` корня тоже допускается,
  как в `u32 in graph.nodes` или `u32 upto graph.edges`, с тем же разрешением
  имён компонентов, что в §3.9. Его идентичность и правило не-сжатия
  принадлежат этому компоненту, независимо от других полей владельца.
* Массив - часть идентичности типа: `u32 in nodes` - ни `u32`, ни
  `u16 in nodes`, ни `u32 upto nodes`, ни `u32 in edges`. Значение - обычное
  целое; C-тип - тип `uN`.
* Тип индекса не принимает собственного постфикса: массив таких -
  `(u32 in nodes)[>..]` или `NodeId[>..]` через псевдоним. У написанного
  типа связывателя `for` следует `in` цикла, поэтому тип индекса, написанный
  там, тоже берётся в скобки: `for w: (u32 in nodes) in ...`.
* **Создание.** `x as (uN in a)` для `x` любого целого типа аварийно
  завершает программу в любой сборке, если только `0 <= x < a.len`, с
  ошибкой, которую дал бы `a[x]`. Это проверка границ, и проход проверки
  границ убирает её там, где убрал бы `a[x]` (§10.5). `x as (uN upto a)` -
  то же с `x <= a.len`. Значение, которое `uN` не может вместить,
  преобразуется затем, как любое `as` (§6.3), и результат заворачивания всё
  ещё в диапазоне. `as!` не может создать тип индекса или границы.
  Преобразование к более широкой ширине типа того же массива неявно
  (`u16 in a` в `u32 in a`), и неявно преобразование типа индекса к типу
  границы его массива; остальные направления требуют `as`, который
  проверяет. Константа никогда не бывает типа индекса и никогда не
  подстраивается под него, поскольку о `a.len` во время компиляции ничего не
  известно.
* **Циклы.** `for i in lo..hi`, чьи границы оба - типы индекса или границы
  одного массива `a`, даёт `i` тип индекса `a` на их объединённой ширине,
  поскольку `lo <= i < hi <= a.len`. Счётный цикл `for i in n` с n типа
  индекса или границы делает то же.
* **Как число.** Значение неявно преобразуется к своему обычному целому
  типу, а дальше - как тот тип (§6.3). Операторы вычисляют с обычным
  значением, поэтому `w + 1`, `w << 3`, `-w` и `w & m` - обычные целые.
  Составное присваивание и `++`/`--` над ячейкой типа индекса - ошибки.
* **Сквозная передача.** Объявления без записанного типа, параметры,
  результаты, поля, payload АТД и элементы несут тип, и запись в любое из
  них принимает только значение этого типа. Значение ветви, `match` или
  блока имеет тип индекса или границы массива, где каждая ветвь имеет тип
  индекса или границы этого массива (на самой широкой ширине, и тип границы,
  если хоть одна ветвь - граница). Иначе это объединение обычных целых
  (`if c { w } else { 0 }` - `u32`). Ссылка или срез на хранилище с типом
  индекса - `(u32 in a)&` или `(u32 in a)[:]`, никогда `u32&` или `u32[:]`,
  которые могли бы записать любой `u32`. Аргумент типа может быть типом
  индекса, и каждая инстанциация проверяется с ним (§7.7).
* **Нет значения по умолчанию.** У типа индекса нет значения по умолчанию:
  `default<T>()`, `..` литерала, значение поля по умолчанию и глобальное
  значение без инициализатора все нуждаются в нём, а у пустого массива нет
  индекса вовсе.
* **Никогда не сжимается.** Массив, который называет тип индекса или
  границы, никогда не сжимается: `pop`, `pop_n`, `resize`, `clear` и целое
  присваивание ему - ошибки везде, напрямую или через ссылочный параметр,
  как и сжатие через ссылку, которая может лишь ограничивать хранилище
  такого массива (§9.5). Его длина только растёт, поэтому значение, однажды
  попавшее в диапазон, в нём остаётся.
* **Что остаётся вне.** `format` и `to_bytes(a, out)` не пишут в массив
  `u8 in x`, который не является байтовым массивом. Когда `from_bytes`
  проверяет образ, он проверяет каждый индекс в образе против длины своего
  массива и отвергает образ, если хоть один индекс вне диапазона. Аргументы
  `qput`, `qget`, `qpoll`, `qlimit` и `thread_spawn` не принимают тип,
  держащий тип индекса: копия массива в программе каждого потока растёт сама
  по себе (§11.2). Сигнатура `extern fn` или `export fn` тоже не держит
  таких, поскольку C-код не проверяется против массива.


## 4. Значения, копирование и присваивание

### 4.1 Всё является значением; передача по классу размера

В Faloya **семантика значений**: переменная, поле или элемент владеет своим
значением inline, а назначение (присваивание, аргумент, возврат, push,
инициализатор поля) получает собственное значение. Как значение попадает
туда, зависит от его класса размера (§1.1):

* **Значения фиксированного размера соединяются по значению.** Скаляры,
  структуры, фиксированные массивы, ссылки и срезы копируются. Копирование
  ссылки или среза копирует саму ссылку или срез, никогда указуемое. Большие
  фиксированные значения копируются молча; порога размера нет. Фиксированный
  массив, чьё назначение - срез его типа элемента, не копируется, а
  рассматривается, как любой массив (§3.10).
* **Значения не фиксированного размера никогда не копируются неявно.**
  *Lvalue* переменного или изменяемого класса (переменная, поле или элемент)
  связывается по ссылке, когда его назначение имеет ссылочный тип или тип
  среза, либо является нетипизированным параметром функции или блока
  (§7.6, §7.7), непроаннотированным `let`/`var`, привязкой `for` или
  результатом с выводимым типом (§7.1). В назначении с типом значения такой
  lvalue - ошибка.
  Назначение с типом значения принимает **rvalue** (литерал, результат
  вызова, строящее выражение, построенное на месте по §4.3) или явный
  **`copy(x)`**, который является свежей копией хранимого значения,
  построенной в назначении, как любое другое rvalue. Собственное локальное
  значение функции *перемещается* через `return` или как финальное выражение
  её тела (§7.3).

Поэтому `f(xs)` передаёт переменную `u8[][>..]` по ссылке в каждый из
`fn f(xs: u8[][:])`, `fn f(xs: u8[][>..]&)` и `fn f(xs)`. `out.push(w)`
нужно записать как `out.push(copy(w))`, когда `w` называет хранилище.
`x.f(a)` (§7.1) читается как `f(x, a)`, каков бы ни был класс размера `x`. В
нетипизированном назначении ссылка на *фиксированное* значение всё ещё
пишется `&x` (`let r = &n;` или равнозначно `let r .= n;`, §3.8; `f(&n)` в
нетипизированный параметр). Везде, где собственный тип назначения - ссылка,
`&` избыточен, а избыточный `&` - предупреждение. `&` у аргумента в теле
генерик-функции, в теле функционального значения и в объявленном в любом из
них освобождён, как и избыточное приведение (§6.3): другая инстанциация
может в нём нуждаться, как `F(N, &value.A)` над `fields<T>` (§6.5)
нуждается в нём для поля фиксированного размера и не нуждается для не
фиксированного.

Эти назначения не дают `if`, `match`, `block`, `loop` или голому `{ }` типа
назначения: непроаннотированный `let`/`var`, результат с выводимым типом
(§7.1), нетипизированный параметр, операнд или значение, с которым работает
`for`, `[..]` или встроенная функция. Там значение конструкции - копия того,
что даёт взятая ветвь, если только её ветви не соединяются в срез (§6.4).
Ссылка на значение фиксированного размера (включая `&x`) копируется там как
своё указуемое, как и везде, где ссылка встречает значение (§3.8).
`let r = if c { &a } else { &b };` делает `r` копией `a` или `b`, поэтому
`&` избыточны и дают предупреждение. Ветвь, называющая хранилище не
фиксированного размера, или ссылка на него, - ошибка там, как и в назначении
с типом значения; `let x = if c { copy(a) } else { copy(b) };` выписывает
копии явно.

В назначении ссылочного типа (проаннотированный `let`/`var`, ссылочный
параметр) каждая ветвь вместо этого связывается по ссылке, каков бы ни был
её класс размера. `let r: i64& = if c { a } else { b };` связывает сам `a`
или `b`. `f(if c { a } else { b })` передаёт сам `a` или `b` в
`fn f(xs: i64[>..]&)`, как `g(if c { i } else { j })` передаёт `i64` `i` или
`j` в `fn g(x: i64&)`. Данный `if c { s } else { t }`, `fn h(p: u8[:]&)`
переводит переменную-срез, которую называет взятая ветвь, на другую область.
Вызов функционального значения - это вызов, не одна из этих конструкций: его
значение - временное, даже если значение его тела называет переменную
(§9.2).

Передачи владения, кроме перемещения при return, нет, деструкторов нет,
`Drop` нет, подсчёта ссылок нет. Единственное освобождение - выход из
области видимости, сбрасывающий указатели стека. `defer` (§6.6) выполняет
написанный программой код при выходе из блока; он привязан к блоку, а не к
значению, и сам память не освобождает. (Операция `move` для изменяемых
массивов, которая присваивает и оставляет источник пустым, предвидится, но в
v1 её нет.)

Копирование переменного или изменяемого значения стоит O(size). Явный
`copy` помечает эту стоимость в исходном коде.

Затенение: внутренняя область может переобъявить имя (отдельная переменная).

### 4.2 Контексты построения

Переменные и изменяемые значения возникают только в этих точках, каждая из
которых даёт свежее хранилище в статически известном месте:

* инициализация `let`/`var` локального или глобального значения;
* слот аргумента по значению (§7.2);
* возвращаемое значение (§7.3);
* `push`/`append` в изменяемое значение (новая область элементов);
* поле/элемент внутри большего строящегося значения.

Построение сначала пишет метаданные, затем элементы или поля по порядку, как
требует инвариант §1.3(4). Построение ограниченного массива пишет только
метаданные и предоставленные элементы; оставшаяся ёмкость зарезервирована,
но **неинициализирована**. Это безопасно, потому что пути чтения к
неинициализированным ячейкам нет (§5.3), и дёшево, потому что среда
выполнения явно выделяет страницы пропущенных диапазонов адресов
(Приложение C.4).

Пока значение строится на месте в массиве, ничто не может растить этот
массив, ни строящееся выражение, ни вызываемая им функция (§1.3(4)). Такое
значение - элемент, добавленный в массив через `push` или выделенный в нём,
который имеет переменный размер или держит относительные ссылки;
результат-массив вызова, добавленный через `append`; литерал массива таких
элементов, добавленный через `append`; или новое содержимое целого
присваивания (§4.4). Компилятор отвергает рост, который он не может показать
как рост другого массива. Целое присваивание строит новое содержимое поверх
старого, поэтому его правая часть вообще не может использовать массив
(§4.4).

Формы литералов, применимые в любом контексте построения:

* литералы массивов `[1, 2, 3]`. Пустой `[]` можно использовать там, где тип
  элемента известен из контекста, или как весь инициализатор локального
  `var`. Контекст - тип массива переменной, параметра, поля, элемента или
  результата, который строит `[]`, или тип среза того, чьим временным
  значением он является (ниже). Это никогда не тип операнда, ветви или
  элемента рядом с `[]`: `x == []`, `if c { [] } else { x }` без типа
  назначения и `[[], [1]]` - ошибки. Как весь инициализатор локального `var`
  (`var out = [];`), `[]` делает локальное значение только растущим
  `T[>..]`, чей `T` фиксируется первым `push`, `append`, `format` или целым
  присваиванием в него (строковый литерал, добавленный в него, делает его
  `u8[][>..]`). `T` обязан быть зафиксирован до иного использования
  локального значения или конца его области видимости. Fill-форма `[v; n]`
  принимает неотрицательное количество элементов времени компиляции
  (константное выражение, как размер: §3.3). `v` вычисляется один раз,
  включая случай нулевого `n`, и его значение повторяется. Относительные
  ссылки сохраняют цель в каждом назначении; `self` в литерале ссылается на
  каждый построенный элемент.
  Литерал, чьё назначение не называет тип массива, - это `T[k]`, или `T[]`,
  когда его элементы не фиксированного размера (§3.3). Литерал `T[k]` может
  также быть временным значением, которое рассматривают назначение-срез,
  `for`, `[..]` или `bytes_of` (`f([])` рассматривает пустой `i64[0]` для
  `fn f(xs: const i64[:])`). Литерал `T[]` - значение переменного класса и
  существует только в контексте построения, поэтому рассматривать его можно,
  лишь связав с ним переменную. `==` и `!=` сравнивают литерал любого из
  двух видов с любым массивом или срезом его типа элемента (§4.5), поскольку
  их результат не держит его вида.
  Литерал, чьи элементы на любой глубине вложенности - все целые константы
  или все вещественные литералы, подстраивается под параметр, как
  подстроились бы его элементы (§3.1, §6.3). Он - значение параметра-массива
  или среза своей формы, чей тип элемента вмещает его элементы:
  `take([0, 0, 0, 7])` для `fn take(c: u8[4])` и `[1, 2, 250]` для
  `const u8[:]`. При разрешении перегрузок это считается приведением (§7.1).
  То же верно для конструкции, чьи ветви - все такие литералы одного типа.
  Добавленный через `append` литерал - серия элементов, которую он добавляет.
  Это `T[k]` для типа элемента `T` массива, или `T[]`, когда `T` не
  фиксированного размера, и его элементы строятся как собственные массива
  (`bytes.append([1, 2])` для `u8[>..]`; `[]` не добавляет ничего; `str()`
  среди них строится в своём элементе). Элементы переменного размера или
  держащие относительные ссылки строятся там, где останутся, поэтому
  относительная ссылка среди них может указывать в массив. Остальные
  элементы вычисляются до добавления серии, как добавляемый элемент
  фиксированного размера;
* литералы структур `X { a: 1, b: 2 }` (именованный) или `X { 1, 2 }`
  (позиционный, в порядке объявления; смешивать нельзя). Именованные
  инициализаторы можно писать вне порядка объявления, только когда каждая
  пара, переставленная этим порядком, доказана свободной от наблюдаемых
  эффектов, ошибок времени выполнения и нелокальных выходов. Переставленная
  пара не может и пересекать эффектный пропущенный default. Вычисление и
  построение всегда идут в порядке объявления, прямо в каждое поле; для
  сохранения исходного порядка не вводятся ни временные значения, ни копии.
  Проверка консервативна. Она допускает чтения, нетрапящие вычисления и
  вызовы, чьи проверенные тела доказывают безопасность. Неизвестные/нативные
  вызовы, рекурсия, изменение, индексация, циклы, проверяемая
  арифметика/преобразования и потенциально проверяемые адаптации назначения
  (ёмкости, префиксы длины, относительные смещения) мешают паре
  переставляться. Проверка выполняется до оптимизации и включает отладочные
  проверки в каждой сборке, поэтому допуск не зависит от оптимизации или
  отладочного режима выполнения.
  Диагностика перечисляет поданные поля в порядке объявления; пропущенные
  значения по умолчанию и заполнение добавлять не требуется. Если побочные
  эффекты должны идти в другом порядке, выполните их до построения литерала.
  Поля с объявленными значениями по умолчанию (§3.2) можно опускать:
  завершающие - в позиционной форме, любые - в именованной. Пропущенное
  опциональное поле без объявленного значения по умолчанию - null; прочие
  пропущенные поля - ошибки, если только литерал не заканчивается на `..`
  (`Entity { kind: k, .. }`). Каждое из этих полей тогда берёт значение по
  умолчанию своего типа (ниже), `[]` для поля-массива, а поле, чей тип не
  имеет значения по умолчанию, всё ещё ошибка;
* `[..cap]` - пустой ограниченный массив `T[..]` с заданной ёмкостью времени
  построения (`cap` - выражение времени выполнения); зарезервированные
  ячейки остаются неинициализированными (§5.3, C.4). Литерал массива или
  строки, строящий ограниченный массив статической ёмкости, обязан в неё
  уложиться (иначе ошибка компиляции);
* литералы вариантов `Shape.Circle { r: 1.0 }`, чьи поля следуют правилам
  литерала структуры, включая `..`. Вариант без payload - также константа
  типа своего enum без скобок: `Shape.Point` или `Opt<i64>.None` для
  генерик-enum, что называет его аргументы типов;
* `self`, только внутри литерала структуры или варианта, как инициализатор
  неопционального поля с относительной ссылкой, указывающего на строящееся
  значение (`Node { prev: self, next: self }`, §3.9). Это единственный
  способ дать такому полю значение до того, как существует что-либо ещё, куда
  оно могло бы указывать;
* строковые литералы (§3.7);
* `copy(x)`: свежая копия хранимого значения, которое называет `x` (или
  указуемого ссылки), построенная в назначении, как любое rvalue. Это
  единственный способ, которым значение не фиксированного размера может
  попасть из хранилища в назначение с типом значения (§4.1). Копирование
  временного значения - ошибка, поскольку оно уже свежее.
