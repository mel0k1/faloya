`dst.move_from(src)` копирует значения среза в перезаписываемый срез того же
типа элемента фиксированного размера. Длины обязаны совпадать; несовпадение
аварийно завершает программу до записи любого элемента в любой сборке.
Копирование ведёт себя так, будто исходные значения сначала сохранены, в том
числе при перекрытии срезов; источник не очищается. Оба среза вычисляются
один раз, приёмник первым. Копирование обязано удовлетворять обычным правилам
времён жизни сохранённых ссылок (§9.2), а элементы, содержащие
самоотносительные ссылки, копировать нельзя (§3.9). Пустые срезы, включая
значения по умолчанию, корректны.

### 3.4 Правила размещения (что что может содержать)

* Значения **фиксированного** размера: где угодно (локальные, глобальные,
  поля на любой позиции, элементы массивов, payload АТД, параметры,
  возвраты).
* Значения **переменного** размера: локальные/глобальные, параметры,
  возвраты, payload АТД, элементы массивов (что делает массив
  последовательным) и поля структуры на *любой* позиции. Поле, размещённое
  после поля переменного размера, достигается динамическим вычислением
  смещения (нормально при итерировании, дорого при произвольном доступе;
  это замечание о производительности, а не правило).
* Значения **изменяемого** размера: локальные/глобальные, параметры по
  значению, возвраты и **последнее поле** обычной структуры. Это применяется
  рекурсивно: структура, заканчивающаяся изменяемым значением, сама
  изменяемая и может появляться только там, где могут изменяемые. Изменяемое
  значение может также быть payload переменного АТД (делая этот АТД
  изменяемым, с теми же правилами хвоста). Любое поле корневой структуры
  может быть изменяемым, с независимым хранением. Элементом массива
  изменяемое значение быть не может.
* **Корневые** значения: только владеющие локальные/глобальные объявления.
  Никогда по значению в другой структуре (включая другую корневую
  структуру), в массиве или срезе (даже фиксированной длины или пустом), в
  payload АТД, в параметре или результате. Ссылки на корневые структуры
  следуют обычным правилам размещения и времён жизни ссылок.
* **Нулевого размера** значения, хотя они фиксированные: массивы нулевой
  длины (`T[0]` и `T[..0]` ёмкости 0) и типы вариантов без полей
  (`Shape.Point` или вариант, состоящий только из pad, не вставляющих
  ничего, §3.2), чей payload не занимает байтов после тега АТД. Они
  появляются только как самостоятельные значения (локальные/глобальные,
  параметры, возвраты и за ссылками), никогда как поле структуры, поле
  payload или тип элемента массива или среза (в том числе выводимого из
  литерала массива). В C нет пустых массивов и структур, поэтому C-бэкенд
  даёт каждому значению нулевого размера ячейку элемента или байт
  (Приложение C.2). Внутри другого значения эта ячейка или байт занимали бы
  байты, которых раскладка значения не учитывает.

Обычная структура владеет максимум одним изменяемым значением, в своём
хвосте. **Корневая структура** группирует несколько независимых компонентов:

```faloya
root struct State<T> {
    items: T[>..] = [],
    scratch: i64[>..<] = [],
    count: i64 = 0
}
```

`root` контекстен непосредственно перед `struct`; в остальных местах это
обычный идентификатор. Поля, генерик-аргументы, значения по умолчанию,
пространства имён и квалификаторы полей работают как у обычных структур.
Поля могут быть фиксированными, переменными или изменяемыми в любом порядке,
включая обычные структуры с изменяемым хвостом. Каждое поле - отдельный
корень хранения, разделяющий время жизни владельца. Его собственные
внутренние правила размещения продолжают действовать. `pad` на корневом
объявлении запрещён, у него нет упакованной раскладки; обычная
структура-компонента может содержать заполнение.

Владелец строится напрямую литералом в своём объявлении, например
`var s = State<i64> { .. };`. Типизированное глобальное значение без
инициализатора использует обычные значения полей по умолчанию.
Инициализаторы выполняются один раз в порядке полей; проверки построения не
позволяют наблюдать недостроенное хранилище. Все стеки компонентов
восстанавливаются при выходе из области видимости, включая нелокальные
выходы во время частичного построения. Число стеков определяется статически.
Владелец с переменными или изменяемыми компонентами не может оставаться
живым через вызов, замыкающий рекурсивный цикл (§7.8); корень, все поля
которого фиксированы, динамических стеков компонентов не требует.

Владельцев нельзя копировать, присваивать целиком, передавать или возвращать
по значению, использовать как временные значения. Непроаннотированная
привязка от существующего владельца заимствует его, как и другие lvalue не
фиксированного размера. Функции принимают `State<T>&`; ссылки можно хранить,
делать опциональными, возвращать или захватывать, когда их обычные времена
жизни позволяют. Присваивание полей, заимствование и операции массивов
сохраняют свои обычные правила. Разные поля остаются разными областями, даже
если их типы элементов совпадают: сжатие одного не делает недействительными
виды в другое. Обычные ссылки, хранимые в поле, всё ещё могут указывать в
другие места, и проверки сжатия следуют этим ссылкам. Самоотносительные
связи остаются внутри разрешённой области одного компонента (§3.9).

Корневые владельцы поддерживают форматирование и инспекцию полей по ссылке,
но не имеют равенства целых значений, арифметики, сырой сериализации или
публичной C-раскладки. Подходящие компоненты можно сериализовать или
просматривать отдельно. Корневые владельцы и их ссылки не могут пересекать
границы worker/очередей; worker может создавать локальных владельцев, но не
может прямо или транзитивно использовать корневые глобальные значения
(§11.2). Неиспользуемые корневые глобальные значения worker не ограничивают.
Частное представление - в Приложении C.2.

Никакой тип не содержит сам себя по значению, ни напрямую, ни через то, что
содержит (поля, payload в любом режиме АТД, типы вариантов, элементы
массивов), иначе он был бы частью самого себя. Тип может ссылаться на себя,
поскольку ссылка или срез фиксированного размера, на что бы она ни
указывала: payload АТД может связываться со своим АТД или одним из его
вариантов, а тип за ссылкой может содержать тип, держащий ссылку
(`enum List { Nil, Cons { v: i64, next: List? } }` или `struct A { b: B? }`
с `struct B { a: A }`).

### 3.5 Алгебраические типы данных

```faloya
enum Shape {
    Circle { r: f64 },
    Rect { w: f64, h: f64 },
    Point,
}
```

АТД - единственный механизм динамического полиморфизма в языке: наследования
нет, traits и vtables отсутствуют. АТД представляется целочисленным тегом
(наименьший тип хранения, вмещающий число вариантов, по умолчанию `u8`), за
которым следует payload.

Каждый *тип* АТД может использоваться в двух режимах, выбираемых в месте
использования содержащим объявлением:

* **фиксированный режим** (`x: Shape`) - применим, только если все payload
  фиксированного размера и не держат самоотносительных ссылок (§3.9).
  Размер складывается из тега и максимального размера payload, дополненного до наибольшего
  варианта (заполнитель никогда не читается, игнорируется `==`). Значение
  фиксированного режима может быть **перезаписано на месте другим
  вариантом**, но внутренние ссылки в его payload никогда не создаются.
  Поэтому его payload связываются только по значению (§8.1, §8.2), и копия
  не сохраняет самоотносительные ссылки (`in pool` ссылки копируются
  нормально).
* **переменный режим** (`x: Shape..`): размер складывается из тега и payload фактического
  варианта. Класс переменный (или изменяемый, если payload хранимого
  варианта содержит изменяемый хвост). Значение переменного режима может
  иметь внутренние ссылки в payload, но его вариант **никогда не заменяется
  на месте**, кроме как целым присваиванием изменяемого АТД (§4.4). Поэтому
  изменяемый АТД связывает свои payload только по значению, как и
  фиксированный режим (§8.1, §8.2). Значит, payload изменяемого АТД, сам по
  себе не изменяемый, не держит самоотносительных ссылок, поскольку копия их
  не сохраняет (§3.9); обычные или `in pool` ссылки копируются нормально.

Разрешение либо замены варианта, либо внутренних ссылок, но не обоих сразу,
сохраняет корректность экзистенциальных типов (Grossman, "Existential Types
for Imperative Languages").

АТД без payload - обычные C-подобные enum, они фиксированные, по умолчанию
1 байт. Типы вариантов (`Shape.Circle`) сами по себе номинальные типы,
подобные структурам (§8.2).

### 3.6 Поля varint

`varint` - это **LEB128**: little-endian base-128, 7 битов payload на байт,
старший бит означает продолжение; от 1 до 10 байт; весь 64-битный диапазон.
Хранимые кодировки каноничны: кратчайшая кодировка беззнакового или
zigzag-преобразованного значения. Проверенный байтовый образ обязан
сохранять этот инвариант (§12). LEB выбран потому, что этот тип оптимизирован
для значений, которые обычно очень малы, но иногда выбиваются, и на них
формат обошёл другие (измерения сведены в Приложении B, Resolved, пункт 1).

Тип `varint` один, с двумя кодировками, зависящими от позиции. Разница видна
пользователю всякий раз, когда данные Faloya сериализуются напрямую:

* Как **тип поля длины** массива (`T[varint]`): беззнаковый ULEB128.
* Везде иначе (поля структур, payload АТД, самоотносительные смещения):
  **знаковый**, с zigzag-преобразованием (`(v << 1) ^ (v >> 63)`), поэтому
  малые отрицательные так же компактны, как малые положительные.
  Пул-относительное смещение (§3.9) беззнаковое, значит ULEB128, как длина.
  Преобразование лежит на пути значения, а не пути длины/продвижения,
  поэтому не стоит никакой задержки декодирования.

Поскольку кодировки различаются, значения varint никогда не копируются
побайтово между контекстами: любое построение varint из varint (например,
поле varint структуры, инициализированное из `arr.len`) идёт через `i64`:
декодирование, затем перекодирование.

Ограничения: поле/элемент `varint` записывается только при построении
содержащего его значения; изменить его означает перестроить контейнер.
Чтение декодирует в `i64`; хранилище при построении принимает любой
целочисленный тип, кроме `u64` (varint вмещает ровно диапазон значений
`i64`). Структура с полями `varint` - переменного класса. Ссылки на поля
`varint` всегда только для чтения (§3.8). Такое поле всё же хранилище типа
`varint`. Назначение `varint&` связывает его без `&`, как назначение ссылки
связывает любой lvalue своего указуемого типа (§4.1). `i64&` его не
связывает, хотя он читается как `i64`. Этот `i64` - не хранилище, поэтому
перегрузка format, принимающая `i64` по ссылке, получает его во временном
значении только для чтения (§3.7).

### 3.7 Строки

Встроенного строкового типа нет. "Строка" - любой тип семейства массивов с
элементом `u8`: `u8[]` (плоская строка фиксированной длины), `u8[varint]`
(компактная), `u8[>..]` (сборщик строк) и так далее. Строковые литералы -
статические константные данные `u8`. Они неявно копируются в любое из этих
представлений и используются напрямую как срезы типа `const u8[:]` (§9.5).
Этот тип делает их доступными только для чтения, поэтому литерал хранится
только в ячейке, объявленной `const`. Никакая кодировка не навязывается;
UTF-8 - соглашение уровня библиотеки.

**Текст.** У каждого скаляра, `bool` и массива или среза `u8` есть текстовая
форма:

* целые - в десятичном виде;
* вещественные - в кратчайшей форме, которая читается обратно в то же
  значение их собственного типа. `f32` 0.1 печатается как `0.1`, без лишних
  цифр расширенного значения `f64`. Целые числа получают `.0`, чтобы
  читаться как вещественные (`1.0`, `-0.0`, `2147483600.0`); экспоненциальные
  формы вроде `1e+20` сохраняют свою форму. Бесконечности печатаются как
  `inf` и `-inf`, а любой NaN - как `nan`;
* `true`/`false`;
* байты массива `u8` как есть.

Три встроенные функции производят его. Каждая принимает любое число
аргументов и не вставляет ничего между ними:

* `print(a, b, …)` пишет формы в стандартный вывод с переводом строки, одной
  записью, поэтому строки, напечатанные разными потоками (§11), никогда не
  перемешиваются.
* `format(out, a, b, …)` добавляет их в `out`, который может быть любым
  растущим массивом `u8`.
* `str(a, b, …)` строит из них свежий `u8[>..]`. Как любой изменяемый
  результат, он строится в своём назначении (§7.3), поэтому
  `words.push(str("item", i))` пишет прямо в элемент.

Символьный литерал - целое (§2), поэтому `str('x')` даёт `"120"`; байт
добавляется через `push`.

Каждый другой тип значения рендерится структурно, поэтому `print(v)`
показывает любое значение: массив или срез других элементов как `[1, 2, 3]`,
структуру или вариант АТД как его позиционный литерал с именем типа
(`vec3<f32> { 1.0, 2.0, 3.0 }`, `Circle { 1.5 }`, вариант без payload как
`Shape.Dot`), ссылку как её указуемое, а пустой опционал как `null`. Массив
`u8`, вложенный в агрегат, берётся в кавычки и экранируется. Ссылки
прослеживаются на всю глубину, включая значения того же типа, что и
держащая их величина. Значение, чьи ссылки ведут обратно в него, поэтому
никогда не заканчивает рендеринг: у его потока кончается системный стек, что
является безопасным аварийным завершением (§9.3).

Пользовательская перегрузка `fn format(out: u8[>..]&, v: T)` (принимающая
`T` по значению или по ссылке) используется вместо этого для рендеринга
`T`, где бы `T` ни встретился в аргументе, поэтому тип может однажды выбрать
свой текст для всех трёх встроенных функций. Генерик-перегрузка, чей
параметр-значение - паттерн структуры, АТД или варианта, например
`fn format<T>(out: u8[>..]&, b: Box<T>)`, рендерит каждую инстанциацию
одинаково, её переменные типа связаны как при вызове (§7.1); негенерик-
перегрузка для одной инстанциации предпочтительнее. Генерик-перегрузка,
принимающая голую переменную типа или массив или срез такой переменной, -
обычная перегрузка и не меняет, как что-либо рендерится. `T` не
фиксированного размера никогда не копируется неявно (§4.1), поэтому его
перегрузка принимает его по ссылке. Перегрузка, принимающая `T` по ссылке,
получает хранилище, в котором лежит `T`, как это делает ссылочный параметр
(§4.1): переменную, поле или элемент, держащие его, или то, что называет
ссылочный аргумент, и она столь же записываема, сколь и это хранилище
(§9.5). `T`, не являющийся хранилищем, лежит во временном значении только
для чтения. Это случай результата вызова, оператора или приведения,
литерала, `.len` или `.cap` и значения `if`, `match` или блока, которое
является копией того, что даёт взятая ветвь, даже если та называет
переменную (§4.1). Перегрузка ищется в пространстве имён, где объявлен
`T`, затем глобально (§11.1): рендеринг следует за типом, а не за
пространством имён печатающего кода. Тип, достигающий себя через ссылки,
рендерится структурно только там, где никакая перегрузка не рендерит ни
одной его части, на любой глубине. Иначе типу нужна своя перегрузка, которая
может рендерить его части через их перегрузки.

Три встроенные функции вычисляют и рендерят аргументы по порядку, вычисляя
каждый прямо перед рендерингом его текста. Они вызывают перегрузку в
середине рендеринга аргумента, содержащего `T`. Поэтому ни переменные,
называемые аргументами после него, ни остаток того же аргумента не могут
ссылаться внутрь того, что сжимает перегрузка (§5.1).

Элементы массива и payload АТД переменного режима (§3.5) рендерятся там, где
лежат, используя количество и вариант, прочитанные при начале их рендеринга.
Поэтому перегрузка, вызванная для одной из их частей, не может сжимать
хранилище, в котором они лежат. Такое сжатие либо освобождает элементы, либо,
как делает целое присваивание (§4.4), перестраивает каждую часть переменного
размера значения, их держащего. Ссылка на целое изменяемое значение - не
исключение.

Элементы среза рендерятся из вида, который срез имел при начале их
рендеринга, а значение за ссылкой - из того, куда ссылка указывала в тот
момент. Перегрузка, переведшая срез на другую область или перепривязавшая
ссылку в это время, не меняет, как рендерится остаток (§2). Payload АТД
фиксированного режима рендерится из копии, взятой сразу после чтения его
тега, поскольку перегрузка может перезаписать АТД другим вариантом, а
ссылаться в его payload ничто не может (§3.5). Поэтому остаток payload всё
ещё вариант, с которого начался рендеринг, и перегрузка, берущая его часть
по ссылке, получает эту часть копии, только для чтения. Payload рендерится
как литерал своего варианта даже там, где есть перегрузка для типа варианта;
эта перегрузка рендерит значения типа варианта.

### 3.8 Ссылки

`T&` - ссылка на `T`. Это один машинный адрес, без арифметики указателей и
без приведений, и он никогда не висит.

**Ссылки прозрачны** (как ссылки C++): выражение, обозначающее ссылку, ведёт
себя как её указуемое в любом контексте значения. Чтение, арифметика,
сравнения (`r1 == r2` сравнивает указуемые), передача параметру по значению
и `print(r)` все работают с целью. Оператора разыменования нет; загрузка
неявная (`copy(r)` называет копию указуемого там, где §4.1 её требует).

* Создаются через `&lvalue`. Lvalue: локальные/глобальные имена, поля,
  индексированные элементы, разыменованные ссылки и (для создания ссылок)
  переменные элементы, достигнутые итерированием. `&` от rvalue (временного
  значения) - ошибка. `&` от ячейки, которая сама держит ссылку, даёт
  *хранимую* ссылку (ссылок на ссылки нет).
* Записи: `r = v` (а также `r += v`, `r++`, …) пишут в указуемое, с учётом
  записываемости (§9.5) и собственных правил цели. `const T&` не позволяет
  писать в своё указуемое.
* Перепривязка: особое присваивание `r .= &x` обновляет само *значение*
  ссылки, а не пишет через неё. `.=` применимо к любой ячейке ссылочного
  типа: переменным (с учётом их `let`/`var`), полям и элементам. На
  нессылочных ячейках `.=` - ошибка, кроме генерик-кода, где он
  присваивает, как `=`. Генерик-код здесь означает тело функции с
  параметрами типов или нетипизированными параметрами и написанные в нём
  вложенные функции и функциональные значения. Поэтому генерик-код хранит
  целое значение типа параметра типа через `.=`: там, где параметр связан со
  ссылочным типом, `.=` перемещает саму ссылку, а `=` писал бы через неё.
  Такое значение он держит в локальном значении того типа, где выведенный
  `let` скопировал бы указуемое (ниже). Например, `swap_at` из std - это
  `let t: T = xs[i]; xs[i] .= xs[j]; xs[j] .= t;`. Он меняет местами
  элементы массива ссылок, включая относительные (локальное значение держит
  обычную ссылку, §3.9), как и элементы любого другого массива. Форма
  объявления `let r .= e;` / `var r .= e;` связывает `r` с `e` по ссылке,
  чем бы ни был `e`: lvalue любого класса размера (`var cur .= pool[0];`
  называет элемент, без `&`), вызов, возвращающий ссылку
  (`let e .= pool.push(v);`), или суженный опционал. Так объявляется
  ссылочная переменная без записи её типа: `.=` говорит, что привязка -
  ссылка, как и при перепривязке. `let` на ссылочной переменной означает,
  что она не перепривязывается, а не что её указуемое const:
  `let r .= xs[i]; r = 5;` пишет в элемент (§9.5).
* Тождество: `r1 .== r2` и `r1 .!= r2` сравнивают сами ссылки, то есть то,
  совпадают ли их адреса (`==` сравнивает указуемые). Оба операнда - ссылки
  на один тип указуемого, или `null` для опционала. Хранилище (переменная,
  поле или элемент) берётся по ссылке, как берёт его `.=`, поэтому
  `n .== pool[head]` спрашивает, называет ли `n` тот элемент.
* Привязывающие контексты сохраняют ссылку, а не загружают через неё.
  Инициализатор, аргумент или поле, чей *объявленный тип* ссылочный,
  связывают значение ссылки, а lvalue указуемого типа связывают по ссылке
  без `&` (§4.1; написанный `&` даёт предупреждение). Там, где тип
  *переменной* выводится (`let x = r;`), ссылка на значение фиксированного
  размера вырождается в копию указуемого. Исключение - явный инициализатор
  `&lvalue`, который выводит ссылочный тип; конструкция, выбирающая ссылку,
  например `if c { &a } else { &b }`, не выводит, и её значение - копия
  (§4.1). lvalue не фиксированного размера, напротив, связывается по ссылке
  (`let w = words[0];` называет элемент), и ссылка на значение не
  фиксированного размера тоже (`let a = c.args;` с `args: u8[>..]&` связывает
  то, на что ссылается поле, как делает `.=`,
  ). Чтобы связать вызов, возвращающий ссылку, со значением фиксированного
  размера, используйте `.=` (`let e .= pool.push(v);`) или аннотацию
  (`let e: T& = pool.push(v);`). Значение, держащее самоотносительные
  ссылки, вообще нельзя скопировать (§3.9). Функция с выводимым типом
  результата берёт его из return тем же способом (§7.1). Нетипизированный
  параметр - анонимная переменная типа и связывает точный тип аргумента,
  ссылку или нет, точно как явный `<T>` (§7.7). Для значения фиксированного
  размера `f(&x)` даёт `f` ссылку, а `f(x)` - копию; lvalue не фиксированного
  размера - ссылка в обоих случаях.
* Ссылки на поля `varint` всегда только для чтения (varint записывается
  только при построении, §3.6).

**Опционалы.** Ссылки по умолчанию не допускают null. `T?` - это
*опциональный T*: он представляется допускающей null ссылкой на T (null =
адрес 0, поэтому лишнего места не занимает) со всей ссылочной семантикой и
ограничениями (корни, времена жизни, записываемость). Это сочетается с любым
типом: передайте `i64?` для опционального целого. Применённый к типу,
который уже ссылка, `?` делает эту ссылку допускающей null (`T&?` - то же,
что `T?`). То же верно для аргумента типа, являющегося ссылкой: `T?` от
`Node&` - это `Node?`, а от `Node&<u32 in pool>` - опциональная
относительная ссылка. `T&` от аргумента ссылочного типа - сама эта ссылка,
как `&` от ячейки, держащей ссылку, даёт хранимую ссылку (загруженную, если
относительная). Литерал `null` - пустое значение любого опционального типа;
опциональное поле структуры без объявленного значения по умолчанию по
умолчанию null. Опционалы *не* прозрачны: доступ требует сужения через
проверки `if`/`while`/`guard`/`assert(r)`/`== null`/`!= null`. Типизация по
потоку: внутри охраняемой области опционал *есть* `T&` во всех отношениях.
Он прозрачен, позволяет запись через себя и связывается через `.=`
(`if n { let m .= n; … }`). Условие `while` сужает своё тело так же, даже
когда тело перепривязывает переменную, поскольку проверка выполняется снова
перед каждой итерацией (`while n { …; n .= n.next; }`). В остальных местах
перепривязка переменной заканчивает сужение. `o .= &x` / `o .= null`
перепривязывают опционал. Перепривязка к обычной ссылке сужает его, а
перепривязка к чему-либо, что может быть null, отменяет сужение.

**Куда ссылки могут указывать.** На что угодно, кроме внутренностей payload
АТД фиксированного режима (§3.5). Ссылка внутрь растущего-сжимаемого массива
`[>..<]` держится только в переменной и обязана больше не быть живой к
моменту следующего сжатия массива (§5.2).

Ссылки внутрь только растущего изменяемого `[>..]` остаются корректными,
пока их можно назвать: выращенная память никогда не перемещается, а массив
сжимается только там, где компилятор видит, что ни такой ссылки, ни среза не
живо (§5.1). Ссылки внутрь ограниченных массивов `[..k]`/`[..]` тоже
допустимы и остаются типово корректными сквозь переиспользование pop/push
(§5.3).

### 3.9 Относительные ссылки

Относительная ссылка - форма хранения ссылки, хранимая как узкое смещение
вместо адреса. Она записывается `T&<u8>`, `T&<u16>`, `T&<u32>`, `T&<u64>`
или `T&<varint>`; ширины записываются беззнаковыми типами (или `varint`),
как типы полей длины массивов. Она бывает двух форм, различающихся только
тем, от чего измеряется смещение: **самоотносительная**, по умолчанию,
измеряется от самого поля смещения; и **пул-относительная**, записывается
`T&<u32 in pool>`, измеряется от базы именованного пула.

Обе формы можно сделать опциональными, записывается `T&<u8>?`, что
резервирует смещение 0 для null. Пул-относительное смещение сдвинуто на
единицу. Самоотносительное поле может делить адрес с объемлющим значением,
поэтому непустая запись не должна кодироваться как null опционала. Такая
запись аварийно завершает программу, а коллизия, известная статически, может
быть отвергнута при компиляции. Неопциональная самоотносительная ссылка не
имеет null-сигнального значения: смещение 0 обозначает адрес её собственного
поля, как `self` в первом поле значения. Поэтому null представим в любой
относительной ячейке, каков бы ни был её корень, и значение, известное как
null, записывается в опциональную относительную ячейку без собственной
проверки корня. Значения, известные как null:

* литерал `null`;
* переменная, связанная до сих пор только с null (§9.5), параметр,
  получивший null, и вызов, у которого каждый `return` даёт null, - ни у
  одного нет корня;
* опциональная ссылка, чей единственный корень - статические данные, где
  статические данные не держат ничего, кроме null: записываемые (§9.5) или
  такие, чей тип указуемого не даёт ни один литерал, поскольку ссылка `u8`
  только для чтения может указывать в строковый литерал.

Как одна альтернатива слитого значения (§9.2), null не называет никакого
массива: `if c { null } else { &pool[i] }` - это ссылка в `pool`. Поэтому
цепочка, заканчивающаяся сигнальным значением, не навязывает обычные ссылки
всей структуре.

**Самоотносительная.** Ограничена указыванием внутри *того же объемлющего
массива/пула*, что и ячейка, хранящая её.

* Хранится как знаковое смещение заданной ширины (смещения `varint`
  используют знаковое кодирование zigzag, §3.6). Загрузка даёт обычную `T&`
  (база: адрес самого поля смещения). Запись требует, чтобы компилятор
  видел: и ссылка, и ячейка назначения происходят из одного корневого
  массива; оба корня обязаны быть одной и той же переменной *и* оба точными
  (§9.2), поскольку корень, лишь ограничивающий время жизни, не говорит,
  какой массив пройдёт смещение. Ссылка, прочитанная из контейнера, годится
  ровно тогда, когда правило чтения обратно из §9.5 называет единственного
  кандидата. Иначе ошибка называет кандидатов, между которыми правило не
  смогло выбрать. Смещение проверяется на диапазон при записи (аварийное
  завершение при переполнении ширины). Оба конца лежат в одном корневом
  массиве, поэтому смещение не может превысить его протяжённость. Проверка,
  значит, существует только там, где корень может быть шире знакового
  диапазона ширины. Корень на стеке данных простирается максимум на
  резервирование (§10.4), поэтому резервирование 2 ГБ и меньше не требует
  проверки для `u32`, а 32 КБ и меньше - для `u16`. Относительные ссылки
  ширины varint записываются только при построении, как поля varint
  (перекодирование могло бы изменить длину в байтах); фиксированные ширины
  можно перезаписывать через `.=`/`=`.
* Копирование *значения, содержащего* самоотносительные ссылки, - ошибка
  компиляции, поскольку скопированные смещения по-прежнему измерялись бы от
  исходной ячейки. Это запрещает присваивание из lvalue, аргументы по
  значению, связыватели match по значению или параметры case-функций по
  значению (§8.1, §8.2) и копии элементов. Также запрещает `append`, кроме
  случая литерала массива, входы по значению для перегрузки `format` (§3.7),
  значения заполнения `resize` и `copy(x)`. Значение заполнения `resize`
  копируется в каждую добавленную ячейку, даже когда это литерал.

  То, что называет ссылка, копируется тем же способом, где бы назначение
  значения ни встретило ссылку (§3.8, §4.1). Для `f`, возвращающей `Node&`,
  `let n = f();` копирует узел из массива, внутри которого указывают его
  связи. Так же делают `var`, проаннотированное объявление, аргумент по
  значению, return (в том числе с выводимым типом результата), присваивание,
  поле или элемент литерала, добавленный элемент и каждый ссылочный
  результат многозначной привязки, когда им дают такую ссылку. Там, где
  объявление, скорее всего, должно было связать ссылку, ошибка предлагает
  привязку `let n .= f();` (§3.8). И связь нельзя прочитать из копии
