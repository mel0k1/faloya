# Справочник по языку Faloya

## 12. Времена жизни: корни, записи и перезаписываемость

Вся проверка заимствования Faloya укладывается в одно правило: ссылка или
срез обязана не пережить переменную, владеющую её целью, и обязана никогда
не увидеть цель в чужом типе. Аннотаций времён жизни в языке нет, правил
единоличного владения тоже: две ссылки на одно значение допустимы, потому
что без разделяемой памяти псевдонимы сами по себе не ломают типовую
безопасность. Проверка статическая, и ошибка компиляции возникает там, где
в языках с ручным управлением памятью жила бы висячая ссылка. Спецификация
§9.1, §9.2.

Регрессионные тесты правил живут в `test/errors/life_*.fal`, рабочие
примеры в `test/cases/life_roots.fal` и сэмпле `36_ownership`.

### Корни

Каждая ссылка и каждый срез носит один или несколько статических корней.
Корень это локальная или глобальная переменная, ограничивающая время жизни
цели. Корень точный, когда хранилище самой переменной содержит цель, и
неточный, когда он лишь ограничивает время жизни цели. Корни выводятся и
никогда не пишутся: `&x` укоренён в `x` точно, срез параметра функции
укоренён в то, что передал вызывающий, а ссылка, прочитанная из
контейнера, укоренена в переменные, чьё хранилище способно держать её
цель. Функции специализируются по различным корням, что даёт точность
параметров времён жизни без единой аннотации. Спецификация §9.2.

### Правила

* **Запись.** Ссылку можно сохранить в переменную, поле, элемент или
  глобальную переменную, только если её корень переживёт владельца места.
* **Возврат.** Корень возвращённой ссылки обязан быть виден вызывающему:
  аргумент, глобальная переменная или собственный результат функции,
  сконструированный на месте. Локальная переменная функции умирает вместе
  с ней.
* **Ветки.** Значение `if`, `match`, блока или цикла принимается после
  окончания областей, открытых ветками, поэтому оно не может быть
  укоренено в переменную, объявленную внутри ветки.
* **Слитые значения.** Значение, которое может прийти из нескольких мест,
  несёт корни всех их и обязано удовлетворить каждому правилу по каждому
  корню.
* **Перепривязка.** Переменная-ссылка держит корень своей первой
  привязки: `.=` перепривязывает её внутри того же корня или на той же
  глубине области, что обычный обход контейнера. Всё остальное требует
  новой переменной.
* **Временные значения.** Литерал, результат вызова, `copy` или значение
  управляющей конструкции живёт до конца своего оператора. Вид внутрь
  него можно передать вниз по вызову; хранить его в переменной и
  возвращать нельзя.
* **Держатели.** Держатель, то есть структура с полями-ссылками, массив
  срезов или payload со ссылкой, укоренён в то, что в него записали.
  Проверка запоминает каждую такую запись и ловит усечение или выход из
  области, которые оставили бы внутри держателя висячую ссылку.

Ошибка времени жизни называет оба конца: и корень ссылки, и место
назначения.

```goose
fn longest(a: u8[:], b: u8[:]) -> u8[:] { if a.len >= b.len { a } else { b } }

fn main() {
    var outer: u8[>..] = [];
    outer.append("outer");
    var w = outer[..];
    {
        var inner: u8[>..] = [];
        inner.append("inner text");
        w = longest(outer, inner);   // ошибка: ссылка с корнем в inner
    }
    print(w);
}
```

Результат `longest` может указывать в любой из аргументов, поэтому он
укоренён в оба, а `inner` не переживёт `w`. Перенесите объявление `w`
внутрь блока или скопируйте текст, и программа соберётся.

```goose
fn make() -> u8[>..] { str("made") }

fn main() {
    let t = make();
    let s = t[..];                   // верно: t живёт дальше
    let u = make()[..];              // ошибка: вид внутрь временного
    print(s, " ", u);
}
```

Запись в массив, на который указывает живая ссылка, и усечение
массива-стека при живой ссылке ловятся так же статически:

```goose
fn main() {
    var a: u8[>..] = [];
    a.append("hello");
    let r: u8& .= a[1];
    print(r);
    a = [];                          // ошибка: r ещё используется
    print(r);
}
```

```goose
fn main() {
    var stack: u8[>..<] = [];
    stack.append("hi");
    let r: u8& .= stack[1];
    print(r);
    stack.pop();                     // ошибка: r ещё указывает внутрь
    print(r);
}
```

Проверка смотрит на живучесть: то же усечение после последнего
использования ссылки ошибки не составляет, потому что ссылка к тому
моменту мертва. Пока ссылка живёт в переменной, усечение отклоняется,
и ошибка называет переменную и строку её привязки.

### Обход контейнера перепривязкой

Ссылка на элемент grow-массива переживает любой рост: элементы не
перемещаются, поэтому корень остаётся точным. Обход цепочки узлов в пуле
делается перепривязкой опциональной ссылки, и сужение действует на каждую
итерацию заново:

```goose
struct Node { value: i64, next: Node&<u32 in nodes>? }

var nodes: Node[>..] = [];

fn walk(start: Node&<u32 in nodes>) -> i64 {
    var total: i64 = 0;
    var cur: Node&<u32 in nodes>? .= start;
    while cur {
        total += cur.value;
        cur .= cur.next;
    }
    return total;
}
```

Полный пример со сборкой списка, обходом и записью через ссылку живёт в
сэмпле `36_ownership`.

### Перезаписываемость

Всё перезаписываемо, пока тип не говорит иного. `const T` это значение,
содержимое которого нельзя записывать: `const i64[3]` не даёт присвоить
элемент, а `const T&` и `const T[:]` это ссылка и срез, сквозь которые
цель не записывается, не растёт и не усекается. Перезаписываемость
выводится для каждого воплощения, как корни:

* **Только чтение:** строковый литерал; `&x` или `x[..]` от `const`
  значения, от его поля, от привязки `for` или `match` по значению; вид
  внутрь временного; то, что читается из слота, объявленного `const`.
* **Перезаписываемое:** всё остальное, включая `&x` и `x[..]` от `var`
  или обычного `let`.
* **Параметры и результаты обобщены по константности.** Параметр,
  объявленный `u8[:]`, принимает и перезаписываемый, и read-only
  аргумент, а тело проверяется с тем, что ему дали: запись сквозь
  параметр, получивший литерал, это ошибка в месте вызова, и сообщение
  показывает цепочку вызовов. Параметр, объявленный `const u8[:]`,
  read-only всегда, и так функция документирует, что она только читает.
  Добавление `const` происходит неявно всюду; снятие его никогда.
* **Слоты говорят, что держат.** Поле, элемент, глобальная или
  аннотированная переменная держит read-only ссылку, только если её тип
  `const`: `struct Named { name: const u8[:] }` может держать литерал, а
  `struct Buf { bytes: u8[:] }` не может. Переменная без аннотации берёт
  константность инициализатора.
* `const` поверхностный: ссылка, прочитанная из поля `const`-структуры,
  так же перезаписываема, как говорит тип самого поля.

```goose
fn upper_first(s: u8[:]) { if s.len > 0 && s[0] >= 'a' { s[0] -= 32; } }

struct Named { name: const u8[:] }

fn main() {
    var buf: u8[>..] = [];
    buf.append("faloya");
    upper_first(buf);                  // перезаписываемый аргумент: верно
    let n = Named { name: "literal" }; // const-слот принимает литерал
    // upper_first("literal");         // ошибка: запись сквозь read-only
    print(buf, " ", n.name);
}
```

Спецификация §9.5.

### Как читать ошибки

Когда проверка отклоняет программу, читайте сообщение целиком. Оно
называет ссылку и место её привязки, держатель и строку записи в него,
воплощение и цепочку вызовов, которая его произвела. Два места в
сообщении подсказывают, какой конец править: использовать вид в последний
раз до усечения, перенести усечение или перенести объявление.
