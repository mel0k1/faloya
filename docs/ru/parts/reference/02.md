значение `i64`; записать его можно только при конструировании содержащего
значения. [Раздел 8](#8-структуры) разбирает его вместе с другими типами
полей.

### Преобразования

Внутри одного вида неявным является преобразование, о котором компилятор может
доказать сохранение значения, а всё, что может потерять бит или сменить знак,
требует приведения. Между видами целое неявно становится плавающим, а плавающее
становится целым только через приведение.

| Преобразование | Как |
|---|---|
| к более широкому целому той же знаковости (`i8 -> i32`, `u16 -> u64`) | неявно |
| беззнаковое к строго более широкому знаковому (`u8 -> i16`, `u32 -> i64`) | неявно |
| `f32 -> f64` | неявно |
| любое целое, включая `u64`, в `f32` или `f64` | неявно, с округлением к ближайшему плавающему |
| литерал или именованная константа в любой тип, чей диапазон вмещает значение | неявно |
| любое целое, кроме `u64`, в хранилище `varint` | неявно |
| сужение, смена знаковости при той же разрядности, знаковое в беззнаковое, `u64` в знаковое, `f64 -> f32`, плавающее в целое | `x as T` или `x as! T` |

`x as T` преобразует между любыми двумя числовыми типами. В отладочной сборке
он проверяет диапазон и прерывает программу, если значение изменилось, а в
релизной молча обрезает, переполняет по модулю или округляет к нулю.
`x as! T` никогда не проверяет, даже в отладочной сборке: он для случаев, когда
потеря битов задумана. Преобразования в плавающий тип не проверяются ни в одной
форме. Преобразование плавающего в целое полностью определено: округление
к нулю, затем переполнение по модулю до разрядности цели; NaN даёт 0.

```goose
let big = 300;
let n: u8 = big as! u8;       // 44, по замыслу
let f = 2.75;
let i = f as i64;             // 2
let back = i as f64 / 4;      // 0.5
let neg = -1;
let u = neg as! u32;          // 4294967295
print(n, " ", i, " ", back, " ", u);
```

Приведение, которое ничего не меняет, даёт **предупреждение**, поэтому
компилятор указывает на приведения, которые правила выше делают ненужными:
`b as i64` для `u8`, хранящегося в `i64`, выдаёт ``redundant `as i64`: a u8
converts to i64 implicitly here``. Приведение, которое что-то решает,
предупреждения не даёт: решает ли оно тип, который ничто больше не задаёт
(`let k = 5 as u32;`), разрядность операции (`(a as i64) * b` с операндами
`i32`) или способ округления плавающего.

**Сравнение `u64` со знаковыми значениями.** `u64` единственный беззнаковый
тип, у которого нет знакового типа для неявного расширения. Сравнение между
`u64` и знаковым операндом допускается, когда знаковый операнд *синтаксически*
известен как неотрицательный: неотрицательный литерал, `.len` или `.cap`, либо
`let`, привязанный к одному из них (и не привязанный также к записываемой
ссылке). Сравнение тогда выполняется как одно беззнаковое. Любой другой случай
требует приведения.

```goose
let h: u64 = 18446744073709551615;
var xs: i64[>..] = [1, 2, 3];
let n = xs.len;
print(h > 5, " ", h > xs.len, " ", h > n);   // всё допустимо: 5, .len и let от него
```

Спецификация §6.1, §6.3.

### Арифметика на структурах и фиксированных массивах

Арифметические операторы применяются поэлементно к двум значениям одного типа
структуры или фиксированного массива, чьи скалярные листья все целые или все
плавающие. Унарный `-` тоже применяется поэлементно, где нет беззнаковых
листьев. `*` и `/` принимают также один скалярный операнд, в любом порядке,
когда у всех листьев ровно один и тот же тип; скаляр преобразуется к этому
типу. Так работают векторные типы библиотеки; перегрузки операторов в языке
нет.

```goose
struct V3 { x: f32, y: f32, z: f32 }
fn main() {
    let a = V3 { 1, 2, 3 };
    let b = V3 { 0.5, 0.5, 0.5 };
    var c = a + b;
    c *= 2;
    print(c, " ", -a, " ", a / 2.0, " ", 2.0 / a);
    let sum = [1, 2, 3] + [10, 20, 30];
    print(sum);
}
```

```
V3 { 3.0, 5.0, 7.0 } V3 { -1.0, -2.0, -3.0 } V3 { 0.5, 1.0, 1.5 } V3 { 2.0, 1.0, 0.6666667 }
[11, 22, 33]
```

`+`, `-` и `%` требуют двух одинаковых агрегатов. Оба операнда вычисляются
один раз до записи любого члена. Спецификация §6.1.

### Побитовые операторы

`~ & | ^ << >>` работают на целых и сохраняют тип операнда. `>>` задвигает
нули на беззнаковых типах и копирует знаковый бит на знаковых. Побитовые
операторы связывают крепче сравнений, поэтому `x & mask != 0` это
`(x & mask) != 0`, а сдвиги связывают крепче `&`. `~c` неотрицательной
константы подстраивается как константа, поэтому `let a: u8 = ~4;` даёт 251,
а `flags & ~F_ROAD` очищает бит в `u8`. Константа, сдвигаемая переменным
счётчиком, всё равно подстраивается как константа: `1 << k` принимает тип
своей цели.

```goose
var flags: u8 = 0;
let F_ROAD: u8 = 4;
flags |= F_ROAD;
flags |= 1 << 1;              // константа 2 подстраивается под u8
flags &= ~F_ROAD;
let k = 40;
let m: u64 = 1 << k;          // сдвиг u64, поскольку m такая
print(flags, " ", m, " ", flags & 2 != 0);
```

Двоичных литералов нет; пишите шестнадцатеричное `0x` или сдвиг. Полная таблица
приоритетов в [приложении A](#приложение-a-ключевые-слова-и-операторы).


## 4. Где живут значения

Этот раздел короток, но всё дальнейшее держится на нём.

### Классы размеров

Каждый тип принадлежит одному из четырёх **классов размеров**:

* **fixed**: размер в байтах является константой времени компиляции. Скаляры,
  структуры из фиксированных полей, фиксированные массивы `T[k]`, массивы
  статической ёмкости `T[..k]`, ссылки и срезы.
* **variable**: размер выбирается при конструировании значения и больше
  не меняется. `T[]`, `T[varint]`, `T[..]`, структура с полем `varint` или
  variable, перечисление в переменном режиме.
* **resizable**: размер может меняться после конструирования. `T[>..]`
  (только рост) и `T[>..<]` (рост и усечение), а также структура, чьё последнее
  поле одно из них.
* **root**: `root struct` владеет независимо хранимыми полями под одним
  временем жизни. У него нет непрерывной раскладки значения, и владеть им может
  только локальное или глобальное объявление. См.
  [Root-структуры](#root-структуры).

Класс обычного составного типа это наибольший из классов его частей.
Root-структура всегда сохраняет свой класс, даже имея только фиксированные
поля. Тип **плоский**, если он не содержит ни ссылки, ни среза, ни относительной
ссылки ни на какой глубине и не является root-структурой; только плоские
значения могут переходить между потоками ([раздел 22](#22-потоки)).
Спецификация §1.1.

### Стеки данных

Программа Faloya имеет нативный стек вызовов, немного статических данных
(строковые литералы и константы времени компиляции) и **N стеков данных**, где
N это число, которое компилятор вычисляет для программы. Стек данных это
большое резервирование адресного пространства с указателем наращивания. Это
вся система памяти. Нет ни `malloc`, ни списка свободных блоков, ни сборщика
мусора, ни подсчёта ссылок, ни деструкторов.

Значения фиксированного размера живут на нативном стеке или в регистрах.
Каждое значение переменного или расширяемого класса живёт на стеке данных
и принадлежит переменной, которая его объявляет (локальная, глобальная,
параметр по значению или поле либо элемент одного из них). Эту схему обеспечивают
два правила:

1. Значения помещаются в порядке времени жизни и освобождаются все разом, когда
   владеющая область заканчивается. Освобождение это одна запись: вершина стека
   возвращается туда, где была.
2. На каждом стеке живёт не более одного расширяемого значения, и оно всю свою
   жизнь является верхней вещью на этом стеке. Поэтому рост это сдвиг указателя
   без проверки ёмкости, и ничто никогда не перемещается.

Три растущих массива, живых одновременно, получают три стека; стек
переиспользуется, как только область его освободит. Компилятор доказывает всё
это статически, и нигде в языке нет синтаксиса для стека. Спецификация §1.2,
§1.3, §10.3.

```goose
fn main() {
    for round in 3 {
        var scratch: u8[>..] = [];                   // свежий буфер на каждом круге
        for i in 100000 { scratch.push((i % 256) as! u8); }
        print("round ", round, ": ", scratch.len, " bytes");
    }                                                // освобождается здесь: одна запись
}
```

```
round 0: 100000 bytes
round 1: 100000 bytes
round 2: 100000 bytes
```

### Ничто не перемещается

Поскольку элементы растущего массива никогда не перемещаются, ссылка внутрь
него остаётся действительной, сколько бы ни было добавлено потом:

```goose
struct Item { id: i32, weight: f32 }
fn main() {
    var items: Item[>..] = [];
    let first .= items.push(Item { 1, 0.5 });         // ссылка на элемент 0
    for i: i32 in 2..1000001 { items.push(Item { i, 0.0 }); }
    first.weight = 99.5;                              // всё ещё действительна
    print(items.len, " items, first is ", items[0]);
}
```

```
1000000 items, first is Item { 1, 99.5 }
```

`std::vector` или `Vec` перераспределяют память и не могут обещать этого.
Поэтому код на Faloya держит типизированные ссылки там, где другие языки держат
целочисленные индексы в арене.

### Копии видимы

Значения фиксированного размера копируются при присваивании молча, как в C,
какого бы размера они ни были. **Значения не фиксированного класса никогда
не копируются неявно**: такая копия занимает O(size) времени, поэтому она должна
быть видимой в исходнике. Переменная, поле или элемент переменного или
расширяемого класса *связывается по ссылке*, когда попадает в цель, являющуюся
ссылкой, срезом, нетипизированным параметром, `let`/`var` без аннотации или
привязкой `for`. В цели, которой нужно собственное значение, это ошибка. Цель
со значением принимает свежее значение (литерал, результат вызова) или явный
`copy(x)`.

```goose
fn main() {
    var a: i64[>..] = [1, 2, 3];
    var b = copy(a);          // явная, видимая копия O(n)
    b.push(4);
    let c = a;                // без копии: c называет тот же массив, что a
    c.push(5);
    var p = Item { 1, 0.5 };
    var q = p;                // фиксированный размер: молчаливая копия
    q.id = 2;
    print(a, " ", b, " ", p.id, " ", q.id);
}
struct Item { id: i32, weight: f32 }
```

```
[1, 2, 3, 5] [1, 2, 3, 4] 1 2
```

То же правило действует для вызовов: `f(xs)` передаёт растущий массив по ссылке
параметру-срезу, параметру `T[>..]&` и нетипизированному параметру одинаково.
Спецификация §4.1.

### Конструирование на месте

Конструируемое значение не фиксированного размера строится **прямо в своём
финальном месте**, через любую глубину вызовов и через какую бы ветвь ни взяли
`if` или `match`. Функция, возвращающая растущий массив по значению, пишет свои
элементы прямо в переменную вызывающего, в добавляемый элемент или в поле
записи, строящейся внутри другого массива. Временный объект никогда не строится
и затем не копируется на место. Поэтому вернуть собранное значение так же
дёшево, как заполнить выходной параметр, и `words.push(str("word", i))`
форматирует текст прямо в новый элемент. Спецификация §4.3, §7.3.


## 5. Семейство массивов

Единого типа массива нет. Вместо него есть семейство типов массивов,
различающихся только тем, что может происходить с их размером. Все они
представлены как `[metadata][elements…]`, встроенно и упакованно, никогда как
указатель на отдельный блок.

| Тип | Класс | Что это | Хранимые метаданные |
|---|---|---|---|
| `T[k]` | fixed | `k` элементов, `k` константа времени компиляции | нет |
| `T[]` | variable | размер задан при конструировании, после заморожен | длина `u32` |
| `T[u8]`, `T[u16]`, `T[u32]`, `T[u64]` | variable | то же, с длиной той разрядности | длина того типа |
| `T[varint]` | variable | то же, с длиной переменной длины | 1 байт для коротких массивов |
| `T[..k]` | fixed | ёмкость `k` встроенно; рост и усечение внутри неё | длина в наименьшем типе, вмещающем `k` |
| `T[..]` | variable | ёмкость выбирается при конструировании; рост и усечение внутри неё | ёмкость и длина `u32` |
| `T[>..]` | resizable | **только рост**: рабочая лошадка | длина |
| `T[>..<]` | resizable | **рост и усечение**: стеки, очереди, кучи | длина |

```goose
fn main() {
    var fixed: i32[4] = [1, 2, 3, 4];
    let zeros: f64[8] = [0.0; 8];           // форма заполнения
    let frozen: i64[] = [7, 8, 9];          // размер задаётся один раз, не меняется
    let packed: u8[varint] = "hi";          // длина в 1 байт перед байтами
    var small: u8[..8] = [];                // ёмкость 8, встроенно где бы ни находился
    small.push('h'); small.push('i');
    var sized: i64[..] = [..16];            // ёмкость 16 выбрана сейчас, длина 0
    sized.push(1);
    var grow: i64[>..] = [];                // растущий массив по умолчанию
    for i in 5 { grow.push(i * i); }
    var stack: i64[>..<] = [];              // тот, что умеет pop
    stack.push(1); stack.push(2); stack.push(3);
    let top = stack.pop();
    print(fixed, " ", zeros.len, " ", frozen, " ", packed, " ", small, " ",
          small.len, "/", small.cap, " ", sized.cap, " ", grow, " ", stack, " ", top);
}
```

```
[1, 2, 3, 4] 8 [7, 8, 9] hi hi 2/8 16 [0, 1, 4, 9, 16] [1, 2] 3
```

### Какой выбрать

* **`T[>..]`** по умолчанию: арены, пулы, построители строк, хранилища деревьев,
  черновые буферы, заполняемые заново между фазами. "Только рост" называет
  гарантию, что ссылки внутрь остаются действительными, а не набор операций;
  `pop` и `clear` всё же доступны в точках, где компилятор видит, что ничего
  не указывает внутрь
  ([раздел 13](#13-рост-усечение-и-присваивание-массивов-целиком)).
* **`T[>..<]`** для стека, очереди или кучи. Ссылки внутрь могут жить только
  в переменных, никогда в хранилище, поэтому компилятор может проверять их
  при каждом усечении.
* **`T[..k]`** и **`T[..]`** когда массив должен сидеть встроенно внутри чего-то
  другого: 16-байтовое имя внутри структуры, короткий список внутри элемента
  массива. `T[..k]` фиксированного размера, поэтому структура с таким полем тоже
  фиксированного размера.
* **`T[]`** и **`T[varint]`** для готовых данных: строка в записи, узел в пуле,
  всё, что построено один раз и потом читается.
* **`T[k]`** для фиксированной формы: матрица 4x4, таблица на 256 записей.

Расширяемые только `T[>..]` и `T[>..<]`, и только они подчиняются правилу
одного на стек. Всё остальное может находиться где угодно, где может значение
его класса.

### Размеры времени компиляции

`k` в `T[k]` и `T[..k]`, как и количество в литерале-заполнителе `[v; n]`,
является константным выражением: литералы, именованные константы, арифметика
над ними и `.len` глобальной переменной, чья длина фиксирована объявлением
(`const names = ["a", "bc"]; var counts: i64[names.len];`). Параметр-тип это
тип, но не размер: `fn f<N>(a: i64[N])` ошибка, поскольку параметров-размеров
нет. Локальная переменная, затеняющая имя глобальной, тоже не константа.
Спецификация §3.3.

### Ограничения на элементы

* Элементы `T[>..<]`, `T[..k]` и `T[..]` должны быть **фиксированного размера**:
  усечение или переиспользование хранилища никогда не должно менять тип,
  который содержит место.
* Элементы `T[]` и `T[>..]` могут быть фиксированными или переменными, но не
  расширяемыми. Массив строк, `u8[][>..]`, это один блок: длина, затем
  собственная длина и байты каждой строки, впритык друг к другу.
* Массив с элементами переменного размера **последовательный**: где начинается
  элемент, зависит от всех элементов перед ним, поэтому массив можно обходить,
  но нельзя индексировать, и у него нет `pop`. Чтобы доставать его элементы
  в любом порядке, держите рядом индекс ссылок
  ([раздел 11](#индекс-для-последовательного-массива)).

```goose
fn main() {
    var words: u8[][>..] = [];
    for i in 3 { words.push(str("w", i)); }
    for w in words { print(w); }         // корректно
    // print(words[0]);                  // ошибка: массивы элементов переменного размера
                                         //        нельзя индексировать, только обходить
}
```

```
w0
w1
w2
```

Хранимая длина должна вмещать фактическое количество: `T[u8]` вмещает не более
255 элементов, а конструирование, которое превысило бы диапазон её типа длины,
отклоняется, когда это известно статически, или прерывает программу, когда
обнаруживается во время исполнения. Спецификация §3.3.

### Размещение: что в чём может содержаться

* **Fixed** значения идут куда угодно: локальные, глобальные, любое поле,
  элементы, полезные нагрузки, параметры, результаты.
* **Variable** значения идут в локальные и глобальные, параметры и результаты,
  полезные нагрузки, элементы массивов (что делает массив последовательным)
  и поля структур на любой позиции. Поле после переменного размера достаётся
  вычислением его смещения, что нормально при обходе и дорого при произвольном
  доступе.
* **Resizable** значения идут в локальные и глобальные, параметры по значению,
  результаты и **последнее поле** обычной структуры, что делает структуру тоже
  расширяемой. Root-структура может владеть несколькими на любой позиции поля.
  Никогда не элемент массива.
* **Root** владельцы идут только в локальные/глобальные объявления. Root нельзя
  владеть внутри другой структуры, массива или среза (даже массива
  фиксированного размера), полезной нагрузки перечисления, а также передавать
  или возвращать по значению. Ссылки на root подчиняются обычным правилам
  ссылок.
* **Zero-size** значения (`T[0]`, `T[..0]`, вариант без полей) существуют только
  как значения сами по себе, никогда как поле или элемент.

Ни один тип не содержит сам себя по значению, ни напрямую, ни через другие
типы. Он может ссылаться на себя через ссылку или срез, которые фиксированного
размера, что бы ни указывали: `enum List { Nil, Cons { v: i64, next: List? } }`
корректно. Спецификация §3.4.

### Литералы массивов

* `[1, 2, 3]`, и `[]` там, где тип элементов известен из цели: типизированная
  переменная, параметр, поле, элемент или результат.
* `[v; n]`: `n` копий `v`, где `n` константа времени компиляции; `v` вычисляется
  один раз.
* `[..cap]`: пустой `T[..]` с заданной ёмкостью времени исполнения.
* Литерал без типа цели является `T[k]` (или `T[]`, когда его элементы не
  фиксированного размера), и его элементы определяют `T`: `[1, 2, 3]` сам по
  себе это `i64[3]`. Литерал из констант подстраивается под параметр той формы,
  в которую вписывается: `take([0, 0, 0, 7])` передаёт `u8[4]` в
  `fn take(c: u8[4])`.
* `var out = [];` без всего прочего делает `out` массивом только-для-роста
  `T[>..]`, чей `T` фиксируется первым `push`, `append`, `format` или
  присваиванием целиком, которое должно произойти раньше любого другого
  использования.

```goose
fn take(c: u8[4]) -> i64 { c[3] }
fn main() {
    var out = [];                    // T[>..]; T определяет первый push
    out.push(2.5);                   // это f64[>..]
    let tbl: i64[4] = [7; 4];
    let names: u8[..8][3] = ["a", "bb", "ccc"];
    print(out, " ", tbl, " ", names, " ", take([0, 0, 0, 7]), " ", [1, 2, 3].len);
}
```

```
[2.5] [7, 7, 7, 7] ["a", "bb", "ccc"] 7 3
```

Литерал структуры и литерал варианта описаны в [разделе 8](#8-структуры) и
[разделе 9](#9-перечисления-алгебраические-типы-данных). Спецификация §4.2.

### Методы

Это встроенные операции. По UFCS ([раздел 17](#17-функции)) `a.push(v)` это
`push(a, v)`, поэтому функции стандартной библиотеки над массивами читаются
так же.

| Метод | На чём | Значение |
|---|---|---|
| `.len -> i64` | все виды массивов и срезы | количество элементов |
| `.cap -> i64` | `T[..k]`, `T[..]` | ёмкость |
| `.push(v) -> T&` | limited, grow-only, grow-shrink | один элемент, конструируется на месте; возвращает ссылку на него |
| `.append(src)` | limited, grow-only, grow-shrink | элементы массива, среза или литерала массива, копируются внутрь |
| `.move_from(src)` | срезы элементов фиксированного размера | копирует срезы равной длины с безопасным при перекрытии порядком |
| `.pop() -> T` | limited, grow-shrink; grow-only там, где усечение разрешено | удаляет и возвращает последний элемент |
| `.pop_n(n)` | то же | отбрасывает последние `n` элементов |
| `.resize(n, v)`, `.resize(n)` | то же | растёт копиями `v` или усекается |
| `.clear()` | то же | опустошает массив |
| `.index_of(r) -> i64` | массивы элементов фиксированного размера | индекс элемента, на который ссылается `r` |
| `.range_index(s, msg?) -> i64` | то же | начало полностью содержащегося среза; проверяется, когда происхождение не доказывает этого |
| `.check_length(n, msg?) -> i64` | grow-only, grow-shrink, элементы фиксированного размера | проверяет количество против резервирования стека данных; возвращает его, не меняя массив |

Рост всегда снабжает элементы значениями: нет операции, открывающей
неинициализированный слот. Превышение ёмкости массива limited прерывает
программу; то же делает усечение ниже пустого. `index_of` требует ссылку,
которую компилятор может доказать указывающей именно в тот самый массив
([раздел 12](#12-времена-жизни-корни-хранилища-и-запись)). `range_index`
принимает срезы, чьё происхождение известно только во время исполнения:
непустой срез должен быть выровнен по элементам и целиком внутри текущей длины
массива. Пустой срез, включая пустой срез по умолчанию или чужой, возвращает
ноль. `check_length` отклоняет отрицательные количества и количества, чьи
элементы одни превысили бы резервирование стека данных, включая слишком большие
беззнаковые количества. Он не выделяет хранилище и не обещает, что добавление
впишется в оставшееся место массива. Обе проверки действуют в каждой сборке.
Строковый литерал последним аргументом, `a.range_index(s, "msg")`, это
сообщение, с которым прерывает программа при провале проверки, вместо
сообщения среды исполнения; так формулируют свои сообщения пулы стандартной
библиотеки. `dst.move_from(src)` требует равных длин и прерывает программу до
записи, если они различаются. Он копирует исходные значения источника даже при
перекрытии срезов; источник не очищается. Оба операнда вычисляются один раз,
слева направо. Цель должна быть записываемой, и действуют обычные ограничения
копирования по времени жизни и относительным ссылкам. Пустые срезы копировать
можно, включая срезы по умолчанию. Типы пулов стандартной библиотеки и
устаревшие операции `reusable` в [разделе 14](#14-переиспользуемые-пулы).
Спецификация §3.3, §12.

```goose
fn main() {
    var xs: i64[>..<] = [];
    xs.push(1);
    xs.append([2, 3, 4]);
    let last .= xs.push(5);
    print(xs.index_of(last), " ", xs.pop(), " ", xs);
    xs.resize(6, 0);
    xs.pop_n(2);
    print(xs, " ", xs.len);
    xs.clear();
    print(xs.len);
}
```

```
4 5 [1, 2, 3, 4]
[1, 2, 3, 4] 4
0
```

### Сравнение на равенство

`==` и `!=` сравнивают массивы структурно: сначала длина, затем элементы.
Операнды *разных* видов массивов тоже сравниваются, как срезы, когда их срезы
имели бы один тип: `u8[>..]` со строковым литералом, поле `u8[..32]`
с `u8[:]`. Спецификация §4.5.


## 6. Строки и текст

Строкового типа нет. Строка это любой тип семейства массивов с элементами
`u8`, и то, какой вы выберете, говорит о намерении:

* `u8[>..]`: **построитель**. Добавление это сдвиг указателя.
* `u8[]` и `u8[varint]`: **готовая строка**, хранится встроенно в том, что её
  держит.
* `u8[..16]`: **малая строка** внутри структуры, без косвенности.
* `u8[:]`: **вид** на байты, живущие в другом месте. Строковый литерал один
  из таких, а именно `const u8[:]`, поскольку литералы это статические данные
  только для чтения.

Кодировка не навязывается; UTF-8 это соглашение библиотеки, и библиотечные
`each_utf8` и `push_utf8` его понимают.

```goose
fn main() {
    var s: u8[>..] = [];
    s.append("hello");
    s.push(',');
    format(s, " world! ", 6 * 7);            // format добавляет текст чего угодно
    let t: u8[] = "fixed";                   // копия литерала, 5 байтов и длина
    let v: const u8[:] = s[..5];             // вид на первые пять байтов s
    print(s, " [", s.len, " bytes] ", t, " ", v);
}
```

```
hello, world! 42 [16 bytes] fixed hello
```

Строковый литерал хранится только в слоте, объявленном `const`, поскольку он
только для чтения; копия его в любой массив `u8` (`let t: u8[] = "fixed";`)
даёт собственное записываемое значение. `u8[..16]` и прочие массивы limited
тоже построители, в пределах своей ёмкости: `format(p.name, "linus")`.

### Превращение значений в текст

Три встроенные функции превращают значения в текст, и каждая принимает любое
число аргументов любого типа, не вставляя ничего между ними:

* `print(a, b, …)` пишет текст и перевод строки в стандартный вывод одной
  записью, поэтому строки разных потоков никогда не перемешиваются.
* `format(out, a, b, …)` добавляет текст к `out`, любому растущему массиву
  `u8`.
* `str(a, b, …)` строит свежий `u8[>..]` с текстом, конструируемый прямо в
  своей цели: `words.push(str("item", i))` пишет прямо в новый элемент.

У каждого скаляра есть текстовая форма: целые в десятичном виде, плавающие
в кратчайшей форме, читающейся обратно в то же значение, `true` и `false`,
а массив `u8` как свои байты. Все остальные значения печатаются структурно:
массив как `[1, 2, 3]`, структура или вариант как свой позиционный литерал
с именем типа (`Point { 1, 2 }`, `Circle { 1.5 }`), ссылка как то, на что она
указывает, а пустой опционал как `null`. Символьный литерал это целое,
поэтому `str('x')` это `"120"`; одиночный байт добавляется через `push`.
Массив `u8`, вложенный в агрегат, печатается в кавычках и с экранированием.

**Перегрузка `format`** `fn format(out: u8[>..]&, v: T)`, принимающая `T` по
значению или по ссылке, вызывается для печати `T` всюду, где `T` встречается
в аргументе любой из трёх встроенных функций, поэтому тип задаёт свою
текстовую форму в одном месте. Дженерик-тип печатается через
дженерик-перегрузку вроде `fn format<T>(out: u8[>..]&, b: Box<T>)`, если
только не существует не-дженерик для его экземпляра; перегрузка на голой
переменной типа для печати не используется. Перегрузка ищется в пространстве
имён, где объявлен `T`, затем глобально, поэтому тип решает, как его печатать,
а не печатающий код. `T` не фиксированного размера никогда не копируется
неявно, поэтому его перегрузка принимает его по ссылке.

```goose
struct Person { name: u8[..16], age: i32 }
fn format(out: u8[>..]&, p: Person) { format(out, p.name, " (", p.age, ")"); }

fn main() {
    var people: Person[>..] = [];
    people.push(Person { name: "ada", age: 36 });
    people.push(Person { name: "grace", age: 45 });
    print(people, " ", str(people[0]).len);
    print(['a', 'b'], " ", "text"[0], " ", str('x'));
}
```

```
[ada (36), grace (45)] 8
[97, 98] 116 120
```

Спецификация §3.7. Модуль `std` стандартной библиотеки добавляет обычные
операции, все над `u8[:]`: `find`, `trim`, `split`, `words`, `join`,
`parse_int`, `parse_flt`, `format_int`, `compare`, `to_lower` и другие
([stdlib.md](stdlib.md#строки)). `split` возвращает массив срезов в свой вход:
каждая часть занимает несколько байтов, и текст не копируется.

```goose
fn main() {
    let line = "  key = some value  ";
    let body = trim(line);
    let eq = find(body, "=");
    print("'", trim(body[..eq]), "' -> '", trim(body[eq + 1..]), "'");
    let parts = split("alice,30,paris", ',');
    print(parts.len, " parts: ", parts, " ", words("  go   north "));
}
```

```
'key' -> 'some value'
3 parts: ["alice", "30", "paris"] ["go", "north"]
```


## 7. Срезы

`T[:]` это ссылка плюс количество элементов: вид на непрерывный ряд `T` внутри
какого-то массива. Это универсальный параметр "обработать диапазон", поскольку
любой вид массива превращается в срез без копирования элементов.

* **Нарезка**: `a[x..y]` это элементы от `x` до `y` (не включая `y`); любую
  границу можно опустить, а `^k` означает "`len - k`": `a[^2..]` это два
  последних элемента. Повторная нарезка среза всегда допустима и никогда его
  не растит.
* **Приведение**: когда массив или ссылка на него попадает в цель, чей тип это
  срез его типа элементов, он становится срезом всего массива целиком, как
  `a[..]`. Это действует для параметра, аннотированной переменной,
  присваивания, поля, добавляемого элемента, `return` и ветви `if`, чья другая
  ветвь срез.
* Срезы элементов фиксированного размера индексируются и обходятся с проверкой
  границ по собственной длине среза. Срезы элементов переменного размера только
  обходятся.
* Срез массива только-для-роста, взятый до `push`, остаётся действительным, но
  не включает новые элементы.

```goose
fn total(xs: i64[:]) -> i64 { var t = 0; for x in xs { t += x; } return t; }

fn main() {
    let fixed: i64[4] = [1, 2, 3, 4];
    var grow: i64[>..] = [10, 20, 30, 40, 50];
    let view: const i64[:] = fixed;       // сам fixed, не копия
    print(total(fixed), " ", total(grow), " ", total(grow[1..4]), " ",
          total(grow[^2..]), " ", view[0], " ", grow[..2].len);
    let s = grow[1..3];
    grow.push(60);                        // s всё ещё видит элементы 1 и 2
    print(s, " ", s == [20, 30]);
}
```

```
10 150 90 90 1 2
[20, 30] true
```

Срез **проверяемый**. Он несёт статический корень, переменную, ограничивающую
время жизни того, что он видит. Срез не может пережить ни эту переменную,
ни усечение, освободившее бы элементы. Проверяющий отслеживает живость,
а не область: срез, чьё последнее использование раньше `clear`, мёртв, и
`clear` разрешён. Правила в
[разделе 12](#12-времена-жизни-корни-хранилища-и-запись), а сторона усечения
в [разделе 13](#13-рост-усечение-и-присваивание-массивов-целиком).

```goose
fn main() {
    var line: u8[>..] = [];
    line.append("hello world");
    let w = line[..5];
    print(w);
    line.clear();                         // корректно: последнее использование w выше
    line.append("again");
    let v = line[..];
    // line.clear();                      // ошибка: нельзя очищать, пока v используется
    print(v);
}
```

```
hello
again
```

Срез это ссылка, поэтому он подчиняется тому же правилу записываемости. Срез
массива `var` записываем насквозь, а строковый литерал и срез значения `const`
нет. Параметр, объявленный `T[:]`, принимает и то и другое и проверяется по
данному аргументу. Функция, которая только читает через параметр-срез,
документирует это, объявляя параметр `const T[:]`. Спецификация §3.10, §9.5.

Поскольку срез никогда не копируется, это естественный ключ для таблицы.
Словарь библиотеки с ключом `const u8[:]` хранит виды на текст, который
программа уже держит:

```goose
import dictionary;

fn main() {
    let text = "the quick brown fox jumps over the lazy dog the fox";
    var counts = dictionary<const u8[:], i32> {};
    each_split(text, ' ') { counts.update(it, 0) { it += 1; }; };
    let n = counts.get("the");
    if n { print(counts.count, " distinct words; 'the' x", n); }
}
```

```
8 distinct words; 'the' x3
```


## 8. Структуры

```goose
struct Unit { kind: i32, hp: i32 = 100, x: f32, y: f32, name: u8[] }
```

Обычная структура это её поля в порядке объявления, **упакованные**:
заполнение не вставляется, невыровненный доступ считается дешёвым, и структура
из `i8[3]` и `i32` занимает 7 байтов. Объявления структур вводят номинальные
типы; две структуры с одинаковыми полями это разные типы.

### Литералы

Литерал называет свои поля или перечисляет их позиционно в порядке объявления;
две формы не смешиваются. Поля с объявленным значением по умолчанию можно
опустить: последние в позиционной форме, любые в именованной. Опциональное
поле без значения по умолчанию при опускании получает null. Литерал,
оканчивающийся на `..`, может опустить *любые* поля, которые тогда берут
значение по умолчанию своего типа: ноль, `false`, null, пустой массив или
строку. Поле, чей тип не имеет значения по умолчанию (неопциональная ссылка),
всё же должно быть задано.

```goose
struct Unit { kind: i32, hp: i32 = 100, x: f32, y: f32, name: u8[] }
var selected: Unit;                                             // глобальная с одним типом:
                                                                // каждое поле по умолчанию
fn main() {
    let a = Unit { kind: 1, x: 1.5, y: 2.5, name: "scout" };   // hp 100
    let b = Unit { 2, 50, 0, 0, "" };                           // позиционно, всё задано
    let c = Unit { kind: 3, .. };                               // hp 100, x 0, y 0, name ""
    print(a, " ", b.hp, " ", c, " ", selected.hp);
}
```

```
Unit { 1, 100, 1.5, 2.5, "scout" } 50 Unit { 3, 100, 0.0, 0.0, "" } 100
```

Глобальная `var`, которой дан только тип, стартует со значения по умолчанию
своего типа. Локальная должна быть инициализирована при объявлении, когда её
тип не фиксированного размера, поскольку хранилище значения раскладывается
при его конструировании. Локальная фиксированного размера может быть объявлена
первой и присвоена на каждом пути до чтения
([раздел 2](#2-объявления-переменные-и-область-видимости)).

Именованные инициализаторы можно писать вне порядка объявления, только когда
компилятор видит, что восстановление порядка ничего не меняет: чтения
и арифметика, которые не могут прервать программу, подходят; вызовы
с эффектами, индексация и циклы нет. Конструирование всегда идёт в порядке
объявления, прямо в каждое поле. Если эффекты должны произойти в другом
порядке, сделайте их до литерала. Спецификация §4.2.

### Значения полей по умолчанию

Значение по умолчанию это выражение, вычисляемое при каждом конструировании,
которое поле опускает. Оно вычисляется в порядке полей среди явных
инициализаторов. Оно может называть глобальные переменные и вызывать функции,
но никогда не может ссылаться на локальные переменные конструктора или соседние
поля. `default<T>()` ([Встроенные функции](#25-встроенные-функции)) строит `T`
фиксированного размера из объявленных значений по умолчанию, поэтому
инвариант, закодированный объявлением как значение по умолчанию, сохраняется
даже в дженерик-коде, заполняющем значения.

```goose
var serial = 0;
fn next() -> i64 { serial += 1; serial }
struct Rec { id: i64 = next(), tag: u8[..4] = "none", score: f64 = 1.0 }

fn main() {
    let a = Rec { .. };
    let b = Rec { score: 2.0 };
    let c = default<Rec>();
    print(a, " ", b, " ", c.id);
}
```

```
Rec { 1, "none", 1.0 } Rec { 2, "none", 2.0 } 3
```

Значение по умолчанию не может вести обратно к конструированию, которое
использует то же значение снова, поскольку это никогда бы не закончилось.
Спецификация §3.2.

### Квалификаторы полей и заполнение

* `let f: T` помечает поле, не присваиваемое после конструирования.
* `const f: T` это `let f: const T`: его содержимое тоже только для чтения.
* `pad n` вставляет `n` неиспользуемых байтов; голый `pad` выравнивает
  *следующее* поле по его скалярной ширине, для внешних раскладок. Байты
  заполнения никогда не читаются, и `==` их игнорирует.

```goose
struct Hdr { magic: u8[4], pad, size: u32, let kind: u8, const name: u8[..8] }

fn main() {
    var h = Hdr { magic: "FALO", size: 4, kind: 1, name: "x" };
    h.size = 8;
    // h.kind = 2;                    // ошибка: kind это let-поле
    // h.name.push('y');              // ошибка: name объявлено const
    print(h, " ", h.name.cap);
}
```

```
Hdr { "FALO", 8, 1, "x" } 8
```

Спецификация §3.2, §4.4.

### Поля переменного размера и `varint`

Структура может держать части переменного размера, и они лежат встроенно
в порядке объявления. `varint` это целочисленное поле LEB128, занимающее
столько байтов, сколько требует значение (один байт до 63, два до 8191 и так
далее; малые отрицательные так же коротки, как малые положительные). Структура
с полем `varint` или `u8[]` переменного класса, и её поля после такого поля
находятся обходом. Поле `varint` записывается только при конструировании;
чтения выдают `i64`.

```goose
struct Item  { sku: u8[varint], qty: varint, cents: varint }
struct Order { id: varint, customer: u8[varint], items: Item[varint] }

fn main() {
    var book: Order[>..] = [];
    book.push(Order { id: 1001, customer: "alice",
                      items: [Item { sku: "SKU-441", qty: 2, cents: 1999 },
                              Item { sku: "SKU-7", qty: 1, cents: 500 }] });
    for o in book {
        var t = 0;
        for it in o.items { t += it.qty * it.cents; }
        print(o.customer, " owes ", t, " cents over ", o.items.len, " items, ",
              bytes_of(book).len, " bytes in all");
    }
}
```

```
alice owes 4498 cents over 2 items, 29 bytes in all
```

Тот заказ занимает 29 байтов и не содержит ни одного указателя. Плата за это
в том, что `book` последовательный: обходите его или держите рядом индекс.
Поле или элемент переменного класса замораживаются после постройки: чтобы
изменить, перестройте их контейнер. Спецификация §3.4, §3.6.

### Расширяемый хвост

**Последнее** поле обычной структуры может быть расширяемым массивом, что
делает структуру расширяемой: она может жить там же, где растущий массив
(локальная, глобальная, параметр по значению, результат), но никогда как
элемент или среднее поле. Хвост растёт сквозь структуру как любой растущий
массив.

```goose
struct Stack { name: u8[..8], items: i64[>..<] }

fn push_twice(s: Stack&, v: i64) { s.items.push(v); s.items.push(v); }

fn main() {
    var s = Stack { name: "main", items: [] };
    push_twice(s, 7);
    s.items.pop();
    print(s.name, " ", s.items, " ", s.items.len);
}
```

```
main [7] 1
```

Спецификация §3.4, приложение C.2.

### Root-структуры

Как обычная структура, `root struct` собирает связанное состояние за
именованными полями. Он снимает требование, чтобы эти поля образовывали одно
непрерывное значение: каждое поле имеет независимое хранилище, поэтому
несколько полей могут расти отдельно. Поля могут быть фиксированными,
переменными или расширяемыми в любом порядке, и все разделяют время жизни
владеющей переменной.

Плата за это размещение: владеющая root-структура должна быть локальной или
глобальной переменной, а не полем или элементом массива. Она может
группировать состояние приложения, рабочее пространство или экземпляр
библиотеки:

```goose
root struct Workspace<T> {
    items: T[>..] = [],
    scratch: i64[>..<] = [],
    calls: i64 = 0
}

fn add<T>(s: Workspace<T>&, value: T) -> T& {
    s.calls += 1;
    let result .= s.items.push(value);
    s.scratch.push(s.calls);
    s.scratch.clear();                // не делает result недействительным
    return result;
}

fn main() {
    var state = Workspace<i64> { .. };
    let first .= state.add(7);
    state.add(8);
    print(first, " ", state.items, " ", state.calls);
}
```

```
7 [7, 8] 2
```

Владелец конструируется литералом прямо в локальном или глобальном объявлении.
Значения полей по умолчанию и `..` работают как обычно; типизированная
глобальная может опустить инициализатор. Компилятор определяет все стеки
компонентов статически и восстанавливает их при выходе из области.
Существующие ограничения на рекурсивные циклы действуют для владельцев
с нефиксированными полями: объявляйте такое состояние вне цикла и передавайте
в него ссылку.

Функции получают root по ссылке. Неаннотированная привязка от существующего
владельца тоже заимствует его; `.=` доступна, чтобы сделать это намерение
явным. Ссылки на владельца могут быть опциональными, храниться в обычных
структурах или массивах, возвращаться и захватываться вложенными функциями,
подчиняясь обычным правилам времени жизни и записываемости. Доступ к полям,
UFCS, рефлексия и форматирование работают через эти ссылки.

Изменяемое поле-массив только-для-роста глобального `var` root можно называть
в компактных типах ссылок и индексов: `Node&<u32 in pool.items>`,
`u32 in pool.items` и `u32 upto pool.items`. Имя разрешается в хранилище
именно этого поля; другое поле или владелец это другой массив. Поддерживаются
только прямые поля: путь не может идти через псевдоним, ссылку, индекс или
вложенное поле.

Сам владелец нельзя копировать, переприсваивать, передавать или возвращать
по значению, использовать как временное значение или помещать внутрь другой
структуры или массива. Это действует даже для root без расширяемых полей.
`root` работает только как модификатор перед `struct`; переменные, поля
и функции по-прежнему могут называться `root`.

У root нет упакованного байтового образа, равенства или арифметики значения
целиком и публичной C-раскладки. `pad` принадлежит обычной структуре-компоненту,
а не root. Сериализуйте подходящие поля по отдельности, например
`to_bytes(state.items)`; этот образ содержит только выбранный компонент.
Воркеры могут конструировать локальные root, но не могут получать владельцев
или ссылки на владельцев, а также использовать глобальный root напрямую или
через другую функцию. Глобальный root, не используемый воркером, допустим.
Вложенные владеющие root и фиксированные массивы владельцев отложены.
Спецификация §3.4, приложение C.2.

### Дженерик-структуры

```goose
struct Pair<T> { a: T, b: T }
struct Node<T> { v: T, next: Node<T>? }

fn main() {
    let p = Pair<i64> { 1, 2 };
    let q = Pair { a: 0.5, b: 1.5 };           // T выводится из полей
    var n = Node<u8> { v: 1, next: null };
    print(p, " ", q, " ", n.next == null);
}
```

```
Pair<i64> { 1, 2 } Pair<f64> { 0.5, 1.5 } true
```

Дженерик-структура моноформируется как функция, и её экземпляры должны быть
конечны: поле, называющее структуру снова с *большим* аргументом типа на каждом
круге (`struct P<T> { v: T, next: P<T[]>? }`), отклоняется. Спецификация §3.2.

### Равенство и арифметика

`==` и `!=` сравнивают обычные структуры поэлементно, исключая заполнение;
поле-ссылка или поле-срез сравнивается по идентичности (адрес и длина),
поскольку рекурсия через него могла бы зациклиться. Арифметические операторы
применяются поэлементно
([раздел 3](#арифметика-на-структурах-и-фиксированных-массивах)). Операторы
порядка существуют только на числах. Спецификация §4.5.


## 9. Перечисления (алгебраические типы данных)

```goose
enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 }, Dot }
```

Перечисление это тег, за которым следует полезная нагрузка одного из его
вариантов. Это единственная форма динамического полиморфизма в языке; нет ни
наследования, ни трейтов, ни vtable. Полезная нагрузка варианта объявляется
как поля структуры, с теми же правилами значений по умолчанию и `..`, а вариант
без полезной нагрузки это обычная константа. Перечисление, у которого все
варианты без полезной нагрузки, это C-подобное перечисление, один байт.
Литерал варианта это `Shape.Circle { r: 1.0 }`, или `Shape.Dot` для варианта
без полезной нагрузки. Литералы дженерик-перечисления, например
`enum Opt<T> { None, Some { v: T } }`, указывают его аргументы типов:
`Opt<i64>.Some { v: 1 }`, `Opt<i64>.None`.

### Два режима

Каждый тип перечисления может храниться двумя способами, выбираемыми в месте
использования типом, написанным там:

**Фиксированный режим** (`Shape`) это раскладка Rust `enum` или C++ `variant`:
тег плюс место под самую большую полезную нагрузку, поэтому каждый `Shape`
занимает 17 байтов, включая `Dot`. Он фиксированного размера, поэтому массив
таких индексируем, и значение может быть перезаписано на месте другим
вариантом. В обмен ничто не может указывать *внутрь* его полезной нагрузки:
`match` связывает полезную нагрузку только по значению. Применим, только когда
каждая полезная нагрузка фиксированного размера.

**Переменный режим** (`Shape..`, с конечными точками) даёт каждому значению
ровно размер его варианта: 1 байт для `Dot`, 9 для `Circle`, 17 для `Rect`.
Массив таких последовательный, и значение никогда не может сменить вариант,
поскольку соседи упакованы прямо за ним. В обмен можно брать ссылки внутрь
полезной нагрузки и править её на месте. Вариант с полезной нагрузкой
переменного размера (скажем, строкой) может использоваться только в этом
режиме.

```goose
enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 }, Dot }

fn main() {
    var shapes: Shape[>..] = [];                 // фиксированный режим: индексируем
    shapes.push(Shape.Circle { r: 1.0 });
    shapes.push(Shape.Dot);
    shapes[1] = Shape.Rect { w: 1.0, h: 1.0 };   // другой вариант, на месте
    print(shapes);

    var packed: Shape..[>..] = [];               // переменный режим: упаковано
    packed.push(Shape.Circle { r: 1.0 });
    packed.push(Shape.Rect { w: 2.0, h: 3.0 });
    packed.push(Shape.Dot);
    for s in packed {
        match s {
            Rect &r => { r.w += 1.0; },          // правит полезную нагрузку внутри массива
            _ => {},
        }
    }
    print(packed, " ", bytes_of(packed).len, " bytes");
}
```

```
[Circle { 1.0 }, Rect { 1.0, 1.0 }]
[Circle { 1.0 }, Rect { 3.0, 3.0 }, Shape.Dot] 27 bytes
```

Допущение либо замены варианта, либо внутренних ссылок, но никогда обоих,
обеспечивает корректность системы типов. Спецификация §3.5.

### `match`

```goose
enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 }, Dot }

fn name(s: Shape) -> u8[:] {
    match s {
        Circle c => if c.r > 1.0 { "big circle" } else { "circle" },
        Rect r => if r.w == r.h { "square" } else { "rectangle" },
        Dot => "dot",
    }
}

fn round(s: Shape) -> bool {
    match s { Circle, Dot => true, Rect => false }
}

fn main() {
    print(name(Shape.Circle { r: 2.0 }), " ", name(Shape.Rect { w: 1.0, h: 1.0 }), " ",
          round(Shape.Dot));
}
```

```
big circle square true
```

* Сопоставление по перечислению исчерпывающее: у каждого варианта есть ветвь,
  или `_` покрывает остальные. Вариант не называется дважды.
* `Circle c =>` связывает полезную нагрузку **по значению**, как копию,
  которую нельзя писать. `Circle &c =>` связывает её **по ссылке**. Это
  допустимо только для сопоставляемого значения переменного режима, и вариант
  никогда не может быть заменён через такую ссылку.
* Ветвь может перечислить несколько вариантов, `Circle, Dot =>`, и тогда
  не связывает ничего, поскольку их полезные нагрузки разных типов.
* `match` это выражение; его ветви должны сойтись на типе, с обычной
  подстройкой литералов ([раздел 16](#16-выражения-и-поток-управления)).
  Ветвь из нескольких операторов это блок, `Rect &r => { … },`.

**Над целыми** ветви это литералы, именованные константы, полуоткрытые
диапазоны или список таких через запятую, и `_` требуется. Берётся первая
подходящая ветвь; ветвь, целиком покрытая более ранней, ошибка. Имя это
вариант, когда сопоставляемое значение перечисление, и константа, когда целое.

```goose
let GROUND = 0;
let SHALLOW = 1;
let DEEP = 4;
let LAVA = 7;

fn terrain(t: i64) -> u8[:] {
    match t {
        GROUND => "ground",
        SHALLOW..DEEP => "water",
        LAVA, 10..12, -3 => "hot",
        _ => "rock",
    }
}

fn main() {
    for t in [0, 2, 7, 11, -3, 20] { print(t, " ", terrain(t)); }
}
```

```
0 ground
2 water
7 hot
11 hot
-3 hot
20 rock
```

Спецификация §8.1.

### Функции-ветви

Вместо этого ветви `match` можно записать как отдельные функции, по одной на
тип варианта, и вызывать со значением перечисления. Вызов диспетчеризуется
по тегу через таблицу переходов, и исчерпывающность проверяется точно как для
`match`: каждому варианту нужна ровно одна применимая перегрузка, и типы
результатов должны сойтись. Это даёт эффект виртуального вызова без vtable,
а добавление варианта ошибка компиляции, пока у него нет своей функции.

```goose
enum Shape { Circle { r: f64 }, Rect { w: f64, h: f64 }, Dot }

fn area(s: Shape.Circle) -> f64 { 3.14159 * s.r * s.r }
fn area(s: Shape.Rect) -> f64   { s.w * s.h }
fn area(s: Shape.Dot) -> f64    { 0.0 }

fn main() {
    var shapes: Shape[>..] = [];
    shapes.push(Shape.Circle { r: 1.0 });
    shapes.push(Shape.Rect { w: 2.0, h: 3.0 });
    shapes.push(Shape.Dot);
    var total = 0.0;
    for s in shapes { total += area(s); }
    let c = Shape.Circle { r: 2.0 };          // тип варианта это обычный тип
    print(total, " ", area(c));
}
```

```
9.14159 12.56636
```

Типы вариантов (`Shape.Circle`) это обычные типы: они могут быть типом
значения, параметра, поля или ссылки `Shape.Circle&`. Перегрузка, принимающая
`Shape.Rect&`, связывает полезную нагрузку по ссылке и требует сопоставляемого
значения переменного режима, как связыватель `&`. Диспетчеризация по одной
позиции параметра; остальные аргументы передаются насквозь, и каждый аргумент
вычисляется один раз до выбора ветви тегом. Диспетчеризация по тегу пробуется,
только когда обычная перегрузка не подошла вызову. Спецификация §8.2.

### Перечисления со ссылками

Перечисление может ссылаться на свой тип через ссылку, что делает возможными
связные и древовидные данные в пуле. В сочетании с переменным режимом и узкими
связями [раздела 11](#11-относительные-ссылки) дерево из по большей части
маленьких узлов больше не нуждается в месте под самый большой вариант в каждом
узле:

```goose
enum Expr {
    Num { v: f64 },
    Add { l: Expr..&<u16>, r: Expr..&<u16> },
}

fn eval(e: Expr.Num&) -> f64 { e.v }
recursive fn eval(e: Expr.Add&) -> f64 { eval(e.l) + eval(e.r) }

fn main() {
    var pool: Expr..[>..] = [];
    let a = pool.push(Expr.Num { v: 1.5 });
    let b = pool.push(Expr.Num { v: 2.0 });
    let sum = pool.push(Expr.Add { l: a, r: b });
    print(eval(sum), " in ", bytes_of(pool).len, " bytes");
}
```

```
3.5 in 23 bytes
```

Каждый `Num` занимает 9 байтов, а `Add` 5: тег и два 2-байтовых смещения.
Ключевое слово `recursive` объясняется в [разделе 19](#19-рекурсия).


## 10. Ссылки и опциональные значения

`T&` это ссылка на `T`: один машинный адрес, без арифметики указателей,
без приведений и без способа сделать её висячей. Спецификация §3.8.

### Ссылки прозрачны

Выражение, обозначающее ссылку, ведёт себя как её цель в каждом контексте
значения: чтения, арифметика, сравнения (`r1 == r2` сравнивает цели), передача
параметру по значению, `print(r)`. Оператора разыменования нет, и `->` нет.
Запись через ссылку, `r = v` или `r += v`, пишет цель.

Поскольку сама ссылка невидима в обычных выражениях, есть отдельный синтаксис
для "ссылки, а не цели":

* `let r .= e;` и `var r .= e;` объявляют `r` как ссылку на `e`, что бы ни было
  `e`: переменная, поле, элемент или вызов, возвращающий ссылку.
* `r .= e;` перепривязывает существующую переменную-ссылку, поле или элемент
  на `e`.
* `r1 .== r2` и `r1 .!= r2` сравнивают две ссылки по адресу.

```goose
fn main() {
    var xs: i64[>..] = [10, 20, 30];
    var r .= xs[0];              // r ссылается на элемент 0
    var c = xs[0];               // c копия элемента 0
    r = 11;                      // пишет xs[0]
    c = 99;                      // пишет копию
    r .= xs[2];                  // r теперь ссылается на элемент 2
    r += 1;
    print(xs, " ", c, " ", r, " ", r .== xs[2], " ", r == xs[2]);
}
```

```
[11, 20, 31] 99 31 true true
```

### Создание и привязка ссылок

`&x` создаёт ссылку на lvalue: переменную, поле, элемент или то, на что
указывает другая ссылка. `&` временного значения ошибка. `&` места, хранящего
ссылку, выдаёт хранимую ссылку: ссылок на ссылки нет.

Где объявленный тип цели это ссылка, lvalue указываемого типа связывается
**без** `&`, а написание `&` даёт предупреждение:

```goose
fn inc(n: i64&) { n += 1; }

struct Cursor { line: i64& }

fn main() {
    var count = 0;
    inc(count);                  // связывает count по ссылке
    inc(count);
    let r: i64& = count;         // аннотированная переменная-ссылка
    r += 10;
    let cur = Cursor { line: count };
    cur.line += 100;
    print(count);
}
```

```
112
```

Где тип переменной выводится, ссылка на значение **фиксированного размера**
вырождается в копию цели: `let x = r;` копирует. Исключения это явный
инициализатор `&lvalue`, который выводит ссылочный тип, и форма `.=`. Lvalue
**не фиксированного** размера связывается по ссылке в любой форме, поскольку
значения не фиксированного размера никогда не копируются неявно
([раздел 4](#копии-видимы)):

```goose
fn main() {
    var n = 1;
    var xs: i64[>..] = [1];
    let a = &n;                  // ссылка: явный &
    let b .= n;                  // ссылка: форма .=
    let c = xs;                  // ссылка: xs не фиксированного размера
    var r .= n;
    let d = r;                   // копия n: r вырождается
    a += 1; b += 1; c.push(2);
    print(n, " ", d, " ", xs);
}
```

```
3 1 [1, 2]
```

Функция, чей тип результата записан `T&`, возвращает ссылку. Функция
с выводимым типом результата возвращает ссылку, когда возвращает lvalue
не фиксированного размера или явный `&x`, и копию, когда возвращает ссылку
на значение фиксированного размера. Чтобы привязать вызов, возвращающий
ссылку, к элементу фиксированного размера, используйте `.=` или аннотируйте:
`let e .= pool.push(v);`.

Переменная-ссылка `let` не перепривязывается, но это ничего не говорит
о цели, которая записываема, как и была: `let r .= xs[i]; r = 5;` пишет
элемент.

### Опциональные значения

Ссылки никогда не null. `T?` это **опциональный `T`**: обнуляемая ссылка,
представленная ссылкой, чей null это адрес 0, без затрат места. Он сочетается
с любым типом (`i64?` опциональное целое, по ссылке), а применённый к
ссылочному типу лишь делает эту ссылку обнуляемой: `T&?` это `T?`. Литерал
`null` его пустое значение, и опциональное поле структуры без объявленного
значения по умолчанию при опускании получает null.

Опционал **не прозрачен**. Сначала его нужно *сузить* через `if`, `while`,
`guard`, `assert` или сравнение с `null`. Внутри суженной области он *есть*
`T&`: прозрачный, записываемый насквозь и привязываемый через `.=`.
Перепривязка переменной заканчивает сужение, кроме `while`, чьё условие и есть
проверка: он выполняет её заново перед каждой итерацией.

```goose
fn first_at_least(xs: i64[:], min: i64) -> i64? {
    for &x in xs { if x >= min { return x; } }
    return null;
}

struct Node { v: i64, next: Node? }

fn main() {
    let xs: i64[4] = [1, 5, 8, 2];
    let big = first_at_least(xs, 5);
    if big { print("first >= 5 is ", big); } else { print("none"); }
    let none = first_at_least(xs, 100);
    print(none == null);

    var c = Node { v: 3, next: null };
    var b = Node { v: 2, next: c };
    var a = Node { v: 1, next: b };
    var cur: Node? = a;
    var sum = 0;
    while cur {                      // сужён для тела, перепроверяется каждый раз
        sum += cur.v;
        cur .= cur.next;
    }
    print(sum);
}
```

```
first >= 5 is 5
true
6
```

Опционал перепривязывается через `.=` к ссылке, что сужает его, или к `null`,
что не сужает. Суженный опционал пишет насквозь как любая ссылка; способа
писать насквозь, не сузив его, нет. `assert(o)` сужает до конца блока.
Спецификация §3.8.

### Куда могут указывать ссылки

Ссылка может указывать на всё, кроме полезной нагрузки перечисления
фиксированного режима ([раздел 9](#два-режима)). Ссылка внутрь массива
роста-и-усечения `T[>..<]` имеет дополнительное ограничение: она может
храниться только в переменной и должна больше не использоваться, когда массив
в следующий раз усечётся
([раздел 13](#13-рост-усечение-и-присваивание-массивов-целиком)). Ссылки внутрь
массивов только-для-роста остаются действительными, пока их можно назвать.
Ссылки внутрь массивов limited остаются действительными через pop и push
и читают то значение, которое их слот держит сейчас.


## 11. Относительные ссылки

`T&` занимает восемь байтов, и адрес не значит ничего вне процесса, который
его создал. **Относительная ссылка** это та же связь, хранимая узким смещением:
`T&<u8>`, `T&<u16>`, `T&<u32>`, `T&<u64>` или `T&<varint>`. Чтение выдаёт
обычную `T&`, а запись переэнкодит её; иначе она используется как любая другая
ссылка. Есть две формы, различающиеся тем, от чего меряется смещение:

* **Самоотносительная**, по умолчанию, `T&<u32>`: смещение от самого поля
  к цели, которая должна жить в том же охватывающем массиве. Структура
  позиционно-независима, поэтому её можно копировать, сохранять и загружать
  целиком ([раздел 23](#23-сериализация)).
* **Относительная к пулу**, `T&<u32 in pool>`: смещение от базы названного
  глобального массива `pool`. Запись это вычитание из базы, уже лежащей
  в регистре, и *другие* массивы могут держать связи в пул.

`T&<u32>?` это опциональная форма, со смещением 0 как null, поэтому связь стоит
четыре байта вместе со своим null. Спецификация §3.9.

### Дерево в одном массиве

```goose
struct Node { key: i32, count: i32 = 1, left: Node&<u32>?, right: Node&<u32>? }

fn insert(pool: Node[>..]&, key: i32) {
    if pool.len == 0 { pool.push(Node { key: key }); return; }
    var cur .= pool[0];
    loop {
        if key == cur.key { cur.count += 1; return; }
        let next = if key < cur.key { cur.left } else { cur.right };
        if next { cur .= next; continue; }
        if key < cur.key { cur.left .= pool.push(Node { key: key }); }
        else { cur.right .= pool.push(Node { key: key }); }
        return;
    }
}

recursive fn in_order(n: Node&, out: i32[>..]&) {
    let l = n.left;
    if l { in_order(l, out); }
    out.push(n.key);
    let r = n.right;
    if r { in_order(r, out); }
}

fn main() {
    var pool: Node[>..] = [];
    for k in [50, 30, 70, 20, 40, 60, 80, 30] { insert(pool, k as i32); }
    var keys: i32[>..] = [];
    in_order(pool[0], keys);
    print(keys, " ", pool.len, " nodes, ", bytes_of(pool).len, " bytes, ", pool[1].count);
}
```

```
[20, 30, 40, 50, 60, 70, 80] 7 nodes, 112 bytes, 2
```

Узел занимает 16 байтов: два `i32` и две 4-байтовые связи.
`cur.left .= pool.push(…)` добавляет узел и сохраняет смещение, и push не может
сделать `cur` недействительным, потому что ничто не перемещается. Запись
самоотносительной связи требует, чтобы компилятор видел, что ссылка и цель
происходят из **одного и того же корневого массива, точно**: здесь оба `pool`.
Смещение проверяется на диапазон при записи только там, где массив мог бы
занять больше, чем вмещает ширина.

### Копирование значений, держащих самоотносительные связи

Самоотносительное смещение имеет смысл только там, где было записано, поэтому
значение, которое его *содержит*, не может быть скопировано никак: присваиванием
из переменной, как аргумент по значению или связыватель match, как копия
элемента или через `copy(x)`. Такие значения конструируются на месте (литерал,
добавляемый в массив), связываются по ссылке (`let n .= f();`, а не
`let n = f();`, как подсказывает ошибка), сопоставляются связывателями `&`
и принимаются по ссылке в функциях-ветвях и перегрузках `format`. Значение,
чьи связи все `in pool`, копируется как любое другое, поскольку его смещения
не зависят от того, где оно лежит. Единственная копия, которая всегда
допустима, это значения по умолчанию: `..` литерала ставит относительное поле
в null. Спецификация §3.9.

Функция или завершающий блок может вернуть свежее значение с относительными
связями. Оно конструируется у получателя, в том числе через границы вызовов
функций и с выключенной оптимизацией:

```goose
struct Node { value: i64, next: Node&<u32>? }
fn linked(first: Node&, value: i64) -> Node {
    Node { value: value, next: first }
}
fn add<F>(nodes: Node[>..]&) { nodes.push(F()); }
fn main() {
    var nodes: Node[>..] = [Node { value: 1 }];
    nodes.push(linked(nodes[0], 2));
    let first .= nodes[0];
    add(nodes) { Node { value: 3, next: first } };
    let next = nodes[2].next;
    if next { print(next.value); }  // 1
}
```

Каждый вызов должен поместить результат в тот же корень, что и связанный
элемент. Например, `let n = linked(nodes[0], 2)` ошибка: новая локальная
переменная это отдельное хранилище. Вернуть существующий узел по значению всё
ещё запрещённая копия. Результат, которому нужен корень получателя, также
нельзя использовать как заполнитель resize или преобразовывать через временное
представление массива.

### Связи относительно пула и `self`

`pool` в `T&<u32 in pool>` называет глобальный массив `var` (включая устаревший
`reusable var`) или изменяемое поле-массив глобального `var` root, например
`T&<u32 in pool.items>`. Массив должен быть только-для-роста, и его элементы
держат `T`; пул часть идентичности типа. Хранимое значение это смещение от базы
пула плюс один, поэтому 0 это null в опциональной форме, а связь `u32` покрывает
пул в 4 ГБ. Чтение укореняется в `pool`, точно, откуда бы связь ни была
прочитана. Это позволяет контейнеру связей оставаться пригодным там, где
контейнер обычных ссылок был бы двусмысленным.

Неопциональная относительная ссылка не имеет null, поэтому значение, чьи связи
должны указывать на само значение, не могло бы быть построено: пока не на что
указать. **`self`**, написанное как весь инициализатор такого поля, обозначает
значение, которое литерал конструирует. Так циклический список получает
часового. После этого ни одна связь не null, и каждая вставка и удаление это
одни и те же четыре записи:

```goose
import slot_pool;

struct Node { val: i64, prev: Node&<u32 in pool.items>, next: Node&<u32 in pool.items> }

var pool = slot_pool<Node> {};
let head .= pool.alloc_with() { Node { val: 0, prev: self, next: self } };   // часовой

fn insert_after(p: Node&, v: i64) -> Node& {
    let n .= pool.alloc_ref(Node { val: v, prev: p, next: p.next });
    n.next.prev .= n;
    p.next .= n;
    return n;
}

fn remove(n: Node&) {
    n.prev.next .= n.next;
    n.next.prev .= n.prev;
    pool.free(pool.items.index_of(n));
}

fn is_end(n: Node&) -> bool { n .== head }

fn main() {
    insert_after(head, 1);
    let two .= insert_after(head.prev, 2);   // .=: `let two = …` скопировал бы узел
    insert_after(head.prev, 3);
    remove(two);
    var line: u8[>..] = [];
    var n .= head.next;
    while !is_end(n) { format(line, n.val, " "); n .= n.next; }
    print(line, "| ", pool.items.len, " slots, ", 8 + 4 + 4, " bytes a node");
}
```

```
1 3 | 4 slots, 16 bytes a node
```

Заметьте `.=` на `two`: `Node` фиксированного размера, поэтому
`let two = insert_after(…)` скопировал бы узел из пула, и `remove(two)` получил
бы просьбу освободить слот локальной копии, что компилятор отклоняет.

`self` допустимо только в литерале структуры или варианта, и только для
неопционального поля относительной ссылки, чей указываемый тип это
конструируемый тип, а для поля `in pool` только в литерале, построенном внутри
того массива (в `push`, записи элемента или построителе `slot_pool.alloc_with`).
`alloc_with` выбирает слот цели до вызова построителя, поэтому `self` указывает
на тот слот. `alloc_ref` принимает уже сконструированное значение; используйте
его, когда конструирование, зависящее от цели, не нужно. Обе операции объяснены
в [разделе 14](#14-переиспользуемые-пулы).

### Какую форму выбрать

* **Самоотносительная** для позиционно-независимых блобов, то есть компактного
  дерева, которое сохраняется, отображается или перемещается целиком, и для
  структур, живущих в локальном или параметровом пуле, у которого нет имени
  для записи в тип.
* **`in pool`** для структур с частыми перепривязками в глобальном пуле, где
  запись это вычитание из регистра; для связей *в* пул из других массивов, чего
  самоотносительная выразить не может; и там, где смещение нужно как индекс,
  поскольку `&pool[i]` энкодится как `i * sizeof(T) + 1`, а `index_of` читает
  его обратно.

Указывает ли параметр в пул, решается в каждом месте вызова, поэтому функция,
которая перепривязывает, специализируется на каждый пул и не требует лишнего
аргумента для пула. Результат функции нельзя объявить относительным:
объявите `T&` или `T?`, а относительный слот, принимающий его, энкодит его.

### Индекс для последовательного массива

Массив элементов переменного размера нельзя индексировать
([раздел 5](#ограничения-на-элементы)), но второй массив 4-байтовых связей
в него можно:

```goose
enum Mark { Circle { r: f64 }, Label { text: u8[varint] }, Dot }

var marks: Mark..[>..] = [];
var mark_at: (Mark..&<u32 in marks>)[>..] = [];

fn main() {
    mark_at.push(marks.push(Mark.Label { text: "hello, faloya" }));
    mark_at.push(marks.push(Mark.Circle { r: 1.5 }));
    mark_at.push(marks.push(Mark.Dot));
    for i in [2, 0, 1] {
        match mark_at[i] {
            Circle c => print(i, ": circle ", c.r),
            Label l => print(i, ": label \"", l.text, "\""),
            Dot => print(i, ": dot"),
        }
    }
    print(bytes_of(marks).len, " bytes of marks, ", mark_at.len, " links of 4 bytes");
}
```

```
2: dot
0: label "hello, faloya"
1: circle 1.5
24 bytes of marks, 3 links of 4 bytes
```

`push` возвращает ссылку на элемент, который он построил. Когда эта ссылка
записывается в `mark_at`, она становится смещением метки от базы `marks`.
Массив, от которого меряется смещение `in`, должен быть глобальным; локальный
массив можно индексировать так же массивом обычных ссылок, `(Mark..&)[>..]`,
по восемь байтов на запись.


## 12. Времена жизни: корни, хранилища и записываемость

Это весь "проверяющий заимствований" Faloya:

> Ссылка или срез не должна пережить переменную, владеющую её целью, и никогда
> не должна наблюдать свою цель под неверным типом.

Аннотаций времён жизни нигде в языке нет, и правил псевдонимности или
исключительности нет: две ссылки на одно и то же допустимы, поскольку без
конкурентности с разделяемой памятью одна лишь псевдонимность не может здесь
нарушить безопасность типов. Спецификация §9.1.

### Корни

У каждой ссылки и среза есть один или несколько статических **корней**. Корень
это локальная или глобальная переменная или временное значение, ограничивающее
время жизни цели ссылки. Корень **точный**, когда собственное хранилище этой
переменной содержит цель, и неточный, когда он лишь ограничивает время жизни
цели. Корни выводятся, никогда не пишутся: `&x` укоренён в `x` точно, срез
параметра функции укоренён в том, что передал вызывающий, а ссылка, прочитанная
из контейнера, укоренена в переменных, чьё хранилище могло бы держать её цель.
Функции специализируются на каждом различном корне, что даёт точность
параметров времён жизни без какого-либо синтаксиса для них. Спецификация §9.2.

### Правила

* **Запись.** Ссылка может быть записана в место (переменную, поле, элемент,
  глобальную) только если её корень переживёт владельца места. Объявление
  записывает своё значение в объявляемую переменную.
* **Возврат.** Корень возвращаемой ссылки должен быть видим вызывающему:
  аргумент, данный вызывающим, глобальная или собственный результат функции,
  сконструированный на месте. Часть собственной локальной переменной функции
  умирает с ней.
* **Ветви.** Значение `if`, `match`, `block` или цикла принимается после того,
  как области, открытые его ветвями, закончились, поэтому оно не может быть
  укоренено в переменной, объявленной внутри ветви.
* **Слитые значения.** Значение, которое может прийти из любого из нескольких
  мест (ветви `if`, привязки `var`-ссылки, возвраты функции), имеет корни всех
  их и должно удовлетворять каждому правилу для каждого из этих корней.
* **Перепривязка.** Переменная-ссылка обязуется корню своей первой привязки:
  `.=` может перепривязать её в пределах того же корня или к корню той же
  глубины области, что обычный случай обхода контейнера. Всё остальное требует
  новую переменную.
* **Временные значения.** Литерал, результат вызова, `copy` или значение
  управляющей конструкции живут до конца своего оператора. Вид на них можно
  передать вниз, но нельзя хранить в переменной, переживают оператор, и нельзя
  возвращать: `let s = f()[..];` ошибка, а `let t = f(); let s = t[..];`
  корректно.
* **Держатели.** Держатель (структура с полями-ссылками, массив срезов,
  полезная нагрузка со ссылкой) укоренён в том, что было записано в него.
  Проверяющий записывает каждую такую запись, поэтому он ловит и усечение,
  или выход из области, которые оставили бы ссылку в держателе висячей.

Ошибка времени жизни называет оба конца: корень ссылки и её цель.

```goose
fn longest(a: u8[:], b: u8[:]) -> u8[:] { if a.len >= b.len { a } else { b } }

fn main() {
    var outer: u8[>..] = [];
    outer.append("outer");
    var w = outer[..];
    {
        var inner: u8[>..] = [];
        inner.append("inner text");
        w = longest(outer, inner);   // ошибка: запись ссылки с корнем в inner
    }
    print(w);
}
```

Результат `longest` может указывать в любой из аргументов, поэтому он укоренён
в обоих, а `inner` не переживает `w`. Перенесите объявление `w` внутрь блока
или скопируйте текст наружу, и это скомпилируется.

```goose
fn make() -> u8[>..] { str("made") }

fn main() {
    let t = make();
    let s = t[..];                   // корректно: t живёт
    let u = make()[..];              // ошибка: вид на временное значение
    print(s, " ", u);
}
```

### Записываемость

Всё записываемо, если тип не говорит иного. `const T` это значение, чьё
содержимое нельзя писать: `const i64[3]` не может получить присваивание
элементу, а `const T&` и `const T[:]` это ссылка и срез, через которые цель
нельзя писать, растить или усекать. Записываемость *выводится* на каждый
экземпляр, как корни:

* **Только чтение**: строковый литерал; `&x` или `x[..]` значения `const`, его
  поля или привязки `for` или `match` по значению; вид на временное значение;
  вид `bytes_of`; что бы ни было прочитано из слота, объявленного `const`.
* **Записываемо**: всё остальное, включая `&x` и `x[..]` от `var` или простого
  `let`.
* **Параметры и результаты дженерики по константности.** Параметр, объявленный
  `u8[:]`, принимает записываемый или доступный только для чтения аргумент,
  и тело проверяется с тем, что ему дано: запись через параметр, получивший
  литерал, ошибка в этом вызове, с цепочкой вызовов. Параметр, объявленный
  `const u8[:]`, только для чтения, что бы ему ни дали, так функция
  документирует, что только читает. Добавить `const` неявно можно всюду;
  убрать его никогда.
* **Слоты говорят, что держат.** Поле, элемент, глобальная или аннотированная
  переменная держит ссылку только для чтения, только если её тип `const`:
  `struct Named { name: const u8[:] }` может держать литерал,
  `struct Buf { bytes: u8[:] }` не может. Переменная без аннотации берёт
  константность инициализатора, поэтому `var t = trim(line);` для `line` только
  для чтения это курсор `const u8[:]`.
* `const` **мелкий**: ссылка, прочитанная из поля `const Box&`, записываема
  настолько, насколько говорит собственный тип поля.

```goose
fn upper_first(s: u8[:]) { if s.len > 0 && s[0] >= 'a' { s[0] -= 32; } }

struct Named { name: const u8[:] }

fn main() {
    var buf: u8[>..] = [];
    buf.append("faloya");
    upper_first(buf);                  // записываемый аргумент: корректно
    let n = Named { name: "literal" }; // слот const принимает литерал
    let who = if buf.len > 3 { n.name } else { buf[..] };   // только чтение, одна ветвь такая
    print(buf, " ", who);
    // upper_first("literal");         // ошибка: запись через параметр только для чтения
}
```

```
Faloya literal
```

Спецификация §9.5.

### Куда может указывать ссылка, прочитанная из контейнера

Контейнер определяет область, но не обязательно хранилище, в которое указывает
его содержимое. Поэтому проверяющий выводит корень заново при чтении ссылки
из контейнера. Каждая переменная в области, чьё хранилище может держать тип
указываемого, **кандидат**. С одним кандидатом ссылка укоренена там точно.
С несколькими она укоренена во всех них неточно.

Некоторые операции требуют точной идентичности массива: запись относительной
связи, вызов `index_of` или определение того, какой массив освободит усечение
через ссылку. Если проверяющий не может выбрать, он сообщает кандидатов:
"`n` was read out of `slots` and may point into `pool` or `spare`". Два правила
сужают кандидатов. Относительная связь `in pool` указывает точно в `pool`.
Локальный держатель, чьи записи все известны проверяющему, укоренён
в записанных в него значениях. Спецификация §9.5.

### Чтение ошибок

Когда проверяющий что-то отклоняет, читайте всё сообщение. Он называет ссылку
*и* место её привязки, держатель *и* строку, записавшую в него, экземпляр *и*
цепочку вызовов, его породившую. Используйте эти два места, чтобы решить,
какой конец изменить: последний раз используйте вид до усечения, перенесите
усечение или перенесите объявление.


## 13. Рост, усечение и присваивание массивов целиком

Рост прост: `push` и `append` сдвигают вершину стека, а массив limited растёт
в пределах ёмкости. Различаются виды массивов в усечении, поскольку усечение
освобождает элементы, на которые что-то может ещё указывать.

### Массивы только-для-роста усекаются там, где ничего не указывает внутрь

"Только-для-роста" называет гарантию, а не набор операций: **`T[>..]` никогда
не усекается, пока ссылка или срез внутрь него может быть жива.** Память ниже
вершины никогда не перемещается и не переиспользуется, пока владелец жив,
поэтому каждая ссылка внутрь массива остаётся действительной, пока её можно
назвать. Усечение (`pop`, `pop_n`, `resize` вниз, `clear` или присваивание
массива целиком) законно ровно там, где компилятор видит, что ничто,
укоренённое в массиве, ещё не используется:

* ни одна *переменная* ссылки или среза, укоренённая в массиве, не используется
  после усечения (в собственном блоке, охватывающем блоке или более поздней
  итерации окружающего цикла), и
* ни один *держатель* (структура с полем-ссылкой, массив срезов), ещё
  используемый, не получил записи ссылки внутрь массива, и
* собственный оператор усечения не использует ссылку внутрь массива,
  вычисленную им раньше (`use(a[0], a.pop())` ошибка; `a[0] + a.pop()` нет,
  поскольку он читает свой левый операнд первым).

Проверка на живость, а не на область: срез, чьё последнее использование раньше
усечения, мёртв, и усечение корректно. Поэтому черновой буфер, заполняемый
заново на каждой итерации, может свободно раздавать срезы себя. Ошибка, если
есть, называет держатель и строку, где ссылка внутрь массива была в него
записана.

```goose
fn reset(buf: u8[>..]&) { buf.clear(); }

fn main() {
    var line: u8[>..] = [];
    for i in 3 {
        reset(line);                        // ничего не указывает в line здесь
        format(line, "line ", i + 1);
        let head = line[..4];
        print(head, "|", line[4..]);        // последнее использование head
    }
    var holder: u8[:][>..] = [];
    holder.push(line[..]);
    // line.clear();                        // ошибка: holder может держать ссылку в line,
                                            //        записанную push выше
    print(holder.len);
}
```

```
line| 1
line| 2
line| 3
1
```

Усечение через параметр-ссылку или глобальной не видит переменных вызывающего,
поэтому проверяется на каждом уровне. Каждая функция записывает, какие
глобальные и чьи цели параметров она усекает, а вызов
