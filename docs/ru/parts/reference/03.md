проверяется так, как если бы он делал эти усечения в вызывающем. `pop`,
`pop_n` и `resize` также требуют элементов фиксированного размера, поскольку
последовательный массив не может найти свой последний элемент. Спецификация
§5.1.

### Массивы роста-и-усечения держат свои ссылки в переменных

`T[>..<]` держит элементы фиксированного размера и усекается откуда угодно:
на локальной, через ссылку, на глобальной, как хвост структуры. Плата в том,
что **ссылки и срезы внутрь него живут только в переменных.** Их можно
привязать к локальной, передать вниз и вернуть, но никогда не записать в поле,
элемент, глобальную или литерал. После pop освобождённая память на вершине
стека может быть переиспользована другим типом, поэтому никакая ссылка внутрь
не может пережить следующее усечение. Поскольку такие ссылки держатся вне
хранилища, проверке достаточно просмотреть переменные в области. Усечение
ошибка, пока такая переменная ещё используется после; ошибка называет
переменную и место её привязки.

```goose
fn main() {
    var stack: i64[>..<] = [];
    for i in 5 { stack.push(i * 10); }
    let top .= stack[4];
    print(top);                             // последнее использование top
    stack.pop();                            // корректно
    var popped = 0;
    while stack.len > 2 { popped += stack.pop(); }
    print(stack, " popped ", popped);
}
```

```
40
[0, 10] popped 50
```

Вызов **сбалансирован** для массива, когда массив никогда не короче во время
вызова, чем в его начале, например функция, которая берёт `let mark = xs.len`,
добавляет и заканчивает `xs.resize(mark)`. Сбалансированный вызов не
освобождает ничего, на что указывает вид, взятый до него, поэтому он не
считается усечением в месте, где он сделан. Так рекурсия делит один черновой
стек ([раздел 19](#19-рекурсия)). Спецификация §5.2.

### Массивы limited

`T[..k]` и `T[..]` свободно растут и усекаются в пределах ёмкости, а ссылки
внутрь них разрешены и переживают pop: ёмкость и тип элементов фиксированы,
поэтому слот, однажды записанный, навсегда остаётся действительным значением
типа элементов. Устаревшая ссылка читает то значение, которое слот держит
сейчас, никогда не портит память. Превышение ёмкости прерывает программу.
Спецификация §5.3.

### Присваивание массива целиком

Lvalue можно присвоить после конструирования, когда его размер не может
измениться или когда он может поглотить изменение:

* lvalue `var` фиксированного размера: простая перезапись;
* целый расширяемый массив или значение, чей хвост такой: присваивание значит
  *очистить, затем построить*. Правая часть строится там, где были старые
  элементы, поэтому она не может использовать массив вовсе, даже его длину
  (`x = f(x)` ошибка; постройте новое содержимое в переменной и присвойте её
  `copy()`);
* массивы limited, если новая длина влезает;
* lvalue перечислений фиксированного режима, любым вариантом;
* **не** присваиваемо: lvalue переменного класса (`T[]` поля, значения
  перечислений переменного режима, `varint` поля), которые заморожены при
  конструировании. Вместо этого перестройте контейнер.

```goose
struct Rec { name: u8[], score: i64 }

fn main() {
    var xs: i64[>..] = [1, 2, 3];
    xs = [4, 5];                            // усечение, затем новое содержимое
    var ys: i64[>..] = [xs[0] + 1];
    xs = copy(ys);                          // вычислено из другого хранилища: корректно
    var recs: Rec[>..] = [];
    recs.push(Rec { name: "a", score: 1 });
    for r in recs { r.score = 2; }          // поле фиксированного размера: присваиваемо
    // for r in recs { r.name = "bb"; }     // ошибка: поле переменного класса заморожено
    var one = Rec { name: "a", score: 1 };
    // one = Rec { name: "bb", score: 3 };  // ошибка: как и локальная переменная переменного класса
    recs = [Rec { name: "bb", score: 3 }];  // вместо этого перестройте контейнер
    print(xs, " ", recs, " ", one.score);
}
```

```
[5] [Rec { "bb", 3 }] 1
```

Спецификация §4.4.

### Конструирование в процессе

Пока значение строится на месте внутри массива (добавляемый элемент,
добавляемый результат вызова, новое содержимое присваивания целиком), ничто
не может растить этот массив: ни строящееся выражение, ни вызываемая им
функция. `xs.push(f(xs))`, где `f` добавляет в свой аргумент, отклоняется.
Спецификация §1.3, §4.2.


## 14. Переиспользуемые пулы

У некоторых данных времена жизни не вкладываются: записи кэша, узлы
редактируемого графа, файлы, удаляемые в любом порядке. Используйте
[`slot_pool<T>`](stdlib.md#slot_pool) стандартной библиотеки для отдельных
слотов и [`slice_pool<T>`](stdlib.md#slice_pool) для непрерывных рядов. Каждый
это root-структура, собирающая массив `items` и его метаданные переиспользования
в одном объявлении. Владельцы должны быть локальными или глобальными
переменными; функции принимают их по ссылке.

**`reusable` и `reusable[]` устарели.** Встроенные операции остаются доступными
для существующего кода и [оставшихся пробелов
миграции](../design/root_structs.md#separate-follow-up-reusable-pools-in-the-stdlib).
Их удаление это шаг на потом.

Импортируйте `slot_pool`, чтобы использовать эти операции:

| Операция | Значение |
|---|---|
| `a.alloc_index(v) -> i64` | индекс слота, держащего `v`: освобождённый слот, если есть, иначе свежий push |
| `a.alloc_ref(v) -> T&` | то же, в виде ссылки |
| `a.free(i)` | помечает слот `i` для переиспользования; прерывает программу, если `i` вне диапазона |

`free` не освобождает память и не заканчивает время жизни. **Каждый элемент
во все моменты остаётся действительным, живым значением своего типа**, поэтому
ссылка на освобождённый и переиспользованный слот читает *другое значение
правильного типа*: логическая ошибка того же рода, что устаревший индекс, но
никогда порча памяти, путаница типов или выход за границы. Такие логические
ошибки и есть вся небезопасность, и этот дизайн позволяет нагрузкам
с изменением деревьев работать без аллокатора.

```goose
import slot_pool;
struct Item { id: i32, weight: f32 }

fn main() {
    var pool = slot_pool<Item> {};
    let s0 = pool.alloc_index(Item { 10, 1.0 });
    let s1 = pool.alloc_index(Item { 11, 1.0 });
    pool.free(s0);
    let s2 = pool.alloc_index(Item { 12, 2.0 });   // забирает слот s0 обратно
    let node .= pool.alloc_ref(Item { 13, 3.0 });
    pool.free(pool.items.index_of(node));          // ссылка, превращённая обратно в свой слот
    print("slots ", s0, " ", s1, " ", s2, ", pool length ", pool.items.len);
}
```

```
slots 0 1 0, pool length 3
```

Пул может быть локальным или глобальным. Его массив `items` никогда не
усекается через API пула; `items.len` включает свободные слоты. Используйте
`items` для обычного доступа к массиву и передавайте владельца как
`slot_pool<T>&`. Элементы должны быть фиксированного размера. `alloc_index`
и `alloc_ref` принимают обычно копируемые значения. Для свежих значений
с самоотносительными связями или относительным к пулу `self` используйте
`pool.alloc_with() { Node { value: 1, me: self } }`: построитель выполняется
один раз, прямо в выбранном слоте, и возвращает ссылку на него. Не правьте его
метаданные `free_slots` и не усекайте `items` напрямую. Поддерживаемые типы
и правила времён жизни см. в [контракте библиотеки](stdlib.md#slot_pool).

### Пулы срезов

`slice_pool<T>` выдаёт *ряды* элементов вместо отдельных слотов, с деревом
свободных промежутков, сливающим соседей:

| Операция | Значение |
|---|---|
| `a.alloc_slice(n) -> T[:]` | `n` элементов из первого свободного промежутка, который их вмещает, иначе с конца массива, который растёт; каждый возвращённый элемент сбрасывается к значению по умолчанию |
| `a.free_slice(s)` | помечает ряд `s` для переиспользования |
| `a.realloc_slice(s, n) -> T[:]` | `s` изменён до `n` элементов, на месте где возможно, иначе освобождён и скопирован туда, куда `alloc_slice(n)` его положит |

Это подходит спискам потомков n-арного дерева: записи каждого узла это один
непрерывный ряд, обходимый как обычный срез.

```goose
import slice_pool;
fn main() {
    var pool = slice_pool<i64> {};
    let a = pool.alloc_slice(3);
    a[0] = 1; a[1] = 2; a[2] = 3;
    let b = pool.alloc_slice(2);
    b[0] = 7; b[1] = 8;
    pool.free_slice(a);
    let c = pool.alloc_slice(2);            // из освобождённого ряда, сброшено к умолчаниям
    let d = pool.realloc_slice(b, 4);       // b до конца массива: растёт на месте
    print(c, " ", d, " ", pool.items.len, " ", pool.items);
}
```

```
[0, 0] [7, 8, 0, 0] 7 [0, 0, 3, 7, 8, 0, 0]
```

free и resize принимают поддиапазоны выделенных рядов. Непустой срез должен
быть выровнен и целиком внутри `items`; где проверяющий не может это доказать,
вызов проверяет во время исполнения. Пустые срезы и срезы по умолчанию можно
освобождать безвредно, а рост пустого среза выделяет новый ряд. Двойные free
остаются логическими ошибками; проверки занятости нет. Выросший срез может быть
перемещён, поэтому `realloc_slice` недоступен для типа элементов, держащего
самоотносительные связи. Выделение и free поддерживают самоссылающиеся элементы
со значением по умолчанию. Передавайте владельца как `slice_pool<T>&`
и используйте его массив `items` для индексации и нарезки. [Контракт
библиотеки](stdlib.md#slice_pool) покрывает значения по умолчанию, поддиапазоны,
пустые срезы, хранилище по высокой воде и перемещение.

### Устаревшие встроенные пулы

Старые объявления `reusable var pool: T[>..] = [];` и
`reusable[] var pool: T[>..] = [];` всё ещё предоставляют соответствующие
операции прямо на массиве, со скрытыми метаданными. Их тип параметра
`T[>..]&`; происхождение пула несёт метаданные через вызовы. Существующие
операции `push` и `append` добавляют в конец, не используя освобождённые
промежутки. Их неизменившаяся семантика задана в
[спецификации §5.4](goose_spec.md#54-переиспользуемые-массивы-безопасный-запасной-путь-выделения).

Для миграции импортируйте подходящий модуль, объявите `slot_pool<T> {}` или
`slice_pool<T> {}`, обновите параметры владельцев до соответствующей
root-ссылки и используйте `pool.items` для операций над массивом. Глобальные
индексные и относительные к пулу типы могут называть `pool.items`. Для
значения, которому нужно конструирование в принимающем слоте, замените
`alloc_ref(value)` на `alloc_with() { value }`; при необходимости получите его
индекс через `pool.items.index_of`. Обычные выделения значений и операции над
срезами сохраняют имена методов. Передача владельца воркерам остаётся пробелом
миграции; держите устаревшие встроенные операции для кода, требующего снимков
воркеров. Локальные для воркера пулы библиотеки уже работают.


## 15. Индексные типы и функции checkfree

Каждый индекс проверяется на границы, и компилятор убирает проверки, которые
может доказать ненужными ([раздел 16](#проверки-границ)). Проверка, которую
не убирает никакой анализ, это индекс, читаемый из *другого* массива,
`dist[adj[k]]`, поскольку попадание в диапазон зависит от содержимого одного
массива в сравнении с длиной другого. Индексные типы переносят эту проверку
туда, где индекс входит в программу.

**Индексный тип** `uN in a` (`u8`, `u16`, `u32` или `u64`) это беззнаковое
целое, которое ниже `a.len` везде, где его можно наблюдать. **Тип границы**
`uN upto a` это беззнаковое целое, которое не более `a.len`, используемое для
конца диапазона. `a` называет глобальный массив `var` (включая устаревший
`reusable var`) или изменяемое поле-массив глобального `var` root, например
`u32 in graph.nodes`. Он должен быть только-для-роста с элементами
фиксированного размера, и массив часть идентичности типа: `u32 in nodes`
не `u32` и не `u32 in edges`. Значение это простое целое.

```goose
struct Node { lo: u32 upto edges, hi: u32 upto edges, weight: i32 }
var nodes: Node[>..] = [];
type NodeId = u32 in nodes;          // псевдоним читается лучше при каждом использовании
var edges: NodeId[>..] = [];
```

* **Создание.** `x as (uN in a)` прерывает программу в каждой сборке, если
  не выполнено `0 <= x < a.len`, с ошибкой, которую дал бы `a[x]`. Это проверка
  границ, перенесённая в эту точку, и проход проверок границ убирает её там,
  где убрал бы `a[x]`. `as!` не может создать индекс, и литерал никогда
  не подстраивается под него.
* **Использование.** Индексация `a` индексом `a` не требует проверки. Значение
  неявно преобразуется к своему простому целочисленному типу, поэтому
  арифметика над ним даёт простые целые; составное присваивание месту
  индексного типа ошибка, как и поэлементная арифметика над структурой или
  фиксированным массивом, держащим его.
* **Циклы.** `for i in lo..hi`, чьи границы индексные или граничные типы одного
  массива, даёт `i` индексный тип этого массива; то же делает `for i in n`
  с `n` такого типа.
* **Передача.** Объявления, параметры, результаты, поля, полезные нагрузки
  и элементы несут тип, и ветвь, чьи ветви-рукава все имеют индексные типы
  одного массива, сохраняет его (на самой широкой разрядности). Ссылка на такое
  хранилище это `(u32 in a)&`, никогда `u32&`.
* **Никогда не усекается.** Массив, названный индексным типом, не может быть
  усечён нигде, поэтому значение, однажды вошедшее в диапазон, остаётся в нём.
  У индексного типа нет значения по умолчанию. `from_bytes` проверяет каждый
  индекс в образе против его массива.

Индексный тип не принимает постфикса, поэтому массив таких это
`(u32 in nodes)[>..]` или, с псевдонимом, `NodeId[>..]`. Индексный тип на
связывателе `for` тоже в скобках: `for v: (u32 in nodes) in …`.

```goose
struct Node { lo: u32 upto edges, hi: u32 upto edges, weight: i32 }
var nodes: Node[>..] = [];
type NodeId = u32 in nodes;
var edges: NodeId[>..] = [];

fn add_node(w: i32) -> NodeId {
    let none = 0 as (u32 upto edges);
    nodes.push(Node { lo: none, hi: none, weight: w });
    return (nodes.len - 1) as NodeId;
}

fn main() {
    for w in [5, 3, 8, 1] { add_node(w as i32); }
    for v in nodes.len {                                   // v связан с v + 1 и v + 2
        nodes[v].lo = edges.len as (u32 upto edges);
        for d in 1..3 { if v + d < nodes.len { edges.push((v + d) as NodeId); } }
        nodes[v].hi = edges.len as (u32 upto edges);
    }
    var total = 0;
    for v in nodes.len {
        let n = nodes[v];
        for k in n.lo..n.hi { total += nodes[edges[k]].weight; }   // проверок не осталось
    }
    let w = edges[0];
    let plain: u32 = w;                                    // как число
    print(total, " ", w, " ", plain + 1);
}
```

```
21 1 2
```

Спецификация §3.11, `docs/design/index_types.md`.

### `checkfree fn`

`checkfree` просит компилятор отклонить программу, если проверка границ
осталась где-либо в тексте функции после устранения проверок границ, в каждой
специализации и каждой копии, встроенной в вызывающего. Она ничего не меняет
в том, что программа вычисляет. Каждый вызов в такой функции должен быть
в другую функцию `checkfree`, встроенную функцию или `extern fn`, а вызываемый
блок должен быть написан в функции `checkfree`. Остальные прерывания остаются,
в частности `assert`, которым такая функция заявляет свои предусловия один раз,
вне своих циклов:

```goose
var nodes: i32[>..] = [];
type NodeId = u32 in nodes;

checkfree fn sum_at(ids: NodeId[:], weights: i32[>..]&) -> i64 {
    assert(weights.len >= nodes.len);          // один раз; цикл тогда свободен от проверок
    var t = 0;
    for id in ids { t += nodes[id] + weights[id]; }
    return t;
}

fn main() {
    for w in [1, 2, 3] { nodes.push(w as i32); }
    var weights: i32[>..] = [10, 20, 30];
    let ids: NodeId[2] = [2 as NodeId, 0 as NodeId];
    print(sum_at(ids, weights));
}
```

```
44
```

Внутри функции `checkfree` компилятор должен доказать ненужность по меньшей
мере этих проверок:

* константный индекс в фиксированный массив;
* индекс индексного типа `a` в `a`;
* индекс индексного типа `a` в `b`, где было заявлено `b.len >= a.len` и ни один
  массив с тех пор не менялся;
* индекс `for` в массив, чья длина это его счётчик;
* `a[i]` после условия, установившего `0 <= i < a.len`;
* повтор уже пройденной проверки.

Ошибка называет оставшуюся проверку и почему. `checkfree` ставится после
`export` и перед `inline`, `simd`, `recursive` или `fn`, и вложенная функция
наследует её. Спецификация §7.14.


## 16. Выражения и поток управления

Язык ориентирован на выражения: `if`, `match`, `block` и голый `{ … }` это
выражения, и значение блока это его последнее выражение. Присваивание, `++`
и `--` операторы. Операторы это операторы C и Rust, с приоритетами Rust
([приложение A](#приложение-a-ключевые-слова-и-операторы)).

### `if`

```goose
let hp = 30;
let kind = if hp > 50 { "healthy" } else if hp > 0 { "hurt" } else { "down" };
if hp > 0 { print(kind); }               // как оператор: else не нужен
```

При использовании как значение `if` требует финального `else`, и его ветви
сходятся в один тип. Ветвь-литерал подстраивается под тип другой:
`if c { x } else { 0 }` имеет тип `x`, `u8` при `u8` `x`, а
`if c { x } else { 0.5 }` это `f32` при `f32` `x`. Целая ветвь рядом
с плавающей преобразуется к плавающей. Конструкция, чьи ветви все литералы,
сама литерал-подобна и подстраивается всюду, где встречает тип. Массивы и срезы
одного типа элементов сходятся как *срез*: где одна ветвь строковый литерал,
а другая поле `u8[..16]`, результат это `const u8[:]` на поле, без копирования.
Спецификация §6.4.

```goose
struct Item { name: u8[..16], count: i64 }
fn main() {
    let item = Item { name: "bolt", count: 0 };
    let name = if item.count == 0 { "none" } else { item.name };   // это const u8[:]
    let k: u8 = if item.count > 0 { 1 } else { 2 };               // литералы подстраиваются под u8
    print(name, " ", k);
}
```

```
none 2
```

Завершающая конструкция, которая не может дать значение, это оператор: `if`
без `else`, `match` с ветвью, заканчивающейся `return`, или `loop`, ни один
из чьих `break` не несёт значения. Поэтому функция с выводимым результатом
может закончиться такой и не выдать ничего.

### `block`, `break` со значением и голые блоки

`block { … }` даёт `break` цель без цикла, поэтому цепочка проверок может
выйти со значением. Голый `{ … }` только область: `break` внутри него покидает
охватывающий цикл или `block`. Все `break E` одной конструкции должны сойтись
на типе `E`.

```goose
struct P { alive: bool, hp: i64 }
fn main() {
    let p = P { alive: true, hp: 0 };
    let verdict = block {
        guard p.alive else { break "gone"; }
        guard p.hp > 0 else { break "dead"; }
        "standing"
    };
    let doubled = { let t = p.hp + 1; t * 2 };
    var n = 0;
    let found = loop { n += 7; if n % 5 == 0 { break n; } };
    print(verdict, " ", doubled, " ", found);
}
```

```
dead 2 35
```

### `guard`

`guard c;` выполняет остаток своего блока только там, где `c` верно, а
`guard c else { … }` выполняет вместо этого блок `else`. Это `if`, вывернутый
наизнанку, и сам по себе он никуда не прыгает. Напрямую в теле функции остаток
блока это остаток функции; в теле цикла пропуск остатка переходит к следующей
итерации; в теле функционального значения он заканчивает этот вызов значения.
Выйти дальше блока дело блока `else`: `guard c else { return; }` покидает
функцию, `guard c else { break; }` цикл. В коде после guard условие известно
верным, что включает сужение опционала: после `guard r else { return; }`,
`r` это `T&`.

```goose
fn half(n: i64) -> i64 { guard n % 2 == 0 else { return -1; } n / 2 }
fn tenfold(p: i64?) -> i64 { guard p else { return 0; } p * 10 }

fn main() {
    for i in 5 { guard i % 2 == 0; print("even ", i); }
    let v = 4;
    print(half(8), " ", half(7), " ", tenfold(v), " ", tenfold(null));
}
```
