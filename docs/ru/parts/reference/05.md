# Справочник по языку Faloya

## 23. Сериализация

Структура, чьи ссылки являются самоотносительными смещениями, означает одно
и то же в любом месте памяти, поэтому сохранить её значит записать её байты,
а загрузить значит прочитать. Три встроенных операции делают это для любого
массива:

| Встроенная операция | Смысл |
|---|---|
| `to_bytes(a) -> u8[>..]`, `to_bytes(a, out)` | кадрированный образ массива: счётчик байтов в varint, затем область элементов; новый буфер или дописывание в `out` |
| `bytes_of(a) -> u8[:]` | одна область элементов как срез только для чтения; ничего не копируется |
| `from_bytes<T[>..]>(b: u8[:]) -> T[>..], bool` | **проверенный** массив из недоверенного образа; `false` и пустой массив, если образ им не является |

Байты, приходящие извне программы, единственное место, откуда ссылка может
попасть в программу без проверки компилятором, поэтому `from_bytes`
проверяет их прежде, чем они станут значением. Он проверяет кадрирование,
каждый тег, каждую длину, каноничность varint и то, что каждая ссылка
попадает на начало элемента того же образа. Повреждённый или враждебный
файл даёт `false` и никогда дикий указатель. Проверяется *безопасность*, и
целостность данных остаётся на совести программы: отредактированные байты
данных всё ещё описывают корректную структуру, а добавление контрольной
суммы лежит на самой программе.

```goose
struct Node { word: u8[..8], count: i32, left: Node&<u32>?, right: Node&<u32>? }

fn insert(pool: Node[>..]&, word: u8[:]) {
    if pool.len == 0 { pool.push(Node { word: word, count: 1 }); return; }
    var cur .= pool[0];
    loop {
        let c = compare(word, cur.word[..]);
        if c == 0 { cur.count += 1; return; }
        let next = if c < 0 { cur.left } else { cur.right };
        if next { cur .= next; continue; }
        if c < 0 { cur.left .= pool.push(Node { word: word, count: 1 }); }
        else { cur.right .= pool.push(Node { word: word, count: 1 }); }
        return;
    }
}

fn lookup(pool: Node[>..]&, word: u8[:]) -> i32 {
    guard pool.len > 0 else { return 0; }
    var cur .= pool[0];
    loop {
        let c = compare(word, cur.word[..]);
        if c == 0 { return cur.count; }
        let next = if c < 0 { cur.left } else { cur.right };
        guard next else { return 0; }
        cur .= next;
    }
}

fn main() {
    var index: Node[>..] = [];
    each_word("the quick fox and the lazy dog and the fox") { insert(index, it); };
    var image: u8[>..] = index.to_bytes();          // кадрированный образ массива
    var loaded, ok = from_bytes<Node[>..]>(image);  // проверка до того, как станет значением
    print(ok, " ", loaded.len, " nodes, 'the' x", lookup(loaded, "the"), ", ",
          bytes_of(index).len, " bytes");
    image[image.len - 3] = 200;                     // порча ссылки
    var bad, bok = from_bytes<Node[>..]>(image);    // ложь и пустой массив
    print(bok, " ", bad.len);
}
```

```
true 6 nodes, 'the' x3, 126 bytes
false 0
```

Возвращается обычный массив: его можно индексировать и растить, а ссылки в
него являются обычными ссылками. `from_bytes` строит также `T[>..<]` и
семейство `T[]`, кроме `T[>..<]`, чьи элементы хранят относительные ссылки:
усечение результата освободило бы то, что его собственные ссылки ещё
называют. Массив индексных типов он сверяет со своим массивом. Ссылки в
*поле* элемента и ссылки `in pool` не сериализуемы. Срез `bytes_of` никогда
не записываем: байты, записанные через него, были бы ссылками, которые
проверщик никогда не доказывал. Контракт байтов описан в
`docs/design/serialization.md`. Спецификация §3.9, §9.4, §12.

## 24. Вызов C и вызов из C

### `extern fn`

Объявление без тела привязывает сигнатуру Faloya к функции C. Строка после
`=` там, где стояло бы тело, это символ C; без неё используется имя Faloya.
Старая форма `extern "cbrt" fn cube_root(...)`, со строкой после `extern`,
устарела и даёт предупреждение. Такое объявление стоит на верхнем уровне,
полностью типизировано, не дженерик и участвует в разрешении перегрузок на
равных с другими функциями. Вызов компилируется в прямой вызов C.

```goose
struct Stats { lo: i32, hi: i32, mean: f64 }

extern fn cube_root(x: f64) -> f64 = "cbrt";    // libm, по имени C
extern fn hypot(x: f64, y: f64) -> f64;
extern fn crc32_bytes(s: const u8[:]) -> u32;   // срез проходит как { data, len }
extern fn stats_of(xs: i32[:], out: Stats&);    // структура заполняется через указатель
extern fn c_version(out: u8[>..]&);             // строитель, в который C дописывает
```

Пересечь границу может ровно то, что имеет плоскую форму C:

* целые и вещественные скаляры и `bool`;
* любое плоское значение фиксированного размера (структуры, фиксированные
  массивы и массивы статической ёмкости, enum фиксированного вида) по
  значению, как упакованный тип C;
* `T&` к такому `T`, как указатель;
* `T[:]` такого `T`, как структура `{ data, len }`;
* `T[>..]&` такого `T`, в которую C может писать и дописывать целые
  элементы (`gs_bld_append` дописывает байты в `u8[>..]&`).

Результат это один скаляр или плоское значение фиксированного размера, либо
ничего. Всё остальное (`varint`, ссылки внутри структур, переменные или
растущие значения по значению, опционалы) отвергается на объявлении.
Параметр так же записываем, как говорит его тип, поэтому аргумент только
для чтения требует объявить `const`. C не должен удерживать заимствованный
аргумент дольше вызова. Собственный C программы кладётся в sidecar
`foo.build` рядом с `foo.fal` (`c_sources = ["impl.c"];`). Программа,
запущенная в процессе (`faloya run`), связана только с самим компилятором,
который поставляет функции C99 `<math.h>` в обеих ширинах (все, кроме
`nexttoward`) и почти ничего сверх них из библиотеки C; прочие функции
библиотеки C требуют `faloya build`, собственного C программы или блока
`extern "lib"`
([command_line.md](../command_line.md)). Заголовки из `c_headers` в sidecar
или из `--include header.h` могут пользоваться типами, которые Faloya
породила сама; см. [packages.md](../packages.md).

### `extern "lib" { … }`: разделяемая библиотека, привязанная по имени

Блок `extern` называет разделяемую библиотеку и объявляет функции,
привязываемые из неё при старте программы, без компиляции или сборки C.
Программа открывает библиотеку и ищет символы; отсутствующая библиотека или
символ это ошибка времени выполнения, которая называет попытанное имя.
Член блока это `extern fn` без слова `extern`; его строка после `=`, если
она есть, его символ C.

```goose
extern "SDL2" {
    fn SDL_Init(flags: u32) -> i32;
    fn SDL_Quit();
    fn SDL_GetTicks64() -> u64;
    fn delay(ms: u32) = "SDL_Delay";
}
```

`"SDL2"` открывает `SDL2.dll`, `libSDL2.dylib` или `libSDL2.so`, найденные
поиском загрузчика. `"bin/steam_api64"` открывает этот файл с тем же
правилом именования для его последнего компонента внутри каталога ресурсов
программы (`resource_dir()`); так программа кладёт библиотеку рядом с
собой. Имя с точками, например `"libSDL2-2.0.so.0"`, берётся как написано.
Имя, которое различается между платформами или установками, кладётся в
sidecar:

<!-- fragment -->
```goose
// myprog.build
dylibs_linux = ["SDL2=libSDL2-2.0.so.0"];     // soname, который ставит каждый дистрибутив
dylibs_windows = ["SDL2=bin/SDL2.dll"];       // поставляется с программой
```

Sidecar пакета отображает свои имена как значения по умолчанию, а sidecar
программы переопределяет их платформа за платформой для упомянутых имён.

Без адаптера член объявляет настоящий прототип библиотеки в терминах форм
Faloya:

* **Скаляры** это их типы C: `i32` это `int`, `u32` `unsigned`, `i64`
  `int64_t`, `f32` `float`, `f64` `double`, `bool` один байт, `size_t`
  `u64`. `enum` в C, включая `SDL_bool`, это `int`, поэтому он объявляется
  `i32`. C-тип `long` это `i64` на Linux и macOS и `i32` на Windows, поэтому
  функция с `long` требует объявления на каждую платформу или адаптера.
* **Непрозрачные дескрипторы**, например `SDL_Window *`, который библиотека
  возвращает и принимает обратно, это `u64`: жетон, который Faloya
  передаёт дальше, не заглядывая внутрь.
* **Указатель на то, чем владеет Faloya**, это `T&` для плоского
  фиксированного `T`: `fn SDL_GetWindowSize(w: u64, x: i32&, y: i32&)`.
  Где C хочет `(ptr, count)`, передайте `xs[0]` и `xs.len` двумя
  аргументами; где он хочет строку с NUL на конце, допишите `\0` и
  передайте первый байт по ссылке:

  ```goose
  extern "SDL2" {
      fn SDL_CreateWindow(title: const u8&, x: i32, y: i32, w: i32, h: i32, flags: u32) -> u64;
  }
  let title = "Faloya\0";
  let win = SDL_CreateWindow(title[0], 100, 100, 640, 480, 0);
  ```

* **Структуры** пересекают границу в упакованной раскладке Faloya, которая
  совпадает с C только тогда, когда поля уже лежат там, где их положил бы
  C. `SDL_Rect { int x, y, w, h }` совпадает с
  `struct Rect { x: i32, y: i32, w: i32, h: i32 }`. `u8` перед `i32`
  требует `pad 3`, написанный там, где pad ставит C, а структура, чей размер
  C округляет вверх, например `{ a: i32, b: u8 }`, требует `pad 3` в
  конце, чтобы её можно было держать в массиве, который индексирует C.
  Структура с `pad` пересекает границу только по ссылке. По значению её
  pad это байты, которые соглашение о вызовах передаёт, а паддинг C вовсе
  не передаётся, поэтому `{ x: f32, pad 4, y: f64 }` прибыл бы в чужих
  регистрах. Структура, переданная по ссылке, `const Rect&`, требует
  переменную, ведь литерал не может быть целью ссылки: напишите
  `let r = Rect { 0, 0, 10, 10 }; SDL_HasIntersection(r, s)`, не кладя
  литерал в вызов.
* **Память, которой владеет библиотека**, например `const char *`, который
  она возвращает, или массив, который она держит, тоже возвращается как
  `u64`. `ffi::cstr(p)` и `ffi::bytes(p, n)`
  ([stdlib.md](../stdlib.md#ffi)) копируют то, что там, в хранилище
  Faloya: `print(ffi::cstr(SDL_GetError()))`.
* **Всё ещё работа адаптера**: обратные вызовы (указатель на функцию,
  который хочет библиотека) и вариадические функции, которые привязать
  нельзя вовсе. Каждому нужны несколько строк C в нативной части.

Привязывается только член, до которого доходит вызов, и библиотека, ни один
член которой не вызван, не открывается вовсе, поэтому блок может объявить
интерфейс шире, чем использует конкретная программа. Программа, чей весь C
это такие библиотеки, работает под встроенным бэкендом без установленного
тулчейна C. Спецификация §7.10,
[packages.md](../packages.md).

### `export fn`

`export fn` делает функцию Faloya вызываемой из C: компилятор порождает
обёртку C под именем функции или под данной строкой. Функция должна быть
верхнеуровневой и не дженерик, с явными типами параметров и максимум одним
типизированным результатом. Значения по умолчанию, `return … from`,
параметры пулов и строители границу не поддерживают. Скаляры и плоские
значения фиксированного размера возвращаются по значению, а результат
`const u8[:]` приходит как указатель и дополнительный параметр
`int64_t *` с длиной (байты без NUL на конце).

```goose
export fn hello_world() -> const u8[:] { return "Hello, world!" }
export "c_add" fn add(a: i32, b: i32) -> i32 { a + b }

fn main() { print(hello_world(), " ", add(20, 22)); }     // один запуск, внутри faloya_init
```

```
Hello, world! 42
```

`faloya --standalone --header hello.h -o hello.c hello.fal` строит C для
хоста на C. У C нет собственного `main`, и он идёт с заголовком,
объявляющим `faloya_init(argc, argv)`, который хост вызывает один раз до
всего остального. Эта функция поднимает среду исполнения и глобальные
переменные и запускает `main` на Faloya, если он есть, поэтому `main` это
то место, где библиотека держит код запуска. Экспортированные функции не
безопасны для потоков: вызывайте их из потока, который вызвал
`faloya_init`. `faloya_exit()` завершает программу и освобождает то, что
запуск создал, так что `faloya_init` может запустить её снова, или другую
сборку её, в том же процессе; во время работы работника программы это
ошибка времени выполнения. Спецификация §7.11.
