
```
even 0
even 2
even 4
4 -1 40 0
```

Спецификация §6.4.

### `defer`

`defer s;` и `defer { … }` выполняют своё тело, когда заканчивается блок, в
котором они написаны, каким бы ни было окончание: падение с конца, `break`,
`continue`, `return`, `return` блока через функцию высшего порядка или
`return … from`, проходящий через функцию. `defer` в теле цикла выполняется
в конце каждой итерации. Выход выполняет записанные до него defer, начиная
с последнего, поэтому уборка стоит рядом с тем, что она убирает, и
пропускается там, где до неё дело не дошло. Тело это обычный код, выполняемый
позже: оно видит переменные такими, каковы они на выходе, а при `return`
выполняется после построения возвращаемого значения и до освобождения
хранилища блока.

```goose
var depth = 0;

fn describe(items: i64[:]) -> i64 {
    depth++;
    defer depth--;                   // любой выход из describe восстанавливает его
    print("depth ", depth);
    var count = 0;
    for x in items {
        defer count++;               // раз за итерацию, включая continue
        if x < 0 { continue; }
        if x > 100 { return -1; }
    }
    return count;
}

fn main() {
    print(describe([1, 2, -3]), " ", describe([5, 500, 7]), " ", depth);
    {
        defer print("block done");
        print("in the block");
    }
}
```

```
depth 1
depth 1
3 -1 0
in the block
block done
```

Тело проверяется там, где оно написано, поэтому оно называет только
объявленное до него, а суженный до него опционал `var` внутри него не сужен,
так как присваивание перед выходом может это отменить. Три вещи телу
запрещены, каждая это ошибка компиляции:

* **Выход.** Никакой `return`, `break` или `continue` в нём не может
  указывать вне его, включая `return` в блоке, переданном вызову в теле.
* **Дальние возвраты.** Оно не может вызвать функцию, которая делает
  `return … from`, распространяет такой или ловит такой, поскольку тело
  может выполняться, пока такой возврат в пути
  ([раздел 20](#20-дальние-возвраты-и-ошибки)); ошибка называет цепочку
  вызовов, которая вносит этот механизм.
* **Называть именованный результат функции.** Локальная, которую функция
  возвращает по имени, строится там, где её получает вызывающий
  ([раздел 17](#результаты)), и к моменту выполнения тела она готова.

`defer` принадлежит функции: у глобального инициализатора нет выхода из
области. Ничто не выполняет defer там, где выхода нет: `abort`, провалившийся
`assert` или проверка границ, `exit` и прерывание изолированного работника
завершают код, не выполнив ни одного, а конец процесса или работника
возвращает то, что тело освободило бы. Спецификация §6.6.

### Циклы

<!-- fragment -->
```goose
for i in 3 { }              // 0, 1, 2
for i in 10..13 { }         // 10, 11, 12: полуоткрытый
for i: i32 in 0..10 { }     // i это i32; каждая граница должна быть им или расширяться до него
for i: u8 in 0..256 { }     // весь u8, конец на единицу за последним значением типа
for x in xs { }             // копии для элементов фиксированного размера; ссылки для остальных
for &x in xs { x *= 2; }    // ссылки: форма с изменением
for x, i in xs { }          // с индексом, это i64
for x, i: u8 in grid { }    // индекс в более узком типе, куда помещается длина массива
while cond { }
loop { if done { break; } }
```

* Границы диапазона сводятся как операнды, и `i` живёт в этом типе;
  `for i in n` это `0..n`. Границы вычисляются один раз; пустой или
  обращённый диапазон не делает ничего.
* `for x in arr` копирует элементы фиксированного размера и привязывает
  элементы переменного размера по ссылке. Копию записывать нельзя
  (`x.f = 1` это ошибка, называющая `&x`), так как запись обновила бы
  только копию. Элемент, который *сам* ссылка, привязывается как та
  ссылка, которую он держит.
* `for &x in arr` привязывает каждый элемент по ссылке. Над `T[>..<]`
  привязка это живая ссылка, поэтому внутри цикла никакое усечение
  не допускается.
* Цикл обходит свою последовательность на месте. Длина расширяемого массива
  перечитывается перед каждой итерацией, поэтому push внутри `for` по
  значению добавляет к обходу; срез держит свою длину. Всё, что цикл
  обходит на месте, живо всё тело, поэтому массив, где это лежит, не может
  там усекаться.
* `continue` переходит к следующему элементу; `break` покидает внутренний
  цикл или `block`. Меток нет.

```goose
fn main() {
    var xs: i64[>..] = [1, 2, 3];
    for &x in xs { x *= 10; }
    for x, i in xs { if i == 0 { xs.push(x + 1); } }   // push продлевает обход
    var count: u8 = 0;
    for i: u8 in 0..256 { count += 1; }
    print(xs, " ", count);
}
```

```
[10, 20, 30, 11] 0
```

(`count` переполнился до 0 после 256 приращений, как и положено `u8`.)
Спецификация §6.5.

### `const for`: развёртка во время специализации

`const for` специализирует фрагмент один раз на каждый элемент
последовательности времени компиляции: поля структуры, варианты
перечисления, список типов или список констант.
Это рефлексия языка, без итератора времени исполнения и без метаданных:
каждая копия тела это обычный код.

```goose
struct Point { x: i64, y: i64, label: u8[..8] }

fn show_fields<T>(v: T&) {
    const for <N, A> in fields<T> { print(N, " = ", v.A); }
}

fn scaled<T, F>(v: T&) -> T {
    T { const for <N, A> in fields<T> { A: F(N, v.A), } }
}

fn main() {
    var p = Point { x: 2, y: 3, label: "pt" };
    show_fields(p);
    const for <U> in types<i8, u16, f32> { print(default<U>()); }
    const for <C> in [1, 2, 4] { let a: u8[C] = [0; C]; print(a.len); }
    let q = scaled(p) { n, x => x };
    print(q);
}
```

```
x = 2
y = 3
label = pt
0
0
0.0
1
2
4
Point { 2, 3, "pt" }
```

`fields<T>` привязывает имя каждого поля (строковую константу) и
*аксессор*, годный как `v.A` или как метка `A:` в литерале того типа
структуры. `types<…>` привязывает тип, а `[…]` привязывает константу
(литералы, именованные константы и целочисленные выражения, которые
допускает размер массива). Фрагмент операторов это своя область для каждого
элемента, а фрагмент конструктора вносит инициализаторы. `break` и
`continue` не могут пересечь развёртку.

`variants<E>` привязывает имя каждого варианта и вариант `V`, который
пишется всюду, где писалось бы имя варианта: `V` как тип (и `fields<V>`
для его полезной нагрузки), `V { … }` чтобы его построить, `V c` или
`V &c` как ветвь `match`, и `V` как значение, когда полезной нагрузки нет.
Фрагмент `match` вносит ветви, которые проверяются как написанные ветви:
каждый вариант по разу, `_` последним.

```goose
enum Shape { Circle { r: i64 }, Rect { w: i64, h: i64 }, Dot }

fn show<T>(value: T) {
    match value {
        const for <N, V> in variants<T> {
            V v => {
                print(N);
                const for <F, A> in fields<V> { print("  ", F, " = ", v.A); }
            },
        }
    }
}

fn main() {
    let s: Shape = Shape.Rect { w: 3, h: 4 };
    show(s);
    const for <N, V> in variants<Shape> { print(N); }
}
```

```
Rect
  w = 3
  h = 4
Circle
Rect
Dot
```

Спецификация §6.5, `docs/design/const_for.md`.

### `const if`: выбор во время специализации

`const if` выбирает один из своих списков фрагментов, пока функция
специализируется, и не порождает ничего из остальных. Он стоит там же, где
стоит `const for`: в списке операторов, в списке инициализаторов конструктора
или в списке ветвей `match`, с фрагментами того вида, что у списка, в каждой
ветви. Цепочка продолжается через `else const if`; обычный `else if` после
`const if` это ошибка.

```goose
struct Item { name: u8[..8], price: i64, tax: i64 = 20, discount: i64 = 0 }
enum Shape { Circle { r: i64 }, Dot }

fn required<T>() {
    const for <N, A> in fields<T> { const if !has_default<A> { print("required: ", N); } }
}

// Копия src, где каждое поле, объявляющее значение по умолчанию, сброшено к нему.
fn reset_defaults<T>(src: T&) -> T {
    T { const for <N, A> in fields<T> { const if !has_default<A> { A: src.A, } }, .. }
}

fn describe<T>(v: T) {
    const if same<T, i64> { print("an integer ", v); }
    else const if same<T, Shape> { print("a shape"); }
    else { print("something else"); }
}

fn main() {
    required<Item>();
    var item = Item { name: "pen", price: 5, tax: 7, discount: 3 };
    print(reset_defaults(item));
    describe(1);
    describe(2.5);
    const for <C> in [1, 2, 4] {
        const if C > 1 { print(C, " is wide"); } else { print(C, " is narrow"); }
    }
}
```

```
required: name
required: price
Item { "pen", 5, 20, 0 }
an integer 1
something else
1 is narrow
2 is wide
4 is wide
```

Условие это константа специализации: `true`, `false` или именованная
константа `bool`; запрос; `!`, `&&`, `||` и скобки над условиями; или
сравнение двух констант одного рода, тех констант, что принимает список
`const for` (литералы, именованные константы, целочисленные выражения,
которые допускает размер массива, и привязки объемлющего `const for`).
Целые сравниваются в типе, к которому сводятся их константы, целое рядом
с плавающим приводится, а булевы и строки принимают только `==` и `!=`.
Локальная, вызов, чтение поля или что-либо ещё, вычисляемое во время
исполнения, это ошибка, а не ветвление времени исполнения.

Запросы верны только в условии `const if`. `has_default<A>` это `true`
ровно тогда, когда поле, за которым стоит аксессор `A` из `fields<T>`,
объявляет написанное `= …`, включая значение по умолчанию, равное нулю
типа; ничего не вычисляется. `same<T1, T2>` это `true`, когда два типа
идентичны после подстановки, включая квалификацию `const`, так что
`same<V, Shape.Dot>` выбирает вариант, а `same<T, i64>`
дженерик-инстанциацию.

Невыбранная ветвь разбирается, но никогда не проверяется, в этом и суть:
`const if` над полем может писать в него в одной ветви и не трогать в
другой, тогда как `if` времени исполнения на том же предикате должен был бы
проверять типы обеих для каждого поля. В списке операторов выбранная ветвь
это вложенный блок, а не развёртка: `break`, `continue` и `return` в нём
значат то же, что в `if`. В конструкторе выбранные записи присоединяются
к списку инициализаторов, а в `match` выбранные ветви присоединяются к
списку ветвей, поэтому `const for` над `variants<E>` может оставить часть
вариантов написанным ветвям.

Спецификация §6.5, `docs/design/const_for.md`, раздел 11.

### Функции, которые никогда не возвращаются

`abort(msg)` и `exit(code)` никогда не возвращаются, и проверяющий это
учитывает: ветвь, заканчивающаяся таким вызовом, не даёт значения, операторы
после него не проверяются, и это распространяется через вызовы, поэтому
функция может заканчиваться вызовом одной из них без фиктивного результата.

```goose
fn fail(what: u8[:]) { abort(str("cannot ", what)); }

fn value(ok: bool) -> i64 {
    if ok { 42 } else { fail("compute") }
}

fn main() { print(value(true)); }
```

```
42
```

Неизвестный рекурсивный вызов считается возвращающимся.
Спецификация §7.3, §9.3.

### Проверки границ

Каждый индекс в массив или срез проверяется, как и каждое приведение к
индексному типу ([раздел 15](#15-индексные-типы-и-функции-checkfree)).
Проверка, которая не прошла, прерывает программу. Компилятор удаляет
проверки, ненужность которых может доказать, и язык устроен так, чтобы дать
этому анализу всё нужное:

* `T[>..]` усекается только на `pop`, `pop_n`, `resize` или `clear`,
  которые анализ видит, поэтому граница, установленная до `push`, держится
  и после него;
* `%` евклидов, поэтому приведение всегда в диапазоне;
* фиксированные размеры и ёмкости это константы;
* каждое место вызова записывает, что оно доказало о своих аргументах.

Идиома, помогающая больше всего, это `assert` длин в начале ядра:

```goose
let W = 8;
fn blur_row(above: u8[:], here: u8[:], below: u8[:], out: u8[:]) {
    assert(above.len == W && here.len == W && below.len == W && out.len == W);
    for x in 1..W - 1 {                     // каждый индекс это x плюс константа: проверок нет
        let sum = above[x - 1] as i64 + above[x] + above[x + 1] +
                  here[x - 1] + here[x] + here[x + 1] +
                  below[x - 1] + below[x] + below[x + 1];
        out[x] = (sum / 9) as! u8;
    }
}
```

`faloya --bce-lines` сообщает по строкам, какие проверки остались. Остальные
прерывания, которые остаются в любой сборке, это деление на ноль,
переполнение ёмкости массива limited, усечение ниже пустого, смещение
относительной ссылки, не влезающее в свою ширину, провалившийся `assert` и
исчерпание стека данных. Все они чистые прерывания с сообщением и строкой
провалившейся проверки; проверка внутри функции стандартной библиотеки
называет строку кода программы, вызвавшей библиотеку.
Спецификация §9.3, §10.5.


## 17. Функции

<!-- fragment -->
```goose
fn name(a: i64, var b: f64, xs: i32[:]) -> i64 { … }
fn generic<T>(a: T, b: T) -> T { … }
fn also_generic(a, b) { … }              // нетипизированные параметры это дженерики
fn scaled(a: i32, b: i32 = 0, c: f32 = 1.0) -> f32 { … }   // scaled(2) это scaled(2, 0, 1.0)
```

Функции это свободные функции. Методов и блоков `impl` нет, но
**`x.f(a)` вызывает `f(x, a)`** для любой функции, поэтому синтаксис
вызова метода доступен всюду, где он читается лучше. Разрешение пробует
сначала поля и встроенные члены, затем функции, начиная с пространства
имён типа `x` ([Пространства имён](#пространства-имён)). Объявления
верхнего уровня не зависят от порядка. Спецификация §7.1.

### Параметры

* Параметр это привязка `let`: переприсвоить его нельзя, а его содержимое
  записываемо настолько, насколько говорит его тип. `var b: f64` делает
  параметр по значению переприсваиваемой локальной.
* Параметр без типа это дженерик
  ([раздел 18](#18-дженерики-и-функциональные-значения)).
* Ссылочный параметр, `n: i64&`, привязывает lvalue указуемого типа без
  `&`. Срезовый параметр принимает любой вид массива. Параметр по значению
  нефиксированного размера, `xs: u8[>..]`, строится в слоте аргумента и
  принадлежит вызываемому как локальная: `f(copy(xs))` или `f(make())`.
* **Значения по умолчанию.** Замыкающий параметр может объявить значение
  по умолчанию, `c: f32 = 1.0`, и вызов может опустить любое число
  замыкающих параметров, у которых оно есть. Значение по умолчанию
  вычисляется на каждом таком вызове, после написанных аргументов, как
  значение типа параметра. Оно может называть глобальные и вызывать
  функции, но не может ссылаться на локальные вызывающего. Значение по
  умолчанию дженерик-параметра подстраивается под тип, к которому
  привязываются аргументы (`fn scale<T>(x: T, by: T = 2)` удваивает и
  `u8`, и `f64`), и само типовую переменную никогда не решает.
